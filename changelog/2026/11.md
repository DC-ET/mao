## 0.0.505 (2026-11-10)

### 后端
- **本地工具执行不再因执行端通道失效长时间卡住**：此前会话绑定设备后，只要 `isConnected` 判定在线，服务端就开等执行端回报，最坏要干等满总超时（默认 900 秒）才返回 `Local tool execution timed out`——桌面端闪断、或 mao-agent 与桌面端共用同一 `deviceId` 时执行连接被抢走（半死连接：socket 活着但执行端没有该会话上下文，收到帧不回报），都会出现这种情况。现在：
  - 设备定向投递零成功时（该设备当前没有任何可写执行连接），立即回「本地执行端未连接，请确保桌面客户端正在运行」，同时收敛服务端 pending，不再留下无人认领的等待。
  - 无审批请求下发后，若执行端在 60 秒内既没回 `tool_approval` 空表态也没回结果，即判通道半死并快速失败，提示用户确认桌面客户端在运行、未被后台挂起后重试。该窗口与总超时定时器同起跑并取更早触发者，只会让结果更早，绝不会把请求拖得比总超时更久。
  - `sendToDevice` 在主执行连接不可写（readyState 非 OPEN / 未授权）时，回退到同一 deviceId 的另一条存活连接（同机多窗口 / 多 CLI 进程场景），避免整个设备被误判离线。

## 0.0.495 (2026-11-10)

### 后端
- **修复一次性定时任务排队结算丢失用户改档**：会话忙入队后、消费完成前，用户把 cron 换成另一个一次性日期，排队结算曾无条件把任务标完结并清空档期——新档期永不触发、任务被误标 finished。现与直跑收尾同口径：改档（队列行 fireTime 不再是当前 cron 的触发点）且任务启用时按最新 cron 重开档期，未改档行为不变。

### 后端
- **修复 Docker 模式容器时区为 UTC**：运行时镜像（`node:22-bookworm-slim`）默认 `Etc/UTC`，创建容器时也未注入时区，容器内 `date`、脚本时间戳、Node 本地时间、`git commit` 全部按 UTC 落——比北京时间慢 8 小时，北京时间 00:00–08:00 时段日期还会显示为前一天；与后端全站 `Asia/Shanghai` 口径（日志时间戳、系统提示「当前日期」、Cron 调度）不一致，Agent 自查时间时自相矛盾。现在 `runtime-agent` 启动时对齐容器时区：① 进程内设置 `TZ=Asia/Shanghai`（优先级最高、立即生效，覆盖 agent 自身与其派生的 shell / pty / MCP 子进程）；② 幂等对齐 `/etc/localtime` 符号链接与 `/etc/timezone`（临时文件 + rename 原子替换），使 `docker exec` 等非 agent 派生进程同样正确。tzdata 随镜像已存在，不依赖挂载宿主机文件；对齐失败仅告警、不阻塞 agent 启动。存量容器在下一次代码漂移懒重启（0.0.394 机制）时自动收敛，无需人工重建。
- 新增单测：时区对齐幂等（localtime 链接 + timezone 内容）、普通文件 localtime 替换为符号链接、zoneinfo 缺失时零改动降级。

## 0.0.394 (2026-11-01)

### 后端
- **容器内代码版本漂移自动收敛（Docker 模式）**：容器内 `runtime-agent` 是常驻进程、`dist` 无热加载，此前发版后容器仍跑旧代码，需人工 `docker restart` / 后台重建（0.0.393 的技能符号链接修复即因此需要人工重启才生效）。现在：① 构建期新增闭包指纹——`npm run build` 在 tsc 之后遍历 `runtime-agent.js` 的静态相对 import 闭包，生成 `dist/harness/container/runtime-build.json`（内容哈希，`generatedAt` 不参与哈希，同源重建幂等）；② 容器 agent 启动时读取该 manifest，`hello` 帧新增可选 `build` 字段上报（协议 v1 不变、旧宿主松校验忽略）；③ 宿主机 `ContainerRegistry` 读取同一份 manifest 作为「本实例加载的代码版本」，在 `ensureRunning`（用户下次调工具）时懒比对：代码漂移且容器空闲 → 自动重启进程（`stop` + `start`，保留容器/挂载/env/容器名，不重建）；忙碌则只记日志（`deferred-busy`），下次再判；挂载 / hosts 漂移仍走重建（正确性优先）。
- **防环与守卫**：每（容器 × host build）只自动尝试一次（蓝绿过渡期旧实例缓存旧 build 时不会反复重启）；draining 实例跳过自动升级（由承接流量的实例执行）；`dist` 无 manifest（LOCAL/dev / 异常部署）时检查整体关闭；旧 agent 不报 build 视为 unknown → one-shot 自愈（首次发布后各存量容器在空闲时自动重启一次完成切换，无需人工）。
- **新增总开关**：`system_setting.runtime.container.autoUpgrade`（V178 迁移，默认 `true`，后台「系统设置 → 运行环境 → 容器管理」可切换；保存后即时生效，5s TTL + 保存失效双保险）。关闭只停用自动重启，人工「重建容器」入口不变；缺行/非法值/读库失败一律回落 `true`。
- 新增单测：闭包指纹（确定性 / 仅闭包内容变化 / 注释内 import 不误判 / manifest 读取降级）、开关解析与 TTL、hello 上报（含旧 agent 无 build）、registry 漂移收敛矩阵（空闲重启 / 忙碌延后 / 开关关闭 / draining / one-shot / stopped 仅 start / 挂载漂移优先重建 / manifest 缺失零动作）、设置值域校验。

### 管理后台
- **「系统设置 → 运行环境 → 容器管理」新增自动升级开关**：「发版后自动重启空闲容器以收敛代码版本」。
- **容器列表新增三列**：「代码版本」（容器 agent 上报，未上报显示「待上报」）、「后台版本」（本实例 dist 版本，manifest 缺失显示「未启用」）、「升级」（漂移时显示「待升级」徽标，一致显示「一致」）。

### 部署
- `npm run build` 自动生成 manifest，无需额外步骤；本次发布后存量容器会在各自「空闲 + 下次使用」时自动重启一次收敛（每容器一次，不是发版风暴），无需人工重启容器。
