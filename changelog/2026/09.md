## 0.0.222 (2026-09-30)

### 前端（桌面 / Web / 安卓）

- 修复文件面板「筛选文件」输入后页面陷入请求风暴、满屏「网络错误」的问题。此前筛选会把整棵文件树逐层预加载（多仓库工作区可达数千个并发目录请求），耗尽浏览器连接/内存后大量请求报 `ERR_INSUFFICIENT_RESOURCES`，聊天等请求被连带阻塞，只能刷新恢复。现改为一次搜索拿全部匹配：云端走后端新接口 `workspace-search`，本地（Electron）走有界的 IPC 遍历；自动跳过 `.git`、`node_modules` 与符号链接；匹配超过 100 条时提示「匹配较多，仅显示前 100 条」。搜索结果行内显示完整相对路径（打开页签与下载文件名仍用文件名），便于区分不同目录下的同名文件；切换会话时自动清空筛选关键词。

### 后端

- 新增 `GET /v1/files/workspace-search?sessionId=&pattern=&limit=`：按文件名递归搜索会话工作区（大小写不敏感子串匹配，仅返回文件），遍历有界（扫描目录 ≤2000、深度 ≤12、结果 ≤100），跳过 `.git`/`node_modules` 与符号链接目录，超限时返回 `truncated: true`，避免大工作区拖垮请求。

## 0.0.211 (2026-09-28)

### 后端

- 修复蓝绿部署后会话卡在「运行中」、消息发出后一直无响应的问题。根因是三重时序错位：切流后旧实例的飞书/微信/钉钉长连接还活着，排空窗口内到达的消息仍被旧实例接走并开始执行；启动期崩溃恢复的两轮扫描（启动时刻 + 延迟 60s/+15s）都早于旧实例真正被 kill 的时刻（systemd timer 可能晚几十秒），于是执行被切断、`session.phase` 永久停在 `RUNNING`，而没有任何机制再接管。
  - 旧实例轮询 `deploy.lock`，看到切流完成（`status=switched`、自己是被替换的旧端口、且 `active-backend-port` 已指向新实例）即主动收尾：静默飞书/微信/钉钉入站 → 等在途执行收尾（上限 40s，并按 `MAO_BLUE_GREEN_DRAIN_SEC` 收敛）→ 把仍被中断的会话原子标记为 `RESUMING` → 自行退出。何时停机不再由外部 drain 定时器决定。已建立的桌面 WebSocket 连接不会被部署流程主动断开，旧实例退出时会自然断开并由客户端重连；断开前发起的执行由"等待 + 标记 + 续跑"兜住。
  - 承接流量的实例每 30s 巡检一次孤儿会话（`RUNNING` 需静默超过 120s、`RESUMING` 需静默超过 45s），并排除本实例正在执行、以及被在途子代理执行占用的会话，自动续跑被中断的任务。该巡检与部署时序解耦，也覆盖非部署原因导致的执行中断；单实例安装（不写 `active-backend-port`）同样生效。被在途子代理占用的父会话仍只在启动期恢复。
  - 启动期的延迟恢复（快照重放 + 全库补扫）同样改为等部署结束再执行：它的候选是"部署窗口内仍活跃的会话"，旧实例可能还在跑，抢跑会双跑。代价是部署后的续跑从"启动后 60s"推迟到"排空窗口结束（`MAO_BLUE_GREEN_DRAIN_SEC` + 60s）后"，最坏约 2 分钟。
  - 执行期间新增独立心跳：原来只在每轮 LLM 调用前后刷新 `last_activity_at`，单个长工具调用期间时间戳不更新，会让"正在跑"的执行看起来像孤儿；现在执行期间按 30s 定时刷新，使"静默"可靠地指向"已死"。
  - 升级到本版本后，历史遗留的、静默超过阈值的 `RUNNING`/`RESUMING` 会话会被巡检自动续跑，无需人工改库。

## 0.0.177 (2026-09-21)

### 后端

- 修复任务完成 webhook 通知在调度参数读取失败（DB 抖动等）后永久停摆的问题：原先失败分支只打日志「1 分钟后重试」却没有重排定时器，整条投递轮询链断开，`PENDING`/`WAITING_WS` 的通知直到重启后端才恢复。现失败后 1 分钟重排续跑。
- 修复 ECP 票自动续期在续期途中重启（部署 / OOM）后永久停摆的问题：`renew_status` 会卡在 `RENEWING`，而扫描只捞 `ACTIVE`，该用户票到期后突然变成「无有效 ECP 票」，只能手动重新登录。现每分钟把超过 5 分钟未收敛的 `RENEWING` 复位为 `ACTIVE`，重新进入续期队列。
- 修复 Shell 后台任务（`async: true`）运行超过 30 分钟后结果被静默丢弃的问题：原先超时即从登记表移除，任务跑完也无人消费（不再自动注入上下文），模型再 `await_async` 只会收到「后台任务不存在或已被消费」。现超时只告警、保留交付，长时构建结束后仍能拿到输出；仅超过 24 小时未结束才回收。
- 修复飞书忙碌期收到的文件在当轮任务失败（FAILED）时永不写入会话的问题：文件只留在内存里，用户后续提问在会话历史中看不到文件路径。现附件落库与上一轮成败解耦，FAILED 只阻止自动消费下一条排队消息。
- 修复队列自动消费在执行提交被拒（线程池打满）时产生重复用户消息的问题：回补队首却没删掉已落库的 USER 消息，下次消费会再写一条同内容消息。现出队之后任一步失败都统一补偿——回补队首 + 删除孤儿消息 + 刷新队列，消息不再丢失、重复或留下无执行的孤儿。
- 修复会话空闲时的「停止」把从未运行过的任务标成「已取消」的问题：`IDLE` 既不在活跃集合也不在终态集合，会被终态写入放行。现仅在确有在途执行时才落 `CANCELLED`。
- 修复 `shell` 工具 `write_stdin` 写入 `exit` 让 bash 退出后，返回文案称「会话已关闭」但会话未真正回收的问题：死会话最多占用 60 秒会话数配额，极端情况下误报「已达会话上限」。
- 修复终端断线重连后历史输出可能整段空白的问题：单帧输出超过缓冲上限时环形缓冲会把这一帧一起丢掉，连截断提示都不显示。现只截掉超限部分并保留最近输出（按 UTF-8 字符边界，不再切出乱码）。
- MCP 工具参数不是合法 JSON 对象时直接返回参数错误，不再兜底成 `{}` 后照常调用——原先会让工具在缺参数下执行或返回与真实原因无关的报错。

### 前端（桌面 / Web / 安卓）

- 修复工具审批在断线时点「批准 / 拒绝」后审批项直接消失、而服务端仍在等待回包（任务像卡死）的问题：现发送失败会把审批项放回队列并提示「审批发送失败，网络连接不可用，请重试」。

- **文件与搜索新增路径沙箱**：读写编辑、`glob_search` / `grep_search` 的搜索根、`shell` 的 `workdir` 都必须落在已信任的工作区或本会话 runtime 目录内；`../` 越界、绝对路径逃逸、指向外部的符号链接一律拒绝。`read_file` / `glob_search` / `grep_search` 也纳入工作区信任门禁（此前只有写类与 shell 受限），`--yolo` 不能豁免
