# 飞书机器人通道（feishu-bot）

通过**飞书自建应用机器人**在飞书内与 Agent 对话：支持多个机器人并行接入（WebSocket 长连接），用户可在私聊直接对话或在群里 @ 机器人触发。绑定以飞书 `union_id` 为身份锚，绑定一次对所有机器人通用。

## 功能特性

| 能力 | 说明 |
|------|------|
| 多机器人 | 管理后台配置多个飞书自建应用机器人，每个可独立绑定 Agent 与模型 |
| 长连接 | 服务端与飞书建立 WebSocket 长连接，自动重连与退避 |
| 私聊 | 用户直接给机器人发消息即触发 Agent（需先绑定飞书账号） |
| 私聊多会话 | 私聊支持任务级会话隔离：发送 `---`（或 3 个及以上 `-`/`—`）新建会话；回复/引用历史消息自动切换到该消息所在会话（0.0.101 起）。同一私聊所有会话共享根工作区，会话列表以「首条消息前 20 字」命名 |
| 群聊 @ | 群里 @ 机器人触发；自动注入最近群聊讨论作为上下文（`[HH:mm] 发送人：内容`，机器人卡片会提取真实文本而非“请升级至最新版本客户端”降级文案，0.0.128 起）；群聊无多会话机制，行为不变 |
| 已打开的网页 | 飞书里继续发消息，或点失败卡「重试」时，已经打开的网页 / 桌面 / 安卓会话会跟上这一轮的执行过程，不必整页刷新（0.0.182 起） |
| 进度卡片 | 任务开始执行即发送「正在处理」卡片，每个 loop round 更新状态与本轮工具摘要；Shell 执行中会展示正在跑的命令（`shell：\`npm test\`（执行中）`，0.0.176 起）；后端重启后续跑或失败卡「重试」时轮次按当前任务已完成的助手轮接续，不从 0 重计（0.0.176 起）；终态显示总轮数与耗时（`状态：处理完成 · 共 8 轮 · 耗时 8 分 26 秒`，排队等待不计入，0.0.120 起），执行中点「取消任务」可停止任务；失败卡正文展示具体 `error.message` 并带「重试」按钮（0.0.144 起，点后基于会话历史续跑、不插入新用户消息，仅原发送者可点）；卡片带「会话详情」按钮，点击在浏览器打开网页端会话页 `/tasks/{id}`（站点地址取 ECP `desktopCallbackUrl` 的 origin，0.0.133 起） |
| 图片 / 文件入站 | 图片转多模态 image_url 并落盘会话工作区 `chat-files/{yyyy-MM-dd}/`（0.0.77 起，含 post 富文本内嵌图片），消息附保存路径提示。独立文件消息只下载并写入当前会话（`@{路径}@`），不单独触发 Agent（飞书无法在同一条消息里带文件和文字，0.0.175 起）；随后的文字作为一次任务处理。只发文件、不跟文字时保持静默。群聊未 @ 的文件同样预下载并回填群日志路径 |
| 工具调用摘要 | 桌面 / Web / 安卓会话中的 `feishu_read_doc`、`feishu_download_file`、`feishu_send_image`、`feishu_send_file` 显示中文操作名称与参数预览；执行后摘要显示文档链接及字符数、下载路径或发送文件名，并标注文件下载 / 发送的成功或失败。历史已保存摘要不回写，动态 MCP 工具保留原始名称 |
| 未绑定 / 无 ECP 票引导 | 未绑定或已绑定但没有有效 ECP 票时，机器人发送橙色标题「新用户绑定」的交互卡片，正文「请先点击下方按钮完成用户绑定（3分钟内有效）。」，按钮「点我绑定」跳转授权页（避免超长 URL 被飞书截断）。登录成功后按邮箱对齐已绑用户并重放原消息。邮箱对不上则不改绑，提示联系管理员 |
| 解绑保留 | 解绑后机器人无法识别身份，原工作区与会话保留 |

## 角色与操作入口

| 角色 | 操作 | 入口 |
|------|------|------|
| 管理员 | 添加/编辑/启停/删除机器人，配置每个机器人的 Agent/模型 | 管理后台「能力 → 飞书机器人」（Skills 管理上方，见 [admin.md](admin.md)） |
| 普通用户 | 绑定/解绑飞书账号、查看绑定状态 | 桌面端「设置 → 飞书Bot」（[desktop.md](desktop.md)） |

## 使用流程

1. **飞书开放平台**：创建自建应用，获取 App ID / App Secret；开通机器人能力与所需权限（至少：消息与群组相关、**获取用户 union_id**——未开通则无法识别发送者，全员按未绑定处理）。
2. **管理后台**：「飞书机器人」→ 添加机器人（内部唯一键、名称、App ID、App Secret、Agent、模型）→ 启用。保存 App Secret 需后端已配置 `APP_FEISHU_BOT_SECRET`（AES-GCM 加密存储）。
3. **用户绑定**：桌面端「设置 → 飞书Bot」→ 绑定飞书账号（扫码/内嵌窗口授权）→ 状态变为已绑定。或在飞书内先给机器人发消息，按引导链接完成授权。全站启用 ECP 飞书登录时，飞书内引导一律走 ECP 授权（按邮箱登录 Mao、写入 `sessionToken`，未绑则绑定 `union_id`）；设置页绑定仍通过 Mao 飞书应用 OAuth 单独获取 `union_id`，但仅绑定还不能触发任务，还需同一邮箱完成一次 ECP 飞书登录。
4. **使用**：私聊机器人直接发消息；群聊把机器人拉进群后 @ 机器人。ECP 开启时，发送者必须同时满足「已绑定」且「有未过期的 ECP 票」，否则再次收到登录引导。私聊想开启新任务时发送 `---` 新建会话；想回到历史任务时回复/引用那个会话里的任意消息（含机器人回复与进度卡片）自动切换回去。
5. **解绑**：设置页「解绑」，不影响既有工作区与会话。

## 消息上下文顺序

群聊传给 Agent 的文本按「【群内最近消息】→【引用的消息】→【用户消息】」组织，没有群聊上下文或引用时省略对应段落。引用内容紧邻用户本次请求，便于理解关联意图；私聊保持引用内容在用户文本前。此顺序适用于新收到的消息（包括随后进入队列的消息），不改写已保存的历史消息或既有队列内容。

## 私聊会话切换与排队取消

- 引用已记录归属的历史消息（包括 Agent 回复、进度卡片）时，先切换到该消息所属会话，再判断目标会话是否忙碌。原当前会话正在执行不阻塞切换：目标空闲时立即执行，原任务继续运行；目标本身正在运行或恢复中时，消息进入目标会话队列。
- 进度卡片的「取消任务」会停止当前正在执行的任务（含后端重启后续跑）。若升级前重启后卡片取消无效，需进桌面/Web 点输入框停止；0.0.115 起飞书卡片取消与客户端停止同语义；0.0.144 起取消终态文案为「任务已取消。」（不再误显示「已被下一条指令中断」）。
- 失败进度卡点「重试」：基于该会话已有历史续跑（不插入新用户消息），原卡就地变为「正在重试」；仅原发送者可点，会话执行中/已结束时 toast 提示不可用。与桌面端 ExecutionErrorBanner 的重试同语义。
- 排队卡片的「立即发送」会中断当前正在执行的任务，并把该条消息插到队首立刻执行；卡片应变成「已插队」，随后就地升级为进度卡。若点击后闪一下又回到「排队中」，是旧版回调没把新卡片带回客户端（0.0.115 已修），可升级后端后重试。
- 排队卡片的「取消本次任务」仅取消该条尚未执行的消息，不停止当前正在执行的任务；停止执行请点击进度卡片的「取消任务」。取消成功后卡片会就地变为「已取消」，并弹出成功提示。
- 引用消息没有归属映射时不会切换会话，仅把引用内容用于当前会话；修复不会为未记录的历史消息补建映射。

## REST API

### 管理端（需管理员权限）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/v1/admin/feishu-bots` | 机器人列表（`appSecret` 不返回，仅 `appSecretConfigured`） |
| GET | `/v1/admin/feishu-bots/:id` | 单个机器人 |
| POST | `/v1/admin/feishu-bots` | 创建：`appKey`、`name`、`appId`、`appSecret`、`agentId?`、`modelId?`、`enabled?` |
| PUT | `/v1/admin/feishu-bots/:id` | 更新（`appSecret` 传空串不修改） |
| DELETE | `/v1/admin/feishu-bots/:id` | 软删除 |
| POST | `/v1/admin/feishu-bots/:id/enable` / `disable` | 启用 / 停用 |
| GET | `/v1/admin/feishu-bots/status` | 全部机器人连接运行状态：`botId`、`status`（ready/reconnecting/failed/disabled）、`lastFailureReason`、`lastFailureAt`、`lastReadyAt`（无记录时字段缺省） |
| POST | `/v1/admin/feishu-bots/:id/reconnect` | 触发重连（仅已启用的 bot；停用或不存在的 bot 返回 2001） |

### 用户端（需登录）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/v1/feishu/binding` | 发起绑定，返回授权链接 `authUrl`（未启用飞书登录返回空） |
| GET | `/v1/feishu/binding/status` | 绑定状态：`bound`、`unionId`、`boundAt` |
| DELETE | `/v1/feishu/binding` | 解绑 |

## 排障

- **保存机器人报「未配置 APP_FEISHU_BOT_SECRET」**：后端未配置加密密钥，配置后重启。
- **全员提示未绑定**：飞书应用未开通「获取用户 union_id」权限。
- **已绑定仍提示登录**：ECP 已开启但该 Mao 用户没有有效 ECP 票（从未 ECP 登录、票过期或 renew 失败）。按引导完成 ECP 飞书登录；若提示邮箱与已绑账号不一致，需管理员核对 `user.email` 与 ECP 邮箱后重试。
- **提示需要 ECP 登录但没有链接 / 链接被截断**：旧版把超长授权 URL 写进纯文本，飞书会截断。0.0.129 起改为卡片「新用户绑定」+ 按钮「点我绑定」。升级后端后重发一条消息即可。
- **群聊 @ 不触发**：确认机器人已进群、@ 的是本机器人（同群多个机器人时以 App ID 精确匹配）、管理员已启用该机器人。
- **长连接频繁断开**：查看 `FEISHU_BOT_RECONNECT_*` 退避参数与 `FEISHU_BOT_MAX_CONSECUTIVE_FAILURES` 告警阈值。
- **蓝绿/重启后任务已完成但进度卡片一直「正在处理」**：旧版崩溃恢复会续跑任务，但不把飞书卡片收成终态。0.0.113 起成功/失败/取消都会 PATCH 原卡片；升级后端后新发生的恢复即生效，已卡住的卡片不会自动刷新。
- **重启后任务继续跑、进度卡片停在重启时的状态**：旧版读进度卡映射时用了 snake_case 字段名，对不上 `Db` 转出的 camelCase，恢复监听挂不上，卡片不再 PATCH。0.0.116 已修；升级后端后对新发生的恢复生效，已卡住的卡片不会自动刷新。
- **重启后进度卡片轮次从 1 重新计数**：旧版恢复 PATCH 固定写第 0 轮，AgentLoop 本趟也从 1 计。0.0.176 起按当前任务最后一条用户消息之后已落库的助手轮接续。
- **重启后飞书任务卡住、卡片「取消任务」无效**：旧版只查内存取消标志，崩溃恢复续跑的任务在飞书侧取消不到，只能去桌面/Web 点停止。0.0.115 起卡片取消会置位引擎标志，并在没有内存执行时把仍为 RUNNING 的会话落成 CANCELLED。
- **任务执行中发的文件，任务失败后 Agent 说找不到**：旧版把「暂存附件落库」和「失败后不自动消费下一条」绑在同一个条件上，当轮任务 FAILED 时文件只留在内存、不写会话历史。0.0.177 起附件无条件落库，FAILED 仅阻止队列接力；升级后端即生效，此前丢失的文件需重新发送。
- **群内最近消息里机器人显示「请升级至最新版本客户端，以查看内容」**：飞书对 interactive 卡片的 receive 事件可能把 content 降级为该文案。旧版会原样落入群消息日志；0.0.128 起归一化阶段过滤该文案，入库占位为 `[卡片消息]` 并后台按 messageId 拉详情回填真实卡片文本。已入库的旧脏数据不会自动清洗，新消息起不再出现。
