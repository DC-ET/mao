## 本轮仍发现的问题

### 1. STARTING 会话直接收到终态时不会退出 tracked

- 优先级：高
- 位置：`android/android/app/src/main/java/cn/etarch/mao/app/TrackedManager.java:172-188`
- 触发场景：任务很快完成、失败或取消，原生端没有先收到 `RUNNING/RESUMING/...`，而是从 `STARTING` 直接收到 `COMPLETED`、`FAILED` 或 `CANCELLED`；STARTING 超时 REST 查询直接返回终态时也会触发。
- 问题：`onSessionStatus()` 的 STARTING 分支只处理活跃 phase，随后无条件 return，终态无法进入后面的 `finalizeSession()`。
- 影响：会话一直留在 `activeTracked` 的 STARTING 状态，前台服务和 WakeLock 可能长期不释放。超时检查只执行一次，REST 返回终态后也不会再检查。

### 2. 超过 4 MB 的磁盘事件文件无法完整恢复

- 优先级：高
- 位置：`android/android/app/src/main/java/cn/etarch/mao/app/PendingQueue.java:359-389`、`android/android/app/src/main/java/cn/etarch/mao/app/PendingQueue.java:417-431`
- 触发场景：`events.jsonl` 大于 4 MB 后应用进程被回收或崩溃，再次启动恢复缓冲。
- 问题：`scanFileMaxSeq()` 和 `loadDiskRecords()` 都依赖 `readLines()`，而 `readFile()` 最多只读取文件前 4 MB。队列允许单会话达到 10 MB，合法文件明显可能超过该读取上限。
- 影响：4 MB 之后的未 ACK 事件不会载入内存，重放永久缺失；若 meta 文件丢失或未及时落盘，还可能根据不完整的最大 seq 复用已有 sequence。

### 3. 通知冷启动时 Service 尚未存在，目标会话跳转会丢失

- 优先级：高
- 位置：`android/android/app/src/main/java/cn/etarch/mao/app/MainActivity.java:30-39`、`android/android/app/src/main/java/cn/etarch/mao/app/MainActivity.java:78-89`
- 触发场景：用户点击任务结果通知冷启动应用，此时 `WsKeepAliveService.getInstance()` 返回 null。
- 问题：`sessionId` 只写入 Activity 的 `pendingNavigationSessionId`；当前工作区没有任何代码调用 `getPendingNavigationSessionId()`。后续 Service 或插件启动不会消费该值。
- 影响：前端收不到 `pendingNavigate`，用户不会跳转到通知对应的任务页面。

### 4. 切换持久化模式时不会把已有未 ACK 内存事件刷盘

- 优先级：中
- 位置：`android/android/app/src/main/java/cn/etarch/mao/app/PendingQueue.java:101-108`、`android/android/app/src/main/java/cn/etarch/mao/app/PendingQueue.java:113-132`、`android/android/app/src/main/java/cn/etarch/mao/app/WsKeepAliveService.java:270-296`
- 触发场景：前台已收到 tracked 事件但 JS 尚未 ACK，随后 App 切到后台或 WebView 被判定不活跃，进程紧接着被回收。
- 问题：`setPersistMode(true)` 只修改布尔值；只有切换后新 append 的事件才写盘，切换前已有的 pending 记录没有落盘。
- 影响：进入后台前的未 ACK 事件存在丢失窗口，后台可靠恢复语义不完整。

### 5. HTTP 200 但缺少 phase 时仍被当作明确 IDLE

- 优先级：中
- 位置：`android/android/app/src/main/java/cn/etarch/mao/app/WsKeepAliveService.java:703-726`
- 触发场景：STARTING 超时查询收到 HTTP 200，但统一响应的 `data` 为 null，或 `data.phase` 缺失。
- 问题：`querySessionPhase()` 使用 `data.optString("phase", "IDLE")`，且 `data == null` 时也返回 `"IDLE"`。
- 影响：实际状态未知或任务仍在运行时，会话仍可能被错误回滚并停止后台保活。只有服务端明确返回 phase=IDLE 才应回滚。

### 6. 正常连接与网络可用回调可能并发创建两个 WebSocket

- 优先级：中
- 位置：`android/android/app/src/main/java/cn/etarch/mao/app/WsKeepAliveService.java:382-410`、`android/android/app/src/main/java/cn/etarch/mao/app/WsKeepAliveService.java:733-749`
- 触发场景：Service 启动调用 `connectWebSocket()` 后，连接尚未打开且 `wsOpen=false`，默认网络的 `onAvailable()` 同时触发重连任务。
- 问题：代码没有 CONNECTING 状态或连接 generation，`onAvailable()` 只检查 `!wsOpen`，可能再次创建 socket。
- 影响：同一事件可能由两个连接重复接收和入队；旧 socket 的回调还可能覆盖新 socket 的全局 `wsOpen` 状态并触发额外重连。
