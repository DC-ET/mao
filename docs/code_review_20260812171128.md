# 未提交代码审查报告

## 1. [高] 子代理结果收集器未响应流重置，父代理会收到拼接后的错误结果

**位置：**

- `backend/src/main/java/cn/etarch/mao/harness/core/CompositeAgentEventListener.java:111`
- `backend/src/main/java/cn/etarch/mao/harness/delegate/SubAgentResultCollector.java:35`

**问题：**

本轮新增的 `onLlmStreamReset()` 会经 `CompositeAgentEventListener` 转发给所有监听器，但 `SubAgentResultCollector` 没有处理该事件。子代理已经输出部分文本后若发生断流，`AgentLoop` 会清空自身缓冲区并重试，WebSocket 端也会清空页面内容；然而结果收集器仍保留中断前的 `contentBuilder` 和 `thinkingBuilder`，随后把重试响应继续追加到旧内容后。

**触发场景：**

1. 子代理流式输出部分文本或思考内容。
2. SSE 在 `[DONE]` 前中断并触发自动重试。
3. 重试返回一份完整的新答案。

**影响：**

`DelegateTool` / `DelegateFollowupTool` 调用 `resultCollector.getResult()` 时，会把“中断前残片 + 重试后的完整答案”返回给父代理。子会话最终落库内容却是 `AgentLoop` 重置后的正确答案，造成父代理获取的结果与子会话记录不一致。中断前已发出的工具调用还会使 `toolCallCount` 重复累计。

**建议：**

让 `SubAgentResultCollector` 同步处理 `onLlmStreamReset()`，清除当前失败尝试收集的文本、思考内容以及对应的工具调用计数，并补充经过组合监听器的子代理断流重试测试。

## 2. [中] 无可见内容的 SSE chunk 也会触发重置，可能误清空上一条已完成回复

**位置：**

- `backend/src/main/java/cn/etarch/mao/harness/llm/OpenAiLlmAdapter.java:260`
- `desktop/src/stores/session.ts:1054`

**问题：**

`OpenAiLlmAdapter` 对任意成功解析的 SSE chunk 都无条件执行 `emitted.set(true)`。许多 OpenAI 兼容接口的首个 chunk 仅包含 `role`、空 delta 或 usage，并不会触发 `AgentLoop` 的文本、思考或工具调用事件。如果此后立即断流，后端仍会发送 `llm_stream_reset`。

前端的 `resetStreamingAssistantMessage()` 没有确认最后一条 assistant 消息是否属于当前执行，只要最后一条消息角色是 assistant，就会清空其内容、思考和工具调用。在其他连接发起任务、当前连接尚未创建本轮 assistant 占位消息，或事件到达顺序异常时，最后一条 assistant 可能是上一轮已经完成的回复。

**触发场景：**

1. 当前消息缓存最后一条是上一轮已完成的 assistant 回复，本轮临时 assistant 消息尚未建立。
2. LLM 返回一个不含可见输出的初始化 chunk。
3. 流在 `[DONE]` 前中断并触发 `llm_stream_reset`。

**影响：**

上一轮正常回复会被前端清空；服务端历史未受影响，刷新页面后又会恢复，导致当前页面与持久化记录不一致。

**建议：**

仅在 chunk 实际产生了可累计的文本、思考或工具调用数据后标记本次尝试需要重置；同时前端应只重置明确属于当前 execution 的流式临时消息，而不是仅按最后一条消息的角色判断。
