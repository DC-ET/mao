## 问题清单

### 【中】子代理首轮（消息区为空）重试提示不可见；SideChatPanel 亦无 typingRetry 兜底

- 位置：
  - `desktop/src/components/chat/SubagentChatPanel.vue`（模板 15-21 行：`ChatRoundList v-if="displayMessages.length > 0"`；无任何重试提示渲染）
  - `desktop/src/components/chat/SideChatPanel.vue`（同样只有三点式 `typing-indicator`，无重试文案兜底）
- 根因：重试提示的两种承载方式在子代理/边路首轮均落空——
  1. `MessageBubble` 重试条要求「最后一条 assistant 消息（`isLast`）且该会话 `thinking/streaming` 为 true」；子代理首轮在收到首个内容事件（`thinking_delta`/`content_delta`）前**消息列表为空**（子代理消息由 `ensureStreamingAssistantMessage` 在收到 delta 时才创建，无本地占位消息），`ChatRoundList` 整体不渲染 → 无承载；
  2. `typingRetry` 兜底仅实现在主会话 `ChatPanel.vue`，`SubagentChatPanel` / `SideChatPanel` 均未实现。
- 影响：子代理在 LLM 瞬时错误重试期间，面板只显示「三点」/空态，用户无法得知模型正在重试，违背本需求「避免重试期间界面无响应」的目标。边路面板真实会话阶段因有占位 assistant + `thinking=true` 可显示，但占位窗口期同样无兜底（见下条）。
- 建议：将 `typingRetry` 类似逻辑（按会话 `getLlmRetry(sid)`，最后一条消息非 assistant 或列表为空时显示）下沉复用到 `SubagentChatPanel` 与 `SideChatPanel` 的 typing-indicator 区域；子代理面板无输入区时可在消息区顶部/底部显示。

### 【低】`typingRetry` 触发场景与注释描述不符，且断线竞态下首轮重试两处均不可见

- 位置：`desktop/src/components/chat/ChatPanel.vue:312-324`（`typingRetry` 及注释）
- 说明：
  1. 注释称「首轮重试场景，消息区无 MessageBubble 承载重试条」——实际首轮 `useChat.sendMessageAndWaitForSave` 会**立即创建占位 assistant 消息**（`useChat.ts` `addAssistantMessage`），且 `thinking_start` 先于 `llm_retry`，因此首轮重试由 `MessageBubble` 承载，`typingRetry` 恒为 null。`typingRetry` 真正生效的场景是「**恢复会话后最后一条为 user**」等（此时后端不落库空 assistant 消息）。注释有误导性，建议修正为实际触发条件。
  2. 竞态缺口：若 WS 断线发生在 `thinking_start` 之后、`llm_retry` 之前（重连后 `thinking_start` 不会重发，`thinking=false`），且最后一条为占位 assistant（空内容、无 running toolCall）→ `isAssistantRunning=false`（气泡内不显示）且 `typingRetry` 因最后一条是 assistant 返回 null（底部不显示）→ 重试提示完全不可见。概率低（需重试恰逢断线窗口），但两处条件均依赖 `thinking` 状态，无本地兜底。
- 建议：`typingRetry` 的「最后一条非 assistant」判据可放宽为「最后一条 assistant 消息**不满足 `isAssistantRunning`**（即无 thinking/streaming/running tool）」时也允许底部兜底显示，以覆盖竞态场景；或维持现状（概率低，仅记录）。

### 【低】SideChatPanel 占位窗口 `session-id=''` 回退主会话（遗留，前几轮已提）

- 位置：`desktop/src/components/chat/SideChatPanel.vue:21`（`:session-id="hasRealSession ? String(realSessionId) : ''"`）
- 说明：首次发送边路消息、`side_session_created` 未返回的占位窗口内，`isAssistantRunning` 与 `llmRetry` 均回退主会话 `active*`。若主会话恰好正在重试，边路占位消息会误显主会话的重试条；边路自身重试则不可见。实际时序上 `llm_retry`（带真实 sid）在 `side_session_created` 之后才可能到达，窗口极短，影响可忽略。建议维持现状或占位阶段不渲染消息列表。

### 【提示】`showStreamIndicator` 仍使用主会话 `activeStreaming`，与 `isAssistantRunning` 的按会话读取不一致

- 位置：`desktop/src/components/chat/MessageBubble.vue:235-237`
- 说明：本轮将 `isAssistantRunning` 改为按 `props.sessionId` 读取 `isSessionStreaming/Thinking`，但 `showStreamIndicator` 仍读 `sessionStore.activeStreaming`。边路/子代理消息在自身会话 streaming 而主会话未 streaming 时不显示三点指示器（漏显），反之主会话 streaming 时可能错显。属既有行为（非本需求引入），但本轮改动后两者语义不一致更明显，建议一并对齐。

### 【提示】`buildScrollAnchor` 未纳入 llmRetry 状态，重试条出现不触发自动滚动

- 位置：`desktop/src/components/chat/ChatPanel.vue` `buildScrollAnchor`（聚合了 `activeThinking/activeStreaming/showTypingIndicator` 等，未含 `activeLlmRetry`）
- 说明：重试条出现/消失不触发 `scrollToBottom`。主会话重试条位于底部打字区（通常可见），影响小；`MessageBubble` 内重试条若用户已上滑则不可见且不自动滚回。建议将 `sessionStore.activeLlmRetry?.attempt` 纳入 anchor。

### 【提示】`llm_retry` 分支未做字段级校验

- 位置：`desktop/src/composables/useStreamWS.ts:750-758`
- 说明：仅 `sessionId && data` 守卫，未校验 `statusCode/attempt/maxRetries/delaySeconds` 的存在性与类型；后端 payload 固定（`WsStreamingEventListener.onLlmRetry` 恒写四字段），风险低。可保持现状。
