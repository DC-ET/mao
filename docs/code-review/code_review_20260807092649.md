## 【中】新关键词防抖窗口内，旧关键词在途请求完成会覆盖回「结果态」，Enter 仍可跳转到旧会话（前两轮同族问题修复残留）

**位置**：
- `desktop/src/components/search/SessionSearchPopover.vue`
  - 第 121-136 行（`onKeywordInput`：非空分支**只清空 results/status 并置 loading，未使旧关键词的在途请求失效**——未 `requestSeq++`、未 `abortController.abort()`）
  - 第 138-155 行（`runSearch`：`const seq = ++requestSeq` 只在**新一次 runSearch** 时递增，响应落地仅校验 `seq !== requestSeq`）
  - 第 172-177 行（`onPanelKeydown` Enter 分支：`if (status.value !== 'results') return`，被下方场景覆盖后守卫失效）

**问题描述**：
上一轮修复覆盖了两个窗口：「请求在途期」（`runSearch` 开头清空）与「防抖窗口期」（`onKeywordInput` 置 `loading`）。但存在第三种泄漏路径：**旧关键词的请求仍在途时用户输入新关键词**——

1. 用户输入 A（停顿 300ms）→ `runSearch(A)` 发出，请求在途（seq=1）；
2. 请求尚未返回时用户改为输入 B → `onKeywordInput` 清空 results、置 `status='loading'`，但**没有 bump requestSeq，也没有 abort 在途请求**；
3. A 的请求在 B 的 300ms 防抖窗口内返回 → `seq(1) === requestSeq(1)` 成立 → 响应落地：`results=[A 的结果]`、`status='results'`——**旧关键词结果重新显示，且输入框内容已是 B**；
4. 此时按 Enter，`status === 'results'` 守卫通过，`results[activeIndex]` 命中 A 的结果 → `handleJump` 跳转到与当前输入无关的旧会话。

**影响**：
- UI 在最多 300ms 窗口内展示与输入不符的旧结果；
- 该窗口内按 Enter 会跳转到错误会话（与前两轮报告的「输入新词后立即回车跳旧结果」同一用户可感知故障，本轮仅收窄了窗口、未彻底关闭）。
- 触发条件：用户在上一关键词请求在途时继续编辑关键词（远程 API 请求耗时 200ms+ 时常见）。

**建议修复方向**：
在 `onKeywordInput` 非空分支、设置防抖定时器之前，同步使在途请求失效（保留新防抖定时器，不能整体调用 `invalidatePending`，否则会误清刚设置的 timer）：
```ts
results.value = []
activeIndex.value = 0
status.value = 'loading'
requestSeq++                 // 使旧关键词在途响应的 seq 校验失败
abortController?.abort()
abortController = null
debounceTimer = window.setTimeout(() => { runSearch(kw) }, 300)
```
或等价地：`runSearch` 响应落地前再校验「本次响应对应的关键词仍等于当前输入」（`kw === keyword.value.trim()`），不匹配则丢弃。
