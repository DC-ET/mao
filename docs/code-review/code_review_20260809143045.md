## 二、新发现问题

### Q4-1【中】ask_user_questions 超时/取消/断连路径未发布 tree 信号（与主会话降档滞留同源）

**位置**
- `ToolDispatcher.dispatchAskUserQuestions`：`backend/src/main/java/cn/etarch/mao/harness/tool/ToolDispatcher.java` 第 262~269 行

```java
// Block until user responds (with timeout)
String result = askUserQuestionsRegistry.waitForAnswer(sessionId, requestId);

// If timed out or errored, notify client to dismiss the question panel
if (result != null && result.contains("\"error\"")) {
    ...
    streamingWsRegistry.send(userId, WsEvent.of("ask_user_questions_cancelled", sessionId, cancelData));
    // ❌ 此处未调用 treeSignalPublisher.publishForSession(sessionId)
}
```

**问题**
`waitForAnswer` 超时（15min）/ 会话取消 / 断连时，`AskUserQuestionsRegistry.waitForAnswer` 内部会 `pending.remove(...)`（计数归零），且 `failAllForSession` 路径同样令 future 返回 error → 本分支执行。但**只发 `ask_user_questions_cancelled`，没有重推 tree 信号**：

- **主会话自身**：`treePendingQuestionCount` 快照残留 1 → 前端聚焦排序 `Math.max(1, 实时0)=1` → priority 0「待回答」**滞留**，且主会话继续执行至 COMPLETED 后仍滞留（TaskTerminalService 不对主会话发布 tree）——正是本轮 reviewer 修复的「降档滞留」问题在超时路径上的残留版，直到列表刷新才恢复。
- **边路任务**：父任务 `treePendingQuestionCount` 残留 → 父任务错置顶；若边路任务随后进入终态（TaskTerminalService 发布父任务）则自愈，若长时间运行则滞留。

**修复建议**
在本分支（发 `ask_user_questions_cancelled` 处）追加一行：

```java
treeSignalPublisher.publishForSession(sessionId);
```

一处修复即可覆盖超时 / 取消 / 断连所有 error 路径（它们都汇聚到 waitForAnswer 返回 error）。

### Q4-2【低】LocalToolExecutorTest 弱断言（恒真）

**位置**
- `LocalToolExecutorTest.doesNotRegisterApprovalForNonApprovalRequests` 第 82 行：`verify(treeSignalPublisher, never()).publishIfSideTask(7L)`

**说明**
生产代码已改用 `publishForSession`，该断言恒真（publishIfSideTask 永不被 LocalToolExecutor 调用），无法真正验证「非审批请求不发布」。建议改为 `verify(treeSignalPublisher, never()).publishForSession(7L)`，与其余两处 `times(2)` 断言口径统一。
