## P2

### P2-1. `observe` 用脱敏后的 `descriptor.value` 做状态比较，与 `inspect` 的脱敏口径不一致 → 敏感字段 `updated` 误报（并漏报真实变化）

**位置**
- `sdk/embed/src/page/snapshot-manager.ts:36-40`（`stateKeyOf` 比较 `descriptor.value`）
- `sdk/embed/src/page/snapshot-manager.ts:152`（`observe` 恒定 `redactSensitive: true`）
- `sdk/embed/src/page/engine.ts:163-164` + `sdk/embed/src/page/authorization.ts:289-294`（`inspect` 在 `full`、或 `task` 命中当前会话时 `redact = false`，即不脱敏）

**问题**
`observe` 的当前扫描恒定为 `redactSensitive: true`，但 `previous` 快照里的 `descriptor.value` 取决于 `inspect` 时的授权级别。当 `inspect` 未脱敏时，同一敏感字段的前后状态是「真实值」vs `'[REDACTED]'`，`stateKeyOf` 必然不相等 → 页面其实没有任何变化也会计入 `updated`。这是本轮新增比较逻辑后才出现的（改动前 `value` 根本不参与比较）。

**复现（实测，happy-dom，探针用例已删除）**
- `<input type="password" value="s3cret">` → `inspect({redactSensitive:false})` 后立即 `observe`：`{added:0, removed:0, updated:1}`（实际未变，误报）。
- 对照组：`<input type="text" value="x">` 未变 → `updated:0`；改为 `value='b'` → `updated:1`（符合预期）。
- 同源副作用（反向）：`per_action`（默认脱敏）下 `inspect({redactSensitive:true})`，把 password 由 `'a'` 改成 `'b'` → `{updated:0}`（漏报，两侧都是 `'[REDACTED]'`）。此条改动前也是 0，属残留缺口而非回归，但同一处可一并解决。

**影响**
`full` 授权（用户已持久化完全授权）或 `task` 授权命中会话时，只要页面存在密码 / 验证码 / 银行卡 / 身份证等 `isSensitiveField` 命中的字段，`page_observe` 会**恒定多报 `updated`**，误导模型认为页面发生了变化，可能触发无意义的重新 inspect / 追加动作。反向缺口则让敏感字段的真实值变化无法被 observe 发现。

**建议（任选其一，均为小改动）**
1. `observe` 不必强制脱敏：它只返回计数 / URL / 标题，不返回任何 `value`，强制脱敏没有收益。改为与快照同口径：
   `const scan = scanPage({ ...this.options, includeHidden: false });`
2. 或让 `stateKeyOf` 对 `descriptor.sensitive === true` 的字段不比较 `value`（返回 `null`），使两侧都不可比。
3. 或按上一轮 P3-2 的原意改用执行器 `stateOf` 的「实时 DOM 值」口径，彻底绕开 descriptor 的脱敏差异。
4. 补两条回归用例：敏感字段未变化 → `updated=0`；敏感字段真实变化 → `updated=1`。

## P3

### P3-1. iframe 用例可能静默跳过（当前环境有效，但缺少防退化断言）

**位置**：`sdk/embed/src/page/executor.spec.ts:53-67`，`if (!doc?.body) return; // 环境不支持 iframe 文档时跳过`

**问题**：一旦运行环境不支持 iframe 文档，用例会静默通过，失去回归保护能力。

**实测结论（有效，不是被跳过）**：happy-dom 20.14 下 `iframe.contentDocument` 与 `.body` 均存在；`input.focus()` 后 `iframeDoc.activeElement === input`，而顶层 `document.activeElement` 为 `BODY`（≠ input）。因此把 `dispatchBlur` 改回 `document.activeElement` 时，该用例会失败（blur 不会被派发），用例确实守住了本次修复。

**建议**：把「静默跳过」改为显式前置断言（如 `expect(doc?.body).toBeTruthy()`），环境不支持时直接失败而不是假装通过；同时保留已有的主文档 blur 对照用例。

### P3-2. 新增用例未覆盖 text / select 状态变化与「未变化 = 0」负例

**位置**：`sdk/embed/src/page/snapshot-manager.spec.ts:76-85`

**问题**：只覆盖了 checkbox 的 `checked`。实测 text 输入 `value` 变化、select `selected` 变化均能正确计入 `updated`，但无回归用例；且缺少「页面完全未变 → `updated=0`」的负例——该负例恰好能捕获 P2-1 的误报。

**建议**：补 text input、select 两个正向用例 + 一个「未变化」负例（敏感字段与非敏感字段各一条更佳）。

## 重点复核结论

1. **`dispatchBlur` 改用 `ownerDocument`**：主文档元素 `ownerDocument === document`，既有行为完全不变（shadow DOM 内元素仍与 `executeFocus` 同口径，未新增回归）；同源 iframe 缺口已闭合，新增用例真实有效（见 P3-1 实测）。
2. **`observe` 的 `updated` 逻辑**：
   - 签名不变但 `value` / `checked` / `selected` 变化已正确计入 `updated`（实测 text、checkbox、select 均 `updated=1`）；checkbox/radio 的 `checked` 通过 `descriptor.value = {checked, value}` 覆盖。

   - 已知接受项「更新元素新签名恰好等于某被移除元素签名」的窄边界仍存在，属已知接受范围，不再重复报告。
3. **`page_observe` 描述与实际返回一致**：`page-tools.ts:111` 新增的「值/勾选状态变化」与 `observe` 返回的 `changes.updated` 口径吻合（`updated` 覆盖 value/checked/selected 及签名/属性变化），无夸大。
4. **产物同步正确**：`desktop/public/embed/mao-chat.js` 与 `mao-chat.v0.1.1.js` 字节完全一致，且均包含 `ownerDocument.activeElement` 与新的 observe 比较逻辑（压缩后的 `ql` 函数），与源码一致。
