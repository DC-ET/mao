# 代码审查报告

审查对象：`sdk/embed` 本次未提交改动（worktree `embed-page-agent`）

## 高严重度

### [高] 元素引用没有快照版本校验，旧引用可能作用于错误的新元素

- 位置：`sdk/embed/src/page.ts:55-58, 61-67`（`PageSnapshotManager.execute`）
- 问题：`elementId` 只在内存 `Map` 中映射到 DOM 节点，没有要求调用方提供 `snapshotId/pageVersion`，也没有在执行前确认页面仍与生成引用时一致。页面重新渲染后，原节点可能已脱离文档（此时会失败），但更常见的是客户端继续使用同一引用执行后续动作，动作与当前页面快照不再对应；若节点被框架复用或页面局部状态变化，则可能对错误状态执行操作。公开 API 的元素引用因此不是稳定、可验证的快照引用。
- 修复建议：让动作携带 `snapshotId`（或 pageVersion），执行时强制匹配当前快照；页面发生导航/DOM 版本变化时使引用失效并返回明确的 `stale_snapshot`。必要时每次动作后重新生成快照/引用，而不是继续复用旧 Map。

### [高] `select` 对非法值仍返回成功，调用方无法知道实际未完成选择

- 位置：`sdk/embed/src/page.ts:65`
- 问题：直接执行 `select.value = action.value` 后派发 `change`，即使 value 不存在于 options 中，浏览器会将 value 设为空字符串，代码仍无条件返回 `success: true`。这会让 Agent 误以为选择成功并继续后续流程。
- 修复建议：执行前确认目标为 `HTMLSelectElement`、未禁用/只读，并确认存在匹配且未禁用的 option；执行后校验 `select.value === action.value`，否则返回失败及 `option_not_found`/`option_disabled`。

## 中严重度

### [中] 动作类型与元素类型未校验，错误动作会被伪成功接受

- 位置：`sdk/embed/src/page.ts:61-67`
- 问题：`fill`/`keyboard` 将任意引用强制转换为 `HTMLInputElement`，对 button、link 等元素可能只派发事件；`check`/`uncheck` 对非 checkbox/radio 也可能调用 `click()`；`click` 对 disabled 元素调用原生 `.click()` 通常不会触发实际行为，但仍返回成功。结果不能代表动作真的符合目标元素语义。
- 修复建议：按 snapshot 的 kind/role/type 在执行前做严格矩阵校验；对 disabled、readonly、不可编辑控件返回明确错误，并在必要时验证状态变化。

### [中] `scroll` 的 elementId 无效时静默退回滚动文档

- 位置：`sdk/embed/src/page.ts:60-61`
- 问题：非 scroll 动作才检查元素存在；scroll 传入不存在或过期的 `elementId` 时，`el || document.scrollingElement` 会改为滚动整个页面，并返回成功。这可能滚动错误容器，且掩盖引用失效问题。
- 修复建议：若调用方提供 `elementId`，必须要求引用存在、仍在文档中且为可滚动目标；只有未提供 elementId 时才允许滚动 document，并校验坐标为有限数值。

### [中] `pageVersion` 生成与返回不一致，不能用于检测页面变化

- 位置：`sdk/embed/src/page.ts:57, 68`
- 问题：快照版本包含 `Date.now()`，每次 inspect 都必然不同；动作返回的版本又省略时间戳和 snapshotId。该字段既不能稳定比较，也不能表达动作前后实际页面版本，公开 API 使用者无法据此判断快照是否过期。
- 修复建议：使用可重复计算且与 DOM/navigation 状态相关的版本（或直接使用 snapshotId + 明确的 mutation/navigation 失效策略），并统一快照和动作结果的版本格式。

## 低严重度

### [低] 填充逻辑在 value setter 不存在时仍返回成功

- 位置：`sdk/embed/src/page.ts:66`
- 问题：`setter?.call(...)` 使用可选调用；当目标不是支持 value setter 的控件时，代码仍派发 input/change 并返回成功，实际值可能未改变。
- 修复建议：setter 不存在时直接返回 `element_not_fillable`；执行后读取并校验值（contenteditable 单独校验 DOM 状态）。

## 审查结论

发现上述功能逻辑问题，尤其是公开元素引用缺少快照代际校验，以及动作结果存在“未执行却成功”的情况。未修改任何已有代码。
