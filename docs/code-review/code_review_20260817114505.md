# 代码审查报告

## 中风险

### 1. 升级后的新主会话没有复制上下文锚点，继续对话时 token 统计会失真
- **位置**：`backend-ts/src/session/session.service.ts:443-445`、`backend-ts/src/session/session.service.ts:457-474`
- **问题**：升级边路任务时，新会话复制了 `contextTokens` 和 `lastPromptTokens`，但没有复制 `contextAnchorMsgId`；同时消息是重新插入到新会话的，原边路任务里的锚点消息 id 即使直接复用也需要通过 `messageIdMap` 映射到新消息 id。当前结果是新主会话可能出现 `lastPromptTokens > 0` 但 `contextAnchorMsgId` 为空/0 的不一致状态。
- **影响**：后续继续在新主会话对话时，`loadContextAnchor()` 无法命中有效锚点，`ActiveContextCalculator` 会退回按完整请求估算；而会话列表/上下文窗口仍可能展示从源边路任务复制来的 `contextTokens`，导致上下文 token 显示和实际执行不一致。对于已有较长历史的边路任务，升级后第一次继续对话的上下文窗口判断可能偏差明显。
- **修复建议**：在复制消息后，根据 `messageIdMap.get(source.contextAnchorMsgId)` 设置新会话的 `contextAnchorMsgId`；如果源锚点不存在或无法映射，则不要复制 `lastPromptTokens/contextTokens`，将 `lastPromptTokens/contextAnchorMsgId/contextTokens` 重置为 0/null，让新会话从完整历史重新计算。
