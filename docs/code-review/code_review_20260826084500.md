## 中严重度

### [中] `onRoundStart` 只更新内存 round，不会在每轮结束时刷新卡片，导致多轮进度和工具摘要错误

**位置：**
- `backend-ts/src/harness/core/agent-loop.ts:152-154`
- `backend-ts/src/feishu/card-progress-listener.ts:33-35, 37-39`
- `backend-ts/src/harness/core/agent-loop.ts:427`

`AgentLoop` 在每次进入循环时调用 `listener.onRoundStart(round)`，但 `FeishuCardProgressListener.onRoundStart` 仅赋值 `this.round`。卡片的 RUNNING 更新仍只在 `onMessageEnd` 中排队，而 `onMessageEnd` 只在整个 `while` 循环结束后调用，并不是每一轮 LLM 输出/工具执行完成时调用。

因此，包含工具调用的多轮执行不会按轮更新卡片：前面各轮没有 RUNNING 更新；最终那次更新使用最后一轮的 round 值，但其 `tools` 是从整个执行期间累积的 Map（此前没有按 round 清理），`content` 也只反映当前保留的内容状态。用户会看到缺失的中间进度，且“本轮工具”可能混入之前轮次的工具，无法满足卡片 round 生命周期和工具摘要的语义。

现有 `card-progress-listener.spec.ts` 仅直接手工调用一次 `onMessageEnd`，没有模拟 AgentLoop 的“round start → LLM → 工具 → 下一 round”时序，因此未覆盖该问题。

**修复建议：**

1. 在 AgentLoop 中定义并触发明确的每轮结束/进下一轮前事件（应发生在当前轮流式输出、工具执行及对应持久化完成后），携带当前 round 的内容和按 toolCallId 匹配的工具摘要；不要把整个执行结束的 `onMessageEnd` 当作 round 事件。
2. 或为 listener 增加专用 round flush 方法：每轮 flush 后再清理内容与工具集合，进入下一轮时不混入历史工具；`onRoundStart` 只负责设置当前轮编号。
3. 补充至少两轮、每轮含工具调用的 AgentLoop/handler 集成测试，断言依次收到 round 1、round 2 的 RUNNING 更新及各自工具摘要，并验证最终终态卡片只发送一次。

## 已核验未发现问题

- `CompositeAgentEventListener` 对新增可选 `onRoundStart` 使用可选调用，旧 listener 不实现该方法时不会抛错；既有 listener 的事件转发方式未见回归。
- 终态卡片更新成功时 handler 返回 `null`，避免重复发送普通文本；卡片创建失败或终态更新失败时保留纯文本兜底。
- 失败/取消路径会先等待已排队的卡片更新，再发送对应终态；普通执行失败不会因卡片更新异常而阻断主流程。
- AgentLoop 的 `onRoundStart` 为可选接口扩展，既有 AgentLoop 调用方无需实现新方法。
