# 代码审查报告（复核）：后台子代理取消级联加固

- 审查范围：当前 git 工作区未提交改动（重点为 `cancelAllForParent` 加固）
- 审查时间：2026-08-16 14:32
- 结论：加固整体正确，解决了「父取消与父 phase 落库窗口内子代理仍启动」的副作用问题；但引入 2 个低风险清理/竞态瑕疵，均不影响主流程功能正确性。

---

## 加固内容核对

新增 `BackgroundSubagentManager.cancelAllForParent(parentSessionId)`，并在 `StreamingWsHandler.abortSubagentChildren` 中于 child cancel flag 之前调用。逻辑为：

1. `listByParent` 取出父会话下所有 execution；
2. 过滤 `invocationType === 'BACKGROUND'` 且非终态的 execution；
3. 对每个：复用/注册 child cancel flag 并置 true；`updateById` 落库为 `CANCELLED + delivery_status=SUPPRESSED`。

核对结果：该加固能正确让「排队中尚未启动」的 `runBackground` 在启动前二次校验命中 `isTerminal` 而跳过执行，达到防副作用的目的。child cancel flag 的复用方式与 `cancel()` 一致，无 flag 覆盖问题。

## 新发现问题

### A（低）`cancelAllForParent` 落库终态后，未把 child session 标记为终态

- 文件：`backend-ts/src/harness/delegate/background-subagent-manager.ts`
- 位置：`cancelAllForParent()`（约第 209-227 行）与 `runBackground()` 二次校验 return（约第 289-292 行）

问题链路：

1. `spawn` 创建 child session 时 `phase = null`，只有 `executeVisible` 进入 `runVisible` 才会 `updatePhase('RUNNING')`；
2. 对「排队中尚未启动」的后台子代理，`cancelAllForParent` 将 execution 落库为 `CANCELLED/SUPPRESSED`，但没有调用 `finishSubagent` 或 `updatePhase` 把 child session 标记为 `CANCELLED`；
3. 之后 `runBackground` 启动，二次校验发现 execution 已终态，`return` 直接返回（也不 `finishSubagent`），child session 永远停留在 `phase = null`。

影响：execution 已终态而 session 未终态，属于数据状态不一致。该 child session 不会被崩溃恢复处理（execution 已 SUPPRESSED），也不会进入终态，仅作为残留记录。对父会话功能无影响。

修复建议：`cancelAllForParent` 落库后同步调用 `finishSubagent(childSessionId, childSession.userId, 'CANCELLED', '')`；或在 `runBackground` 的「二次校验 isTerminal → return」路径补一次 `finishSubagent`，与 `markCancelledSuppressed` 路径保持一致。

---

### B（低）`SUPPRESSED` 可能被 `onCompleted` 覆盖为 `DELIVERED`

- 文件：`backend-ts/src/harness/delegate/background-subagent-manager.ts`
- 位置：`cancelAllForParent()`（约第 209-227 行）与 `onCompleted()`（约第 366-384 行）

问题链路：

1. 对「正在运行」的后台子代理，`cancelAllForParent` 先落库 `CANCELLED/SUPPRESSED` 并设置 child flag；
2. 子代理响应取消退出后，`runBackground` 走到 `onCompleted(execution, ..., 'CANCELLED', ...)`；
3. `onCompleted` 查询父 session phase：若父 phase 尚未落库为终态（`finishCancelledSession` 仍在执行），则进入「父未终态」分支，写入 `resultsByParent`、调用 `persistCompletionNotice` 插入一条「后台子代理已取消」消息，并将 deliveryStatus 覆盖回 `DELIVERED`；
4. 这与 `cancelAllForParent` 的 `SUPPRESSED` 意图冲突，会在已取消的父会话中残留一条通知消息（`cleanupIncompleteTail` 不会清理无 toolCalls 的独立 ASSISTANT 消息）。

影响：仅在「子代理退出速度快于父 phase 落库」的低概率窗口出现，表现为取消后的父会话多一条通知消息，无数据丢失、无副作用。属既有投递逻辑与加固的交互竞态。

修复建议（可选）：`onCompleted`/`failExecution` 在「父会话正在取消/已取消」时应保持一致地走 `SUPPRESSED`。可在 `cancelAllForParent` 中记录取消意图（如复用内存集合或检查父 cancel flag），或在 `onCompleted` 中同时检查 `deliveryStatus === 'SUPPRESSED'` 时不再覆盖为 `DELIVERED`。

## 总体结论

加固本身正确，能达到预期目的，未引入严重功能 bug。上述 A、B 均为低风险清理/竞态问题：A 建议顺手修复（child session 状态一致性），B 为低概率 UI 噪音，可后续处理。

在不强制修复 A、B 的前提下，本次后台子代理功能整体可判定为 **通过**。
