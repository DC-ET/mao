# 代码审查报告

## 高风险

### 1. 升级边路任务的校验与删除不在同一事务内，重复点击可能创建多个主会话
- **位置**：`backend-ts/src/session/session.service.ts:404-449`、`backend-ts/src/session/session.service.ts:454-527`
- **问题**：`promoteSideTaskToMainSession()` 在事务外读取并校验源边路任务，随后才进入事务复制并逻辑删除源会话；事务内没有重新加锁/复查源会话仍未删除。若用户连续双击“升级为主会话”、多个客户端同时请求，或前端重试同一请求，多个请求都可能在源会话被删除前通过 `getSession()` 和状态校验，然后各自在事务中插入一个新的 `NORMAL` 会话并复制同一批消息。后续 `logicalDelete(sideSessionId)` 对已删除源会话不会阻止第二个事务提交。
- **影响**：同一个边路任务可能被升级成多个内容相同的主会话，主会话列表出现重复数据，用户继续工作时也无法判断哪个才是有效升级结果。
- **修复建议**：将源会话加锁、类型/状态/子会话校验、创建新会话、复制数据、删除源会话放到同一个事务中执行。可在事务内使用 `SELECT ... FOR UPDATE` 锁定源 `session`，并在删除时要求 `deleted = 0` 且检查影响行数；如果影响行数为 0，返回“边路任务已升级/已删除”之类的业务错误，避免重复创建。
