## 二、新发现问题

### P（中）主会话自身审批/待回答「降档滞留」——并集的 tree 快照在结束时不会实时归零

- **位置**：
  - 前端：`desktop/src/stores/session.ts` `focusedSessions` computed（`Math.max(tree*, realtime)` 并集）
  - 后端：`LocalToolExecutor.java`（64/98 行）、`ToolDispatcher.java`（228 行）、`StreamingWsHandler.java`（ask_user_questions_cancelled 分支）——审批/待回答 register/unregister/complete 均只调 `treeSignalPublisher.publishIfSideTask(sessionId)`
- **机制**：
  1. **升档路径（正确）**：主会话自身 `tool_execute`/`ask_user_questions` 事件到达 → 前端 `sessionPendingApprovals`/`sessionPendingQuestions` 计数 → 并集 `max` 立即 priority 0 ✓
  2. **降档路径（缺口）**：审批/待回答结束时——
     - 前端 `decrementPendingApproval`/`removeAskQuestion` 将实时计数归零；
     - 后端 `publishIfSideTask` 只对 `sessionType == SIDE_TASK` 生效，**主会话自身不推送 session_tree_status**；`ApprovalRegistry` 也只发 `session_status`/`session_list_update`（phase 事件），不发 tree\*；
     - 实体 `treePendingApprovalCount`/`treePendingQuestionCount` 仍是**进入聚焦时的服务端快照**。若该快照包含主会话自身 pending（即拉取列表时审批/待回答正挂起——恰是聚焦模式要处理的核心场景），则 `max(快照>0, 0) = 快照 > 0` → 任务仍停留在 priority 0「待审批」，**直到手动刷新列表或下次列表拉取才降档**。
- **影响**：聚焦模式核心场景（看到「待审批」→ 处理掉 → 任务应降档）下，主会话自身审批/待回答处理完毕后仍置顶显示「待审批」，需手动刷新才恢复。与 H-1 修复前同类的「排序与真实状态不一致」，只是方向相反（假性待审批而非漏提示）。边路任务路径不受影响（后端 register/unregister 已推父会话 tree\*）。
- **修复建议**（后端一处即可根治，前端并集无需改）：
  给 `SessionTreeSignalPublisher` 增加统一发布方法，替换三处 `publishIfSideTask` 调用：
  ```java
  /** 边路任务推父会话，主会话推自身（审批/待回答 register/unregister 场景）。 */
  public void publishForSession(Long sessionId) {
      Session s = sessionMapper.selectById(sessionId);
      if (s == null) return;
      Long target = "SIDE_TASK".equals(s.getSessionType()) && s.getParentSessionId() != null
              ? s.getParentSessionId() : sessionId;
      publish(target);
  }
  ```
  调用点：`LocalToolExecutor`（审批 register 64 行 / unregister 98 行）、`ToolDispatcher`（待回答 register 228 行）、`StreamingWsHandler`（ask_user_questions_cancelled 处）改调 `publishForSession`。
  注意 `ApprovalRegistry` 不要直接注入 `SessionTreeSignalPublisher`（两者相互依赖会形成循环，`SessionTreeSignalPublisher` 依赖 `ApprovalRegistry.countForSessionIds`），在调用方（LocalToolExecutor 已同时注入两者）发布即可。

## 三、核对通过项（无问题）

- **标签/排序一致性**：priority 0（WAITING_APPROVAL phase / pending>0）↔ 标签「待审批/待回答」；priority 1（FAILED/treeFailed）↔「已失败」+ status-failed；priority 2（RUNNING_PHASES/treeRunning）↔「运行中/恢复中/取消中」+ status-running；全部一致。
- **并集响应性**：`sessionPendingApprovals`/`sessionPendingQuestions` 是 `ref(Map)`（Vue 对 Map 走 reactive 包装），`.set`/`.delete` 均触发 `focusedSessions` computed 重算；且只在副本上取 max，不污染实体。
- **WAITING_APPROVAL 与并集无冲突**：`focusPriority` 第一行 `phase === 'WAITING_APPROVAL'` 直接归 0，与并集计数路径并存不重复。
- **边路实时计数不误伤主会话**：边路任务的 pending 计数落在边路 sessionId key 上，`focusedSessions` 只迭代主会话，不会错配。
- **已读分流无遗漏**：主会话 `markAsRead` 与边路 `markSideTaskRead` 两条路径的后端重推均已覆盖；前端 `markAsRead` 成功回调清实体 `unread`、`treeUnread` 依赖后端推送的链路已闭环。
- **测试**：24/24 通过；新增用例（treeFailed 升档、历史边界、深链接回归、自动重排）与修复一一对应。
