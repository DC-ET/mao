## 中等严重程度

### 1. 未配置 upstream 时，只要仓库存在任意提交，推送按钮就会启用

**代码位置：** `desktop/src/components/task/GitChangeList.vue:114-119`

**问题说明：**

`pushDisabledReason` 在当前分支没有配置 upstream 时不会检查 ahead 数，只检查 `hasHead`。但 `hasHead` 仅表示仓库至少有一个提交，并不表示该提交尚未存在于远端。

因此，在本地分支与 `origin/<branch>` 完全同步、但 upstream 被取消或从未设置的场景中，手动 fetch 成功后推送按钮仍会启用。实际执行 `git push --set-upstream origin <branch>` 只会返回 `Everything up-to-date`，不符合“没有提交可推送时禁用推送”的需求。CLOUD 与 LOCAL 模式共用该前端判断，两种模式均受影响。

**修复建议：**

刷新状态时，为无 upstream 的分支确认本次选中远端是否存在同名分支：

- 若存在 `<remote>/<currentBranch>`，计算 `HEAD...<remote>/<currentBranch>` 的 ahead/behind，并向前端返回明确的 `hasCommitsToPush` 或等价状态；ahead 为 0 时禁用推送。
- 若远端不存在同名分支，则 `hasHead=true` 时可视为存在首次推送的提交并允许推送。
- 不要仅用 `hasHead` 推断是否可推送，因为它无法区分“远端已有相同提交”和“远端尚无该分支”。

建议为 CLOUD 和 LOCAL 各补充一条“远端同名分支与本地同步，但未配置 upstream”的测试，并断言推送不可用。
