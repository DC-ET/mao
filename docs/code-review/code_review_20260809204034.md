## 中等严重程度

### 1. LOCAL 提交输入在进入有界读取前，仍会通过 `collectChangedFiles()` 整文件读取未跟踪文件

**代码位置**

- `desktop/electron/gitOperations.cjs:173`
- `desktop/electron/gitStatus.cjs:79-83`
- `desktop/electron/gitStatus.cjs:163-179`

**问题说明**

`buildFileDiff()` 已改为最多读取 `200KB + 1` 字节并在 `finally` 中关闭句柄，这一处修复正确。但 `buildCommitInput()` 在调用它之前会先执行：

```text
collectChangedFiles(repoRoot)
```

`collectChangedFiles()` 为统计每个未跟踪文件的二进制状态和新增行数，会调用 `readTextLimited()`；而 `readTextLimited()` 仍使用 `fs.readFileSync(filePath)` 读取整个文件，之后才调用 `truncateText()`。

因此点击 LOCAL 提交时，大型未跟踪文件仍会先在 Electron 主进程中被完整读入内存，随后才进入本轮新增的有界读取逻辑。第四轮报告中的主线程阻塞、高内存或主进程崩溃风险实际上仍可发生，只是直接读取点从 `buildFileDiff()` 转移到了它的上游依赖。

此外，Git 状态刷新和一级子仓库汇总也复用 `readTextLimited()`，大型未跟踪文件同样可能导致状态刷新卡顿。

**建议修复**

将 `gitStatus.cjs` 的 `readTextLimited()` 本身改为有界读取，使所有调用方统一受限，而不是只限制 `buildFileDiff()`。可读取 `MAX_DIFF_BYTES + 1` 字节（或更小的二进制检测前缀），根据文件实际大小和额外字节设置 `truncated`，并保证句柄在 `finally` 中关闭。

补充大型未跟踪文件的调用链测试，直接执行 `buildCommitInput()`，并通过 mock/spies 或稀疏大文件验证 `collectChangedFiles()` 不会申请与文件总大小相等的 Buffer。
