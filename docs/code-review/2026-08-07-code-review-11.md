## 结论摘要

本轮两处滚动改动均正确，未引入新的高/中严重度 bug：

- **`SideChatPanel.buildScrollAnchor` 纳入 llmRetry**：watch 源读取 `sessionLlmRetry.value.get(key)`（`ref<Map>` + 键级 track/trigger），响应式成立；锚点值仅在重试条「出现（'' → 'retry'）/消失（'retry' → ''）」时变化，`attempt` 递增不改变锚点字符串 → 不会频繁滚动，符合「重试条出现时自动滚动」的目标且无性能问题；`scrollToBottom` 不写 store，无死循环风险。
- **`SubagentChatPanel` 新增 attempt watch**：getter `sessionStore.getLlmRetry(sid.value)?.attempt ?? 0` 可追踪（`?.attempt ?? 0` 优先级正确）；每次 `llm_retry` 事件（attempt 1→2→3）触发一次 `scrollToBottom`，重试结束 clear（attempt → 0）再触发一次，共 maxRetries+1 次滚动，均在合理范围；`scrollToBottom` 无副作用，无死循环。

整体功能链路（后端事件 → WS → store → 主/边路/子代理三处展示 → 清理时机 → 滚动联动）经完整时序核对无高/中严重度问题：重试期间任一面板均可见重试条（MessageBubble 承载或底部 `typingRetry` 兜底，二者互斥不重复），清理点覆盖 `content_delta`/`thinking_delta`/`thinking_end`/`thinking_start`/`tool_call_start`/`message_end`/终态 `session_status`/`error`/WS `onclose`/登出 reset/取消 stop，无残留路径。

发现 2 个低严重度问题与若干提示级遗留，详见下文。

## 问题清单

### 【低】SubagentChatPanel 重试滚动无用户滚动保护，且重试结束时多触发一次滚动

- 位置：`desktop/src/components/chat/SubagentChatPanel.vue:245-249`（新增 watch）
- 说明：
  1. `scrollToBottom` 为无条件滚动（`el.scrollTop = el.scrollHeight`），无 `userScrolledUp` 保护——重试期间若用户正在向上翻阅历史，每次 `llm_retry`（attempt 递增）都会强制拉回底部。该面板既有的 `watch(displayMessages.length)` 同样无条件滚动，故非本次新增回归，但与主会话/边路面板（有 `userScrolledUp` 保护）行为不一致。
  2. 重试结束时 `clearLlmRetry`（attempt → 0）会额外触发一次 `scrollToBottom`（此时 `content_delta`/`message_end` 等事件通常已触发其他滚动，多一次无害，但属可避免的重复调用）。
- 建议：如需要与主/边路对齐，可为该面板引入 `userScrolledUp` 机制（`handleScroll` 判断 `isNearBottom`）并在 watch 回调前检查；`attempt` 为 0 的清理触发可忽略或加 `if (retry)` 守卫。均非必须。

### 【低】SideChatPanel 占位窗口 `session-id=''` 回退主会话（遗留，前几轮已提）

- 位置：`desktop/src/components/chat/SideChatPanel.vue:21` + `MessageBubble.vue:243-246`（`llmRetry` computed 对空 `sessionId` 回退 `activeLlmRetry`）
- 说明：首次发送边路消息、`side_session_created` 未返回的占位窗口内，MessageBubble 的 `llmRetry`/`isAssistantRunning` 回退主会话状态。若主会话恰好正在重试（thinking=true），边路占位 assistant 消息会短暂误显主会话的重试条。实际时序上 `llm_retry`（带真实 sid）必在 `side_session_created` 之后到达，窗口极短且需主会话并发重试才触发，影响可忽略。维持现状可接受。

### 【提示】`delaySeconds` 为静态文案，不倒计时

- 位置：三处模板（`ChatPanel.vue` / `SideChatPanel.vue` / `SubagentChatPanel.vue` 的 `typing-retry`）
- 说明：文案「{{ delaySeconds }} 秒后继续…」为固定值，不随时间递减。需求仅要求「展示重试提示条」，静态展示可接受；如需倒计时可本地 `setInterval` 递减，非必须。

### 【提示】重试提示的显示依赖该会话 thinking 状态（遗留）

- 位置：`MessageBubble.vue:228-240`（`isAssistantRunning`）+ 三处 `typingRetry`
- 说明：正常时序（后端每轮 `thinking_start` 先于 `llm_retry`）下 thinking=true 成立，显示链路完整；仅页面刷新/断线窗口（thinking 状态丢失且 `thinking_start` 不重发）存在极低概率盲区。前几轮已记录，不影响常规使用。
