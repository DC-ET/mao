## 二、新引入的 bug

### N-1【中→高】clearedSecrets 的 watch 判断条件写反：清空按钮失效、且用户输入的新值会被静默清空

- 位置：`admin/src/views/settings/components/IntegrationConfigPanel.vue:236-242`

```ts
watch(model, () => {
  const changed = new Set<string>()
  for (const key of clearedSecrets.value) {
    if ((model[key] ?? '') !== '') changed.add(key)   // ← 收集“值非空”的键
  }
  if (changed.size !== clearedSecrets.value.size) clearedSecrets.value = changed
})
```

- 注释与 `clearSecret` 的意图是"输入新值则自动**移除**清空标记"，但回调把非空键收进 `changed` 后**整体替换**了 `clearedSecrets`——等于"只保留非空键的标记"，语义正好颠倒。且 `watch(model)` 是无 debounce 的深层全局监听，任何字段输入都会触发。
- tsx 复现（复刻同段逻辑 + Vue 真实 watch 调度）：
  - A. 直接点"清空"（值 `''→''` 不变化，watch 不触发）→ 标记侥幸保留，提交 `''` ✓
  - B. 点"清空"后在输入框打入新值 → watch 触发 → 标记被保留 → 保存提交 `''` → **用户输入的新值被丢弃，已存 secret 被静默清空** ✗（数据丢失路径：LDAP 密码/飞书 Secret/OSS SK 等被意外清空，LDAP/飞书登录随之失效）
  - C. 先输入新值再点"清空" → 值真实变化触发 watch → 标记被抹掉 → 保存提交 `null` → **清空按钮静默失效** ✗
- 修复建议：不要用全局 watch 兜底，改为在 `saveGroup` 提交前按当前值判定——`model[key] === '' ? (clearedSecrets.has(key) ? '' : null) : model[key]`；若保留 watch，则改为对空值键**保留**标记（`changed` 只收集"值非空"的键后从集合中 delete，而非整体替换），并监听具体 secret 键而非整个 model。补充组件级测试覆盖 B/C 两个交互序列。

### N-2【中】test/oss 合并逻辑对嵌套 sts secret 处理错误：存量配置点"测试连接"必然失败

- 位置：`backend-ts/src/settings/settings.routes.ts`（test/oss 路由）+ `admin/.../IntegrationConfigPanel.vue:189-205`（oss testPayload）
- 问题：构造 overrides 时 `sts.accessKeyId: overrides.stsAccessKeyId ?? ''`、`sts.accessKeySecret: overrides.stsAccessKeySecret ?? ''` 等把"留空"物化为空串，再以**整体对象替换** `stored.sts` 传给浅合并的 `mergeWithDefaults`（空串不覆盖仅对顶层 string 生效）。于是 secret 掩码不回显、用户留空时：
  - `merged.sts.accessKeySecret = ''`（而顶层 `accessKeySecret` 留空能正确回落已存密文）→ 不对称；
  - tsx 复现输出：`merged.sts.accessKeySecret = ""`，`testOssCredentials` 前置校验直接抛"OSS Region、Bucket、STS AccessKey 不能为空"。
- 影响：**所有已正确保存 OSS 配置的环境，管理员打开设置页直接点"测试连接"必报错**（除非把两个 secret 明文重填一遍），L-5 修复的初衷（可测未保存修改）落空，还引入误报。
- 修复建议：后端对 sts 各字段采用与顶层相同的语义——overrides 传 `null`/undefined 表示回落已存值（`regionId: overrides.stsRegionId ?? null`，配合 `mergeWithDefaults` 的 `v != null` 判断即可回落）；或前端 testPayload 对留空的 sts 字段同样不发送，后端 merge 时保留 `stored.sts` 原值。

### N-3【低】侧边栏菜单权限未同步：拥有 settings:read 的用户看不到"系统设置"入口

- 位置：`admin/src/components/SideMenu.vue:139`（`{ index: '/settings', ..., permission: 'user:write' }`，本次未改动）vs `admin/src/router/index.ts:106`（已改 `settings:read`）
