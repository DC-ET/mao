## 高严重度（P1）

### 1. 授权存储未按用户、范围和版本隔离，账户切换会继承授权

**位置**：`sdk/embed/src/authorization.ts:3-9`。

存储键只有服务端 Origin 和 agentId，构造函数也不接受用户身份、操作范围或授权版本。同一业务站点上，用户 A 设置 full 后，用户 B 使用相同服务端和 Agent 创建授权对象会直接恢复 full。相同服务端 Origin 下不同路径部署也共用一个键。与方案第 3.3 节的隔离约定不符。

浏览器 localStorage 已提供业务站点 Origin 隔离，因此问题不是不同业务 Origin 天然共享存储，而是同一 Origin 内账户/范围/版本没有隔离。当前模块尚未接入执行器，此问题是授权模块恢复语义本身错误。

**修复建议**：身份确定后再构造授权上下文；使用规范化服务地址、用户 ID、业务 Origin、Agent、操作范围及策略版本作为键/校验字段。身份或范围变化时丢弃旧内存授权。补充同站点切换用户、同服务端不同部署路径及策略升级测试。

### 2. task 授权写入 localStorage，刷新后仍恢复为 task

**位置**：`sdk/embed/src/authorization.ts:9-13`。

`set('task')` 与 full 一样持久化，构造函数无条件恢复 task；没有 taskId 或任务结束、会话切换失效机制。实际复现：设置 task 后重新构造对象，current 仍为 task。与“仅本次任务有效，刷新/任务结束/切换会话后失效”冲突。

**修复建议**：仅 full 按持久化规则保存；task 保存在内存并绑定明确的任务/会话标识，在结束、刷新、切换、撤销时失效。补充生命周期测试，不应通过增加永久恢复逻辑延长任务授权。

### 3. 新增执行 API 直接执行动作，默认逐次确认没有生效

**位置**：`sdk/embed/src/index.ts:57-66`；`sdk/embed/src/page.ts:85-101`。

实例把 executePageAction 直接委托给 page.execute。调用链没有 PageAuthorization、确认回调或身份状态检查。初始化后取得快照即可点击提交按钮或填写字段，无需授权；authorization.ts 的 per_action 默认值对该 API 完全无效。此处是 SDK 授权产品语义缺失，不是声称宿主 JavaScript 获得了浏览器之外的权限。

**修复建议**：将对外执行入口接入统一授权调度层，逐次确认、task 范围和 full 范围必须在产生 DOM 副作用前核验。未认证/未确认/已撤销时明确拒绝；内部裸执行器不作为可绕过授权的公开入口。补充拒绝时零 DOM 副作用测试。

### 4. 快照不随 SPA 导航或关键 DOM 变化失效，会操作旧页面语义

**位置**：`sdk/embed/src/page.ts:82-89,101`。

execute 只比较 snapshotId，随后检查元素仍在 document 且 visible；没有核对 URL/pageVersion、元素关键属性或过期时间。SPA 路由复用表单/按钮 DOM 时，旧快照仍可执行。内存运行复现：inspect 后 history.pushState 到另一条路由，使用旧 snapshotId focus 仍返回 success。复用按钮改成删除另一条记录时同样可能对错误对象产生副作用。

**修复建议**：建立导航/DOM 语义变化及超时的快照失效机制，执行前重新核验版本与目标身份；失效明确返回 snapshot_expired。pageVersion 的生成与动作返回应使用同一版本机制，而不是一处包含时间戳、一处不含。

## 中严重度（P2）

### 5. 截图默认调用无法识别实际 SDK host，Shadow DOM 排除也依赖渲染器剪枝

**位置**：`sdk/embed/src/screenshot.ts:4-10`；关联 `sdk/embed/src/controller.ts:77-81`。

host 参数可省略，但兜底只识别 `[data-mao-embed-host]`，实际 mountApp 仅设置 `id="mao-chat-embed-host"`。因此按函数允许的默认方式调用时，ignore(actualHost) 为 false；支持渲染 Shadow DOM 的渲染器可能把浮窗/聊天内容截入图片。

传入实际 host 时，ignore(host) 为 true，这条路径本身有效，不能笼统认定所有截图都会包含 SDK。不过 host.contains(shadowChild) 和 shadowChild.closest(...) 都不会跨越 ShadowRoot，逐个询问 Shadow DOM 元素时仍返回 false，正确性依赖渲染器在忽略 host 时跳过整个子树。渲染器克隆节点后也不能只依赖原节点身份比较。

**修复建议**：统一挂载与截图使用的 host 标识，并由 SDK 自身把 host 传给截图适配器；明确 ignore 的子树剪枝契约，必要时沿 getRootNode().host 检查。使用真实挂载 host、Shadow DOM 和克隆渲染路径测试，不只测试虚构 data 属性节点。当前没有实际渲染器接入，未进行像素级截图验证。

### 6. 扫描器省略 host 时完全跳过排除逻辑，现有测试反而认可 SDK 按钮被采集

**位置**：`sdk/embed/src/page.ts:65,75-80`；`sdk/embed/src/page-scanner.ts:6-7`；`sdk/embed/src/page-scanner.spec.ts:7-12`。

collectPageSnapshot 使用无 host 的 manager，而 inspect 把整个 excluded 检查包在 `if (this.host && ...)` 中，所以即使节点带 data-mao-embed-host 也不会被过滤。已复现返回 SDK 按钮。

测试中的业务控件只有 3 个，却断言总数 4，实际把 SDK 按钮算入；最后按 label === SDK 检查，但按钮文字在 text 而非 label，因而测试通过而未验证排除。公开 init 的 inspectPage 已传 host，且主文档 querySelectorAll 不穿透真实 SDK Shadow DOM，所以该特定主文档路径不应误报为已包含聊天按钮。

**修复建议**：标记排除独立于可选 host 参数生效；测试断言 3 个业务控件，同时核验 SDK 文本/引用不存在，并覆盖真实 mountApp host。

### 7. 执行器忽略 disabled/readonly 和动作适用类型，失败操作也返回成功

**位置**：`sdk/embed/src/page.ts:78-80,88,94-101`。

扫描虽报告 disabled/readonly，execute 却未检查。实际复现 readonly 输入被 fill 改写且返回成功；disabled 按钮 click 没有效果却返回成功；已选 radio 执行 uncheck 通过 click 无法取消选中，仍返回成功。select 不存在的 value、对不可填写按钮执行 fill 也没有有效的结果回读保障。

**修复建议**：按动作验证真实元素类型、`:disabled`（含 disabled fieldset 继承）、readonly 和 ARIA 状态；不支持的操作明确拒绝。填写/选择/勾选后验证最终值或 checked 状态，不把“未抛异常”等同于执行成功。补充以上失败路径及 Vue/React 受控控件测试。

### 8. keyboard 被当成 fill，按键请求会覆盖字段

**位置**：`sdk/embed/src/page.ts:31-32,98`。

keyboard 与 fill 共用兜底分支，只调用 value setter 并发送 input/change，没有键盘事件或按键语义。实际复现 keyboard(value: 'Enter') 将字段值改为字面量 Enter，并返回成功；不能触发预期 Enter 提交，反而破坏已填写内容。

**修复建议**：将文本填写与键盘操作分开建模、分支执行，明确 key/code/modifiers 与受支持的行为。无法可靠模拟的浏览器默认行为返回不支持，不伪装成成功。补充 Enter、Escape、Tab 及不覆盖原值的测试。

### 9. destroy 不释放/禁用页面管理器，销毁后的实例仍能读写业务页面

**位置**：`sdk/embed/src/index.ts:57-70`；`sdk/embed/src/page.ts:67-70,85-101`。

page 被 API 闭包持有，但 destroy 只销毁 controller 并清除全局实例，没有清空 page refs/snapshot 或置失效状态。保留旧 instance 的调用方在 destroy 或重新 init 后仍可 inspectPage/executePageAction。页面 API 绕过了 controller 原有的 destroyed 生命周期保护。

**修复建议**：为 PageSnapshotManager 增加显式销毁和执行中取消，销毁清理快照引用；所有公开页面 API 检查实例状态，已销毁时拒绝。补充 destroy 后读取、写入、以及重复 init 后旧实例失效测试。

### 10. 授权和截图模块没有接入 SDK，初始化后的页面能力链路不完整

**位置**：`sdk/embed/src/index.ts:1-8,57-66`；`sdk/embed/src/types.ts:8`；`sdk/embed/src/screenshot.ts:3-6`。

入口仅集成 inspect/execute；截图函数既未导出到 SDK 入口，也没有实例方法、渲染器配置或内部调用。PageAuthorization 同样只有定义没有接入。使用发布入口或 window.MaoChat.init 的业务方无法截图或管理页面授权，普通聊天通道也没有新增页面请求处理。capturePageScreenshot 还要求宿主提供 renderer，而当前 init 没有相应配置路径。

若本提交只是分阶段内部实现，应明确尚不可作为完整页面 Agent 功能交付；这里不把方案中所有未来后端/UI 工作逐项列为缺陷。但当前对外暴露执行 API、授权与截图却不可达，属于直接相关的集成缺口。

**修复建议**：接入内部截图适配器与授权中心，明确公开页面 API/内部 WS 请求通道的职责，让入口能走通所承诺的功能；未完成授权前不要暴露可直接产生副作用的能力。新增从 init 到截图排除、确认、执行和销毁的集成测试。
