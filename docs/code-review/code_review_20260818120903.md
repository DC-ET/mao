## 中等严重程度

### 1. 边路任务的标题更新事件可能早于创建事件，导致前端永久保留占位标题

**代码位置**

- `backend-ts/src/session/ws/streaming-ws-handler.ts:568-570`
- `desktop/src/composables/useStreamWS.ts:507-518`
- `desktop/src/views/task/TaskView.vue:425-443`

**触发条件**

创建 `SIDE_TASK` 后，后端先调用 `scheduleForFirstUserMessage()`，随后才发送 `side_session_created`。当后台执行器有空闲线程且标题模型响应很快（例如低延迟模型、测试模型或纯图片分支）时，`session_title_updated` 可能先到达前端。

此时前端尚未通过 `side_session_created`：

1. 将占位 Tab 绑定到真实 `sideSessionId`；
2. 把边路任务加入 `sideTaskCache`。

因此提前到达的 `session_title_updated` 找不到对应缓存项和真实 Tab，`updateSideTaskTitle()`、`updateSideTaskTabTitleFor()` 都不会产生有效更新。随后 `side_session_created` 又以“任务”写入 Tab 和缓存，界面会一直显示占位标题，直至重新拉取数据或刷新页面。

**影响**

边路任务标题虽已正确持久化，但当前客户端的边路列表和已打开 Tab 可能无法实时显示生成结果，不满足 WS 实时更新要求。多端中事件到达较快的客户端均可能出现该问题。

**建议修复方向**

按照技术设计规定的顺序，在首条消息保存后先发送 `side_session_created`，再调度异步标题任务，确保前端先建立真实 ID、缓存和 Tab 映射。也可以额外让前端缓存尚未匹配的标题事件，但后端保证创建事件先于更新事件更直接。

同时补充事件顺序测试：让标题执行器立即完成，断言 `side_session_created` 必须先于 `session_title_updated`；现有 `streaming-ws-handler.spec.ts` 只断言调用了调度方法，没有验证顺序，因此无法发现该竞态。

### 2. 快捷指令查询异常时不会执行前缀兜底，会话会一直停留在占位标题

**代码位置**

- `backend-ts/src/session/session-title.service.ts:56-101`
- `backend-ts/src/session/session-title.service.ts:113-120`

**触发条件**

首条有效用户文本包含 `#{快捷指令}#`，且 `userCommandService.listAvailableForUser()` 因临时数据库错误或服务异常抛错。

`preprocess()` 的异常会直接落入 `generateAndApply()` 最外层 `catch`。当前最外层只记录日志，不会使用原始文本或基础预处理结果调用 `TitleGenerator.generate()`，所以既不会调用标题模型，也不会写入失败兜底标题。

**影响**

该会话会一直保留“未命名会话”或“任务”。这与“标题辅助流程失败时使用现有文本前缀规则兜底”的业务要求不一致，而且本次设计明确不提供重试或历史补偿，失败后不会自动恢复。

**建议修复方向**

将快捷指令展开视为可降级的预处理步骤：查询失败时记录原因，但继续使用未展开的指令标记或至少完成 Skill/文件引用清理，再进入模型调用；若后续仍失败，则基于可用的预处理文本执行 `TitleGenerator.generate()` 并通过同一 CAS 写回。不要让快捷指令查询异常越过兜底逻辑。

补充单元测试：令 `listAvailableForUser()` reject，断言最终执行占位标题 CAS 更新、结果为前缀兜底且不影响主执行流程。现有测试只覆盖“模型无法解析时兜底”，未覆盖预处理依赖异常。
