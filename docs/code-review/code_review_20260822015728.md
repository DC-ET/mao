## 一、轻微问题

### 1. 新建任务首发失败回填分支：旧 blob 预览 URL 在重建之前被 revoke，且回填未校验当前 draftKey 仍为 'new'

- **严重程度**：轻微（低频复合场景；最坏后果为图片缩略图短暂裂图或预览失效，文本与文件本体不受影响，可正常重发）
- **位置**：
  - `desktop/src/components/chat/ChatPanel.vue:638-646`（首发失败回填分支）
  - `desktop/src/components/chat/ChatInput.vue:1146-1157`（clearInput）、`1171-1188`（restoreContent：先 clearInput 再重建预览）
- **描述**：回填分支的处理顺序是：① 对草稿条目中的旧预览 URL 执行 `URL.revokeObjectURL`（642）；② `clearDraft('new')`（643）；③ `restoreContent(entry.text, entry.files)`（644）——其内部先 `clearInput()`，再按文件类型重新 `createObjectURL` 生成新预览。两处瑕疵：
  1. **revoke 先于重建**：旧 URL 被显式 revoke 后，新 URL 要等到 `restoreContent` 内部 `addPendingImage` 才创建。当前代码同步执行、中间不会渲染，暂无可见影响；但该分支绕过了 ChatInput 统一的 URL 所有权规则（"卸载/清除时才 revoke"），属于对同一批 blob URL 的第二处释放点。实际上由于 ② 已删除 'new' 条目、组件当前键已切到 `s:{newId}`，此处 revoke 完全可以省略（旧 URL 的释放本应由原组件卸载/清空逻辑兜底），保留反而是多余且脆弱的耦合。
  2. **未校验当前键**：回填条件只校验 `generation === sendGeneration && draftKeyAtSend === 'new'`，未校验 `currentDraftKey.value === 'new'`。若保存确认失败前用户已手动切回"新建任务"模式：draftKey watcher 会先从 'new' 槽位恢复草稿到编辑器，此时 `hasDraft()` 为 true，640 行的守卫生效、回填被跳过——该场景已被第 2 轮修复覆盖；但若用户切回新建任务后**手动清空了输入**（`hasDraft()` 为 false），`restoreContent` 内部的 `clearInput()` 会按当前键 'new' 联动 `clearDraft('new')`（对已删除条目是 no-op），随后回填失败草稿——行为恰好正确。真正遗留的窗口是：用户切回新建任务、输入了**仅含空白/空行**的内容（`hasDraft()` 为 false 但编辑器非空文档），回填会覆盖之。概率极低、后果轻微。
- **建议修复方向**：① 删除 642 行的 revoke 循环（URL 释放交给统一所有权规则）；② 回填条件追加 `currentDraftKey.value === 'new'` 校验，与 generation 校验形成双保险。

### 2. 主会话等待保存路径（含新建任务）：60s 超时判定为"保存失败"但消息可能实际已入队，草稿与输入框保留导致重复发送风险

- **严重程度**：轻微（需 WS 保存确认回调丢失/晚到且消息实际已保存的组合才触发；后果为用户重发产生重复消息，与改动前行为一致，非本次引入的回归，但本次"草稿保留"语义放大了该场景的感知）
- **位置**：
  - `desktop/src/composables/useChat.ts:604-625`（`sendMessageAndWaitForSave` 内 `onMessageSaved` + 60s `setTimeout(() => finish(false), 60000)`）
  - `desktop/src/components/chat/ChatPanel.vue:629-646`（`saved === false` 时不清草稿、不清输入框；新建任务分支回填草稿）
  - `desktop/src/components/chat/SideChatPanel.vue:604-620`（边路等待保存同样 60s 超时不清草稿，注释明确"超时/卸载只解锁 waitingForSave，保留草稿以便重试"）
- **描述**：`sendMessageAndWaitForSave` 的保存确认依赖 WS `user_message_saved` 事件；若事件丢失（WS 重连窗口）或晚于 60s 到达，Promise 以 `false` 结束。此时消息**可能已经**被服务端持久化并进入执行，但前端按"失败"处理：主会话保留输入框内容与草稿（新建任务还会把草稿回填进输入框），用户看到输入框仍是待发状态，自然倾向再次点击发送——产生重复消息。改动前的行为相同（输入框保留以便重试），因此这不是本次引入的回归；但本次需求将"失败保留"从"输入框 UI 保留"升级为"输入框 + 草稿槽位双保留"，且新建任务失败回填使内容重新可见，用户重试的概率与重复发送的代价略有上升。属于既有超时机制的固有模糊性，本次改动只是继承了它。
- **建议修复方向**：超时路径可在 `finish(false)` 前主动向服务端查询该 eventId 是否已保存（或依赖现有 `fetchSession`/消息列表比对），确认未保存才按失败保留草稿；或超时提示文案明确"消息可能已发出，请检查后再决定是否重发"。若认为成本过高，可接受现状并在设计文档风险节记录。

## 二、已核查无问题的关键点（供回归参考）

1. **第 2 轮修复 1（hasDraft 守卫）**：ChatPanel.vue:640 `entry && !chatInputRef.value?.hasDraft()`，与队列撤回编辑 `handleQueueEdit`（427）的冲突检查语义一致；`hasDraft` 判定"文本 trim 非空或有待发文件"，覆盖图片/非图片附件场景。
2. **第 2 轮修复 2（队列路径 generation）**：ChatPanel.vue:614 `const generation = ++sendGeneration` + 619 条件 `clearInput`，与首发路径（626、632）及 `onActivated` 的作废机制（576-579）形成完整闭环；`clearDraft(draftKeyAtSend)`（617）不受 generation 影响，符合"已入队的消息必须清目标槽位"的语义。
3. **clearedKeys 语义闭环**：`clearDraft` 标记（draft.ts:52-57）→ 兜底 `saveDraft` 跳过（ChatInput.vue:733）→ `setDraft` 重新写入解除标记（draft.ts:39）→ `reset` 全清（draft.ts:60-63）；删除会话/边路任务后 KeepAlive 淘汰的晚到兜底保存不会复活条目，单测覆盖（draft.test.ts:44-51、55-58）。
4. **删除会话**：`deleteSession` 的 `clearDraft('s:'+sid)`（session.ts:1022）在 API 删除成功后执行，API 抛错则不清，语义正确。
5. **删除边路任务 / 晋升**：TaskView.vue:587-590、603-606 在 `closeTab` 后立即 `clearDraft(tab.id)`；晋升后路由跳转新主会话，旧 tab 草稿已清；关闭（不删）边路 tab 不清草稿，重开恢复，符合设计 2.3。
6. **边路双路径清草稿**：队列路径显式 `clearDraft(props.tabId)`（SideChatPanel.vue:530）+ 等待保存路径捕获 `draftKeyAtSend`（605、617），幂等；tabId 在占位→正式 ID 演变中恒定（useCenterTabs `updateSideTaskTab` 不改 tab.id），键稳定。
7. **登出**：`logout()` finally 中 `useDraftStore().reset()`（auth.ts:89），与 session reset 同步；`reset` 同时清 `clearedKeys`，换账号登录后无标记残留，单测覆盖（draft.test.ts:55-58、71-75）。
8. **blob URL 所有权主链路**：卸载时仍有草稿条目则不 revoke（ChatInput.vue:1196-1200）；`restoreDraft` 浅拷贝隔离 store 快照（748-749），`removePendingFileAt` 的 splice/revoke 不影响草稿槽位。
9. **富文本节点往返**：`getHTML()/setContent()` 保留 quickCommand（`${name}$`）/fileReference（`@{path}@`）自定义节点的 attrs（两节点均有 parseHTML/renderHTML 属性映射），切走切回后节点渲染与 `getText` 序列化发送均正常。
10. **加载过渡期**：`currentDraftKey` 在无 activeSessionId 且非新建任务时返回 null（ChatPanel.vue:308-312），watcher 对 null 旧键 `saveDraft` 跳过、null 新键 `restoreDraft` 清空编辑器，不会把瞬态内容误存。
11. **类型与测试**：`vue-tsc -b` 通过；draft store 单测 9/9 通过。
