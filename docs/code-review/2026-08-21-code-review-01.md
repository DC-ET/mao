# 未提交代码审查报告

审查范围：当前 Git 工作区未提交的功能代码；忽略文档和页面样式变更。

## 结论

发现 6 个本轮变更引入的功能问题。

## 1. [高] 多问题问答只会提交最后一题答案

- 位置：`agent-cli/src/tui/modals.tsx:20`、`agent-cli/src/tui/modals.tsx:36`、`agent-cli/src/tui/modals.tsx:70`、`agent-cli/src/tui/modals.tsx:105`
- 触发条件：一次 `ask_user_questions` 包含两道或更多问题。
- 原因：`answers` 是组件函数内的普通局部数组。回答一题后调用 `setQIndex()` 会触发重新渲染，数组随之重置为空。
- 影响：最终发送的 `ask_user_questions_result.answers` 只包含最后一次渲染中回答的题目，前面问题的单选、多选或自定义答案都会丢失，Agent 会基于不完整答案继续执行。

## 2. [高] LOCAL 审批未接入 Ink modal，审批输入会与主输入框互相干扰

- 位置：`agent-cli/src/commands/chat.ts:142`、`agent-cli/src/local/executor.ts:118`、`agent-cli/src/repl/repl.ts:187`
- 触发条件：交互式 LOCAL 会话遇到需要人工确认的工具调用。
- 原因：`LocalExecutor.askApproval` 仍固定调用基于 readline 的 `fallbackAskApproval()`；当前代码没有任何路径打开 `{ type: 'approval' }` modal，因此新增的 `ApprovalModal` 实际不可达。与此同时 Ink 的 `useInput` 仍在监听同一个 stdin。
- 影响：用户输入 `y`/`n` 和回车时，按键可能同时进入审批 readline 和主对话输入框。例如批准工具时可能额外排队并发送一条 `y` 消息，且 readline 输出会破坏当前 TUI 交互。

## 3. [高] 恢复等待问答的会话时可能空引用并永久挂起

- 位置：`agent-cli/src/commands/chat.ts:160`、`agent-cli/src/commands/chat.ts:167`、`agent-cli/src/commands/chat.ts:196`、`agent-cli/src/commands/chat.ts:220`
- 触发条件：恢复正在执行或正在等待用户回答的会话，服务端在 `runner.attach()` 订阅后立即发送或重放 `ask_user_questions`。
- 原因：Ink renderer 在 `runner.attach()` 完成后才创建；提前触发的 `askHandler` 会执行 `tuiHolder.ink!.setAskResolver(...)`，此时 `tuiHolder.ink` 仍为 `undefined`。该异步调用由 `void this.handleQuestions(...)` 启动，异常不会反馈到主流程。
- 影响：问题无法显示和回答，后端执行可能一直停留在等待用户输入的状态。

## 4. [高] TTY 打印模式显式启用问答后必然按失败处理

- 位置：`agent-cli/src/commands/chat.ts:160`；相关参数行为见 `agent-cli/src/args.ts:285`、`agent-cli/src/args.ts:294`
- 触发条件：在 TTY 中使用打印模式并显式指定 `--on-question=ask`。
- 原因：参数解析允许 TTY 打印模式使用 `ask`，旧实现也会通过 `askQuestionsInTty()` 收集答案；本轮代码却用 `&& !cfg.print` 排除了打印模式，导致 `SessionRunner` 收不到 `askHandler`。
- 影响：收到 `ask_user_questions` 后会直接进入失败分支、取消会话并返回问答失败，而不是按参数约定向用户提问。

## 5. [中] 执行中第二次 Ctrl+C 会跳过资源清理

- 位置：`agent-cli/src/repl/repl.ts:80`、`agent-cli/src/repl/repl.ts:91`
- 触发条件：任务运行时第一次 Ctrl+C 发送 cancel，任务仍在收尾时再次 Ctrl+C。
- 原因：第二次处理先把 `closing` 设为 `true`，再调用 `requestExit()`；后者因 `closing` 已为 `true` 立即返回。
- 影响：不会执行 `runner.shutdown()` 和 `tuiHandle.unmount()`，WebSocket、LOCAL executor、MCP/本地 shell 以及 Ink spinner 定时器可能继续存活，进程可能无法正常退出。

## 6. [中] 交互模式的 trace 文件不再记录正式执行事件

- 位置：`agent-cli/src/commands/chat.ts:86`、`agent-cli/src/commands/chat.ts:101`、`agent-cli/src/commands/chat.ts:236`
- 触发条件：非打印模式使用 `--trace-file`。
- 原因：初始 renderer 是包含 `TraceRenderer` 的 `MultiRenderer`，但创建 Ink 后直接把 `SessionRunner.opts.renderer` 替换为单独的 `inkRenderer`。
- 影响：之后的消息、工具调用、执行结果和 `finish` 都绕过 `TraceRenderer`，trace 文件缺失本轮会话的核心执行记录。
