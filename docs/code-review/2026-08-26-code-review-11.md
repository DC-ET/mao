# 代码审查报告

- 审查范围：当前 Git 工作区未提交代码（仅功能逻辑）
- 需求：飞书消息触发者身份下，每次 Shell 命令刷新 `MAO_TOKEN`、`HOME`、Git token、`GIT_ASKPASS`/`GIT_TERMINAL_PROMPT`，清理上一用户残留，并保证共享持久 Shell 串行安全。
- 结论：发现 2 个功能逻辑 bug。

## 高严重程度

### 1. `write_stdin` 的异步等待/锁与 `exec` 的工作目录刷新不一致，可能破坏串行安全

- **位置**：`backend-ts/src/harness/tool/impl/shell-session-tool.ts:197-216, 264-280`。
- **问题**：`handleWriteStdin` 在拿到命令锁后，写入输入并等待 marker；命令完成后调用 `resolveCurrentWorkdir`，该方法又直接向同一 Shell 写入 `pwd` 并等待第二个 marker，但这段额外操作本身没有独立的锁边界（当前仍持有锁）。在 `readUntilMarker` 超时、Shell 被关闭或后台命令残留输出等情况下，后续请求虽然会排队，却可能消费/混淆前一请求的 `pwd` 输出或 marker；更关键的是 `exec` 的异步路径把 `releaseCommand` 延迟到后台任务结束，但 `backgroundTaskManager.submit` 只同步返回 task id，若 submit/任务调度异常，锁释放依赖未执行的异步 finally，可能永久阻塞同一持久 Shell。
- **影响**：共享 Shell 后续命令卡死或读取错误结果，形成会话级可用性故障。
- **修复建议**：将“命令输出 + cwd 查询”设计为同一受保护的协议，确保每个 marker 消费范围明确；异步提交失败时立即释放锁，并为后台任务建立可观测的最终释放兜底。关闭/超时也应使等待者可确定地结束。

### 2. `HOME` 刷新不能清理上一用户的 HOME：无 HOME 的新调用者会继承旧用户目录

- **位置**：`backend-ts/src/harness/shell/shell-session-manager.ts:205-224, 265-274`。
- **问题**：`refreshUserEnvironment` 创建空 env 后调用 `configureUserHome(env, userId)`；当本次 `userId` 为 `null` 时，`configureUserHome` 直接 return。`ShellSession.refreshEnvironment` 只会 unset `userEnvironmentKeys` 中记录的键，而 `HOME` 从未被加入该集合（因为集合只在 `refreshEnvironment` 中更新，但首次创建持久 Shell 时 HOME 是通过 `createSession` 的 spawn 环境设置的）。因此同一 Shell 从用户 A 切换到没有解析到用户的飞书消息时，A 的 HOME 仍在进程环境中，违反“清理上一用户残留”。同样，`GIT_TERMINAL_PROMPT` 的初始值也可能保留：首次创建无凭据时未设置，后续有凭据再切到空凭据会被记录并 unset；但 HOME 的初始 spawn 注入不在刷新跟踪集合内。
- **影响**：未绑定身份的消息可能读写上一用户的 `~/.config`、Git 配置/凭据及缓存，产生跨用户数据泄漏和错误行为。
- **修复建议**：把所有请求级初始环境（尤其 `HOME`、Git token、askpass、`GIT_TERMINAL_PROMPT`）统一纳入 session 的可清理键集合，或在刷新时明确 `unset HOME`；刷新应基于“上一请求实际设置的键”与本次目标环境做差集，而不能只依赖 refresh 后才记录的键。

## 已核对

- `MAO_TOKEN` 在同步 `exec` 和 `write_stdin` 的命令写入前注入；Feishu handler 已优先使用 `session.executionUserId` 传递触发者身份。
- 非空 Git 凭据的 askpass 路径由 `RuntimeDataResolver.resolveGitAskpassScript(userId, conversationId)` 生成，目录创建和权限设置存在；空 token map 会清除已由刷新逻辑记录的 Git 环境变量。
- `ToolDispatcher` 保留旧的 8/9 参数调用形态，execution user 仅用于 shell。
- 未执行代码修改。构建尝试因后台任务返回 `exit_code=-1` 且未提供 tsc 诊断，不能据此判定构建通过。
