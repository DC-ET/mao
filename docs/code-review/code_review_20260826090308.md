## 中严重度

### 1. 卡片更新成功但消息发送失败时，文本兜底没有生效

**位置：**
- `backend-ts/src/feishu/agent-inbound-handler.ts:108-116`
- `backend-ts/src/create-app.ts:804-827`

**问题：**
`onExecutionFinished` 在获取最终回复前执行；之后 `cardListener.complete(text)` 只捕获并吞掉卡片 `patch` 的异常，并以 `false` 触发 `onReply` 文本兜底。这个兜底只覆盖“卡片更新失败”的情况。

但在 `createFeishuProgressCard` 中，卡片创建阶段的 `message.reply`/`message.create` 是在 `onMessage` 的 try 块内执行的；创建成功后才返回 listener。若卡片发送成功但 SDK 返回体缺少 `message_id`，或创建请求在飞书侧已落库后因响应超时/网络异常抛错，`createProgressCard` 会抛异常，`cardListener` 仍为 `null`，随后 Agent 根本不会执行，catch 直接返回文本错误文案。此时用户可能已经收到一张处理中卡片，但不会收到最终文本回复，也没有可更新的终态卡片，形成悬挂卡片/丢回复。

同样，`createProgressCard` 创建阶段没有像 `safeUpdate` 一样把发送异常转成“禁用卡片、继续 Agent”，所以飞书卡片服务的瞬时故障会直接阻断业务 Agent。

**修复建议：**
将卡片创建视为可选增强能力：创建失败（包括响应缺少 `message_id`）时记录日志并返回 `null`，继续执行原有 Agent；若已知消息已创建但无法取得 ID，无法可靠 patch 时至少继续执行并走 `onReply` 文本发送。对 `complete`/`fail` 兜底保留现有 `safeUpdate` 逻辑，并补充“卡片创建失败仍执行 Agent、最终通过文本回复”的测试。

## 已核验未发现问题

- `AgentEventListener` 仅新增可选 `onRoundStart`/`onRoundEnd`，`CompositeAgentEventListener` 使用可选调用并隔离单个 listener 异常，不会破坏既有 WebSocket/子代理监听器。
- `AgentLoop` 在每轮开始触发 round start；工具轮和无工具最终轮都在离开该轮前触发 round end；空响应重试和后台任务等待的 continue 路径不会提前清空/结束卡片 round。
- `FeishuCardProgressListener` 将工具按 tool call id 独立维护，最终完整参数会刷新摘要输入，工具结果按 id 归属，摘要使用 `ToolResultSummarizer`；round 更新通过 Promise 链串行化，终态更新等待已排队更新。
- 卡片 patch 失败会被吞掉并返回 `false`，完成/失败路径会回退文本；正常成功时不再重复发送文本。
- 群聊卡片创建/文本回复均使用 message reply（原消息）作为目标；私聊使用 sender open_id，群聊非 reply 分支使用 chat_id，参数类型与目标选择一致。
- 既有工具结果 rawResult 仍传给通用监听器，未引入上一轮发现的 WebSocket 图片预览回归。
