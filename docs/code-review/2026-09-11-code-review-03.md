- 审查范围：仅功能逻辑（后端全量同步 / admin 表单 / Embed SDK 空白态与填入链路）

## 总体结论

**本次需求的核心功能链路未发现会破坏业务正确性的重大 bug。** 全量同步规则（带 id 更新 / 无 id 新增 / 缺失删除 / null 不动 / 空数组清空）、前后端 5 条 & 100 字校验、级联删除、复制去 id、SDK 空白态判断与点击填入链路均实现正确，且与既有 experiences 实现保持一致，测试覆盖到位。

以下按严重程度列出发现的低危问题与确认过安全的边界项，供合并决策参考。

## 低危问题（建议关注）

### L1. `.mao-suggested` 样式在 style.css 中重复定义，且后者与设计文档「每条完整展示文本（不截断）」矛盾

- 位置：`sdk/embed/src/ui/style.css:1019-1047` 与 `sdk/embed/src/ui/style.css:1049-1080`
- 现象：同一选择器 `.mao-suggested` / `.mao-suggested__item` 被连续定义了**两遍**（应为开发过程两次写入，漏删前一段）。后一段覆盖前一段，导致：
  - 前一段的 `align-items: stretch`、`:focus-visible` 聚焦环、`word-break: break-word`（完整换行展示）被后一段的 `-webkit-line-clamp: 2`（超 2 行截断 + 省略号）覆盖；
  - 设计文档 §8.2 明确要求「每条完整展示文本（不截断）」，且单条上限 100 字，line-clamp:2 会让较长问题在 UI 上被截断（有 `title` 悬浮提示兜底，但移动端无 hover）。
- 影响：功能可用，属样式回归 + 死代码；按审查要求「不关注样式」本可不列，但重复定义是明显的遗留产物，且「100 字 vs 2 行截断」会造成部分推荐问题实际展示不完整，与产品预期（引导完整问题）有偏差，故记录。
- 建议：删除前一段（1019-1047）重复定义；如需遵循「不截断」设计，去掉 `line-clamp` 改为 `word-break: break-word`（前一段的写法）。

### L2. 后端未校验「id 归属其他 Agent」的输入：传入他人 Agent 的推荐问题 id 会静默变为新增

- 位置：`backend-ts/src/agent/agent-suggested-question.service.ts:53-68`（`syncSuggestedQuestions`）
- 现象：请求项带 `id` 但该 id 不属于当前 Agent（`existingIds.has(item.id)` 为 false）时，走 `insert` 新增一条，而不是报错或忽略该 id。
- 触发条件：仅当调用方（CLI / API 直接调用）构造恶意或错误请求体时发生；管理后台正常流程（详情→表单→提交，id 均来自本 Agent）不会触发。
- 影响：与既有 `syncExperiences` 行为完全一致（既有模式），不构成数据串号（update 分支只更新 `findById` 拿到的本 Agent 记录；insert 的 agentId 为当前 Agent）。属「与现状一致性」范围内的可接受行为，非本次引入的回归。
- 建议：如后续要收紧，可在两条 sync 中对「带 id 但 id 不属于该 Agent」直接抛 `PARAM_INVALID`；本次不强求。

## 已确认无问题的关键点（审查清单复盘）

### 后端全量同步（`AgentSuggestedQuestionService.syncSuggestedQuestions`）

| 边界 | 结论 |
|------|------|
| 带已有 id 且属于该 Agent | `findById` 后更新 content/sortOrder，不跨 Agent（update 对象来自库，agentId 原样保留） |
| 无 id / id 为 null | insert，`question.id` 由 repo 回填进 `keepIds`，不会误删 |
| 库中存在但请求缺失 | 循环 `deleteById` 物理删除 |
| `suggestedQuestions == null`（字段未传） | `items == null` 提前 return，不动。CLI 只改 name 时（`buildAgentBody` 不含该 key）也不会误清 |
| `suggestedQuestions: []` | 清空全部（有单测 `syncEmptyClearsAll` 覆盖） |
| 超过 5 条 | 先于所有 DB 操作抛 3029（`AGENT_SUGGESTED_QUESTION_LIMIT_EXCEEDED`），无半写状态 |
| content 空/空白/超 100 字 | `normalizeAndValidateContent` trim 后校验，抛 3028；normalize 后落库，详情返回的是干净文本 |
| sortOrder 缺省 | 按数组下标兜底（`item.sortOrder != null ? item.sortOrder : i`），与 experiences 一致 |
| 重复 id | `keepIds` 集合天然去重，重复 update 幂等 |

### 级联删除

`AgentService.deleteAgent` 在 `deleteById` 前 `suggestedQuestionService.deleteByAgentId(id)`，顺序正确（有 service 单测断言）。

### 校验一致性（前后端 5 条 / 100 字）

- admin：`maxlength=100` + `show-word-limit`（输入硬限）+ `validateSuggestedQuestions`（trim 后空/超 100 拒绝、超 5 条拒绝并自动切到对应 Tab）+ `addSuggestedQuestion` 在 ≥5 时直接拒绝添加。
- 后端：MAX_ITEMS=5、MAX_CONTENT_LENGTH=100，硬拒绝（3028/3029）。
- 两端一致；`el-input maxlength` 与后端 trim 校验语义兼容（trim 后 ≤100 必然 ≤100）。

### 复制模式去 id

`mapSuggestedQuestions(source, props.mode === 'edit')` —— 仅编辑模式保留 id；复制/创建均置 null，提交 `id: isEdit ? item.id : null` 双重保险，与 experiences 完全同构。

### SDK 空白态判断

- `showSuggested = isEmpty && suggestedQuestions.length > 0`；`isEmpty = messages.length === 0`。
- boot 时拉取：`(agent.suggestedQuestions ?? []).map(trim).filter(非空)`，null/undefined/接口失败（catch 分支不改值，保持 `[]`）均回落空数组，空白态与现状一致。
- 发首条消息 → `ui.messages` 经 store watch 更新 → `isEmpty` 变 false → 隐藏；「新对话」`store.reset()` 清空 messages → 重现。均通过响应式自然驱动。
- 身份切换：`setIdentity` 中显式 `ui.suggestedQuestions = []` 并 `booted = false`，随后重新 boot 会重新拉取赋值，无跨身份残留。
- 多 tab / 恢复已有会话：恢复的会话历史非空 → 空白态不展示推荐问题，符合「仅新会话空白态」语义。

### 点击填入链路（ChatPanel → Composer ref → setText）

- `fillSuggestedQuestion`：`composerEl.value?.setText(content)` + `focus()`；`Composer.setText` 写 `text.value` → 既有 `watch(text, () => nextTick(autoGrow))` 自动撑高，函数内再显式 `autoGrow` + 聚焦 + 光标置尾，双保险。
- 不触发 `onSend`（未 emit send），用户手动发送；`canSend` 由草稿非空驱动，发送按钮自然可用。
- `running` 态点击仍可填入（草稿保留），发送按钮由既有 `running` 禁用逻辑控制，与设计文档风险项 §12.2 一致。
- 有单测覆盖「点击填入不自动发送」「有消息后不渲染」「空数组不渲染」「setText 覆盖已有草稿」。

### 其他确认项

- `GET /v1/agents` 列表接口：复用 `toVO` 会连带返回 `suggestedQuestions: []`（每 Agent 一次额外 SELECT，最多 5 行）。设计文档说「列表不返回该字段」——实际响应中**始终包含该字段**（值为 `[]`）。差异仅是 payload 中多一个空数组字段（experiences 本来也是这样全量返回的），无功能影响，验收标准 2 的意图（列表不膨胀、不暴露配置）实质达成，可视为文档表述与实现的措辞差异。
- 迁移 V109：版本号衔接 V108 无冲突；表结构含 `(agent_id, sort_order, id)` 复合索引支撑排序查询；`VARCHAR(100)` 与后端 100 字校验一致（utf8mb4 按「字符」计，JS `length` 与之等价，含 emoji 一致）。
- `shared/contracts`：`SuggestedQuestionVO` 新增字段全部 optional，agent-cli / desktop 无引用不受影响；backend-ts、admin 构建均通过。
- mao-cli：`--suggested-questions-json` 经 `parseJsonFlag` 透传，未传时 body 不含该 key → 后端不动；`mao agent get` 返回的详情自然含 `suggestedQuestions`。
