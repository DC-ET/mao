# 微信入站文件处理代码复审报告

审查范围：当前 Git 工作区中与微信入站文件处理相关的未提交代码，仅关注功能逻辑。

上一轮的“下载失败静默丢弃”和“并发同名覆盖”已修复；媒体字段回退已补充，但仍有一个关联缺口。复审发现以下问题。

## 发现的问题

### 1. [高] 文件失败的快速返回不会取消同会话上一条 Agent 执行

- 位置：`backend/src/main/java/cn/etarch/mao/weixin/handler/AgentWeixinInboundHandler.java:127-143`
- 相关位置：`backend/src/main/java/cn/etarch/mao/weixin/handler/AgentWeixinInboundHandler.java:147-150`

当同一微信会话已有一条消息正在执行时，用户再发送下载失败、解密失败或保存失败的文件，失败分支会在 `nextGeneration()` 和 `abortRunningExecution()` 之前直接返回。

用户虽然会收到“文件接收失败”，但上一条 Agent 仍会继续执行并在稍后发送过期回复，破坏当前处理器约定的“新消息接管并取消旧执行”语义。文件失败消息也应作为新一代消息，在返回错误前使旧执行失效并触发取消。

### 2. [高] 文件全部失败时会连同有效文本或图片一起放弃处理

- 位置：`backend/src/main/java/cn/etarch/mao/weixin/handler/AgentWeixinInboundHandler.java:127-132`

当前短路条件只判断“没有成功文件且存在文件下载错误”，没有检查消息是否还包含有效正文或图片。

因此，用户在同一条消息中发送“帮我分析”文字和一个失败文件，或发送图片并附带失败文件时，handler 都会直接回复文件接收失败，不触发 Agent，导致有效文字或图片被忽略。只有消息确实不存在其他可处理内容时才应短路；存在文字或图片时，应继续处理有效内容，并附加文件失败说明。

### 3. [中] 回退到 `thumb_media` 下载参数时，AES key 未同步回退

- 位置：`backend/src/main/java/cn/etarch/mao/weixin/service/WeixinMediaService.java:134-140`
- 相关位置：`backend/src/main/java/cn/etarch/mao/weixin/service/WeixinMediaService.java:164-180`
- 相关位置：`backend/src/main/java/cn/etarch/mao/weixin/service/WeixinMediaService.java:267-295`

当 `file_item.media` 节点存在但字段不完整，而有效的 `encrypt_query_param` 和 `aes_key` 位于 `thumb_media` 时，下载参数会正确回退到 `thumb_media`，但传给 `resolveAesKey()` 的节点仍是优先选中的 `media`。

结果是无法读取 `thumb_media.aes_key`，代码会把 CDN 密文当作明文并作为“成功文件”保存，Agent 最终无法读取文件内容。下载参数和 AES key 应基于同一媒体节点解析，或让 AES key 按 item、media、thumb_media 完整回退。

### 4. [中] 文件名包含 `}` 时，传给 Agent 的文件路径会被截断

- 位置：`backend/src/main/java/cn/etarch/mao/weixin/service/WeixinFileStorageService.java:101-114`
- 相关位置：`backend/src/main/java/cn/etarch/mao/weixin/handler/AgentWeixinInboundHandler.java:381-390`
- 解析位置：`backend/src/main/java/cn/etarch/mao/harness/core/PromptEngine.java:66`

文件名清洗保留花括号。若用户发送名为 `报告}最终版.pdf` 的文件，保存后路径会被包装为 `@{路径}@`；文件引用正则在文件名中的第一个 `}` 处结束匹配，传给 Agent 的路径因此被截断，无法指向实际文件。

建议在文件名清洗时排除文件引用语法的保留字符，至少处理 `{`、`}`，或改用不会受文件名字符影响的引用构造方式。
