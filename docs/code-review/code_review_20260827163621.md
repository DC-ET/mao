## 中危（功能 Bug）

### 1. TaskInspector 在 side_task / subagent 视图下，「工作区」标签误用子任务标题当作群名

- **位置**：`desktop/src/components/task/TaskInspector.vue:553-557`，根因涉及 `desktop/src/views/task/TaskView.vue:34,252-262`
- **现象**：右侧边栏切换到「边路任务」或「子代理」视图时，「工作区」行显示的是**子任务的标题**（如"修复登录页"），而不是该工作区对应的群名。
- **原因**：
  - TaskInspector 的 `workspace` / `projectKey` / `executionMode` 始终来自**主会话**（飞书群场景即 `…/feishu-chat/{botId}/{chatId}` 工作区目录）；
  - 但本次新增的第 7 个参数传的是 `props.title`，而该 prop 实际绑定的是 `inspectorTitle` —— 在 `side_task`/`subagent` 视图下返回的是子任务/子代理标题，只有 chat 视图才等于主会话标题；
  - 于是 `cloudWorkspaceIndicator(..., props.title)` 把被查看对象的标题当成了工作区名称，与真实工作区主体不一致，且与底部输入区指示器（显示真正群名）相互矛盾。
- **影响**：飞书群聊会话中打开任意 side task / subagent 后，右侧栏「工作区」信息失真；若子任务标题为空则又静默回退合成标签，同一界面两种口径。
- **建议**：给 TaskInspector 新增独立的 `sessionTitle` prop（由 TaskView 传入主会话 `sessionTitle.value`），不要复用随视图切换的 `inspectorTitle`；保证工作区标签的 title 与 workspace/projectKey 出自同一主体（主会话）。

### 2. SideChatPanel（边路任务面板）输入区指示器未传 session-title，用户反馈的合成标签在该入口仍复现

- **位置**：`desktop/src/components/chat/SideChatPanel.vue:82-95`
- **现象**：在飞书群聊会话的边路任务面板底部输入区，工作区指示器依旧显示 `飞书群1·oc_xxxxxx…` 这类合成标签。
- **原因**：
  - 该 `<ChatInput>` 绑定的是主会话上下文：`:workspace="parentWorkspace"`、`:project-key="parentProjectKey"`、`:execution-mode="parentExecutionMode"`（均 inject 自主会话，即飞书群工作区路径），CLOUD 模式下必然渲染 `cloudIndicatorLabel`；
  - 但本次改动只在 `ChatPanel.vue` 补了 `:session-title`，SideChatPanel 这个第二使用点被遗漏。`sessionTitle` 为可选 prop，缺省不报错，静默走 `displayTitleOf(undefined) → undefined → formatCloudGroupLabel` 回退到合成标签。
- **影响**：需求目标（消除 botId+chatId 合成标签）未完整达成；同一会话内主面板显示群名、边路面板显示合成标签，行为不一致。
- **建议**：补传 `:session-title="parentSession?.title"`（`parentSession` 即该组件已有的 `sessionStore.activeSession` 计算属性）。建议以「谁绑定了 workspace，就传谁的 title」为原则全局复查一遍 `cloudWorkspaceIndicator` 调用点（当前共 3 处：ChatInput、TaskInspector、测试文件）。

## 低危（可维护性建议）

### 3. 占位标题魔法串 `'飞书Bot会话'` 第 4 处硬编码

- **位置**：本次新增 `desktop/src/utils/cloud-project.ts:21`（`displayTitleOf`）；存量还有 `cloud-project.ts:64`、`desktop/src/components/task/TaskIndexPanel.vue:848`，以及后端 `backend-ts/src/create-app.ts:814,850`、`session.service.ts:238`。
- **风险**：前后端任一端调整兜底文案（如改为「飞书 Bot 会话」或加空格），所有等值比较将静默失效，占位标题会被直接外露给用户，且无任何报错。目前验证前后端字符串一致，属潜在地雷而非现行 bug。
- **建议**：前端提取导出常量（如 `FEISHU_PLACEHOLDER_TITLE`）供 `displayTitleOf` / `formatCloudGroupLabel` / `TaskIndexPanel` 复用，后端同理。

### 4. `cloudWorkspaceIndicator` 已膨胀至 7 个位置参数

- **位置**：`desktop/src/utils/cloud-project.ts:143-152`
- **风险**：本次新增参数排在最末，第 4-6 个参数必须显式占位 `undefined` 才能传到位——`TaskInspector.vue:556` 已经出现 `(executionMode, workspace, projectKey, undefined, undefined, undefined, props.title)` 这种易错写法；后续继续追加参数极易错位（且类型上 `string | undefined` 相互兼容，编译器无法拦截串位）。
- **建议**：重构为 options 对象参数 `{ draftProjectKey?, workspaceMode?, gitCloneUrl?, sessionTitle? }`，或将各分支拆成小函数。

### 5. 私聊判定与群聊合成分支的段位取法不一致（提示级）

- **位置**：`cloud-project.ts:12-15`（`isFeishuPrivateWorkspace` 取**最后一段**判断 `private-` 前缀）vs `cloud-project.ts:78-80`（`formatCloudGroupLabel` 取 `feishu-chat` 段后的第 2 段）。
- **风险**：两处约定仅在路径形如 `…/feishu-chat/{botId}/{leaf}` 且无尾随斜杠/子目录时等价。经核实后端用 `path.resolve(workspaceRoot, 'feishu-chat', safeAccountId, safeLeaf)` 构造（`create-app.ts:210`），形态有保证，现阶段无实际问题；若未来工作区内生成子目录（如工具产物落盘到该目录下）或数据库存入尾斜杠，两处判定可能出现分歧。知悉即可，不要求本次处理。
