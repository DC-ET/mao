# 第 4 轮代码审查报告

- 审查范围：当前 Git 工作区未提交代码
- 重点：绑定卡片失败回退、OAuth PROCESSING 收敛、并发回调、成功回调单次恢复及同卡片复用
- 结论：发现重大功能 bug，上一轮关键问题未全部解决。

## 高严重程度

### 1. 成功 OAuth 回调无法领取并恢复绑定前的原消息

- **位置**：`backend-ts/src/feishu/pending-binding.repository.ts:27-38`
- **问题**：`claim()` 先查询 `status = 'PENDING'` 的记录，但随后执行的条件更新却要求 `status = 'SENT'`。而成功发送并持久化卡片 ID 的正常记录在 `setCardMessageId()` 中被置为 `SENT`，因此 `claim()` 永远拿不到该记录：查询返回 null；即使查询到 PENDING，也会因更新条件不匹配返回 null。
- **影响**：OAuth 成功后不会调用 `pendingBindingProcessor.process()`，原始群消息不会恢复执行，已发送的绑定卡片也不会被复用/patch；直接违反“成功回调只恢复一次原消息并准确复用同卡片”的核心需求。
- **修复建议**：`claim()` 的查询条件与原子领取条件统一为 `status = 'SENT'`（并在领取更新中使用同一状态条件）；领取成功后再返回已读取的数据。补充成功回调测试，断言：只处理一次、传入保存的 `cardMessageId`，且不会重新发送进度卡片。

### 2. OAuth state 在 PROCESSING 期间过期仍可能被写成 SUCCESS

- **位置**：`backend-ts/src/auth/feishu-oauth.repository.ts:22-49`、`backend-ts/src/auth/feishu-auth.service.ts:106-125`
- **问题**：虽然 `claimPending()` 已原子地把 PENDING 变为 PROCESSING 并检查有效期，但完成外部飞书认证后，`updateByState()` 只按 `state AND status = 'PROCESSING'` 更新，没有再次约束 `expires_at > 当前时间`，也没有传入/比较当前时间。外部调用跨过二维码有效期时，仍会转换为 SUCCESS。
- **影响**：过期授权仍可成功绑定，并触发 `onUserAuthenticated` 及（设计上）原消息恢复，PROCESSING 过期不能可靠收敛到 EXPIRED。
- **修复建议**：为成功转换增加原子条件 `expires_at > ?`，使用数据库时间或统一的 `now`，并严格检查 affectedRows；更新失败时读取最终状态，按 EXPIRED/已处理返回，禁止继续成功副作用。增加“claim 后外部认证耗时超过 expiresAt”的测试。

## 中严重程度

### 3. 卡片 ID 持久化失败虽能文本回退，但会留下不可恢复的 PENDING 记录

- **位置**：`backend-ts/src/create-app.ts:846` 附近的 `sendUnauthorizedCard` 调用链（当前实现主体约 `1010-1055`）；`backend-ts/src/feishu/pending-binding.repository.ts:15-24`
- **问题**：发送卡片成功后，`setCardMessageId()` 抛错时异常会被 `FeishuInboundProcessor` 捕获并触发文本回退，这一部分已改善；但该异常路径没有调用 `pendingBindingMessages.fail(auth.state)`，数据库记录仍是 `PENDING`。后续 OAuth 成功时又因 `claim()` 状态条件错误无法领取；即使修正 claim，缺失 card ID 也无法准确复用原卡片。
- **影响**：持久化失败时系统会留下永远无法正常恢复的待绑定任务，且状态与实际已发卡片不一致；重试/运维清理也无法区分发送成功但 ID 未落库的记录。
- **修复建议**：将“发送成功、响应解析、cardMessageId 持久化”纳入统一异常处理；`setCardMessageId` 失败时尽力标记 FAILED（或专门的不可恢复状态），并保持文本回退。对已发送但无法持久化 ID 的场景不要保留可恢复的 PENDING 记录。

## 已核验

- 未授权卡片发送异常现在会在 `FeishuInboundProcessor` 中捕获，并继续发送文本回退；发送响应缺少 `message_id` 也会回退。
- OAuth 并发回调在进入飞书外部认证前通过 `claimPending()` 做了 PENDING→PROCESSING 原子领取，重复回调不会再次执行外部认证；成功转换也检查 affectedRows。
- `renderCallbackPage()` 不会在 `completeStateWithCode()` 成功路径内重复调用认证回调；但当前成功副作用链路被上述 pending claim bug 阻断，修复后仍应保留单次领取保护。

未修改业务代码；本报告已写入指定目录。
