## BUG-A（P2，建议合入前修复）`echoesPersistedReply` 跨轮误判：中止轮次的「唯一副本」被当同轮回显删除

### 位置

`desktop/src/stores/session/messages.ts:26-40`（`echoesPersistedReply`，问题在 32-36 行的扫描循环）；调用点 `messages.ts:214`（尾部保留分支）与 `messages.ts:230`（两条已落库消息之间插回分支）。

### 根因

```ts
for (let j = index - 1; j >= 0; j--) {
  if (local[j]!.role !== 'user') continue;
  const userPos = fetched.findIndex(m => String(m.id) === String(local[j]!.id));
  if (userPos < 0) return false;
  for (let k = userPos + 1; k < fetched.length; k++) {
    if (fetched[k]!.role !== 'assistant') continue;   // ← 遇到后续 user 消息不停止
    return fetched[k]!.content === message.content && ...
  }
  return false;
}
```

从「本轮的 user 消息」向后找**第一条 assistant** 时，中途再出现 user 消息（即进入了下一轮）不停止，于是拿**下一轮已落库的助手消息**和本轮的中断气泡比内容。两者相同（含「双方都为空」）即判「同轮回显」，把气泡删掉/不插回。

注意这正是 BUG-1 竞态面修复（同轮去重）自身引入的新回归：去重逻辑本应只认「同一条 user 消息之后、下一条 user 消息之前」的那条助手消息。

### 触发路径（两种，均已复现）

1. **文本场景**：第一轮流式中途被停止（服务端不落库）→ 用户重发同一问题（或队列补发重复消息），第二轮完整落库且回复内容与半段恰好相同（确定性短答案，如 "2"）→ 终态/切会话重拉 → 第一轮的中断气泡被当回显删除。
2. **工具轮场景（更常见）**：`harness-service.ts:147-150` 的 `persistAssistant` 对「content 为空 + 有 toolCalls」的轮次落库 `content ?? null`，桌面 `chatMessage.ts:332` 把 NULL 映射为 `''`。于是「被中止的工具轮气泡（content '' + toolCalls）」对上「下一轮已落库的工具轮回复（content ''）」即 `'' === ''` 误判为回显。工具轮是高频轮次，该场景不需要任何「内容巧合」。

### 用户/系统可见损害

被删/不插回的气泡是**服务端不落库的唯一副本**（BUG-1 修复要保护的对象）：对话区里该轮已流出的部分回复（含工具调用卡片）永久消失，且不因刷新恢复。文本场景丢文本，工具轮场景丢整轮工具调用记录。

### 最小验证用例（临时 spec，已删除）与运行结果


## BUG-B（P3）异步 exec 的 `current_workdir` 刷新在默认 `keep_session=false` 下是死代码

### 位置

`backend-ts/src/harness/tool/impl/shell-session-tool.ts:203-209`（异步任务内 `settleSession` 在 204 行、`resolveCurrentWorkdir` 在 208 行）；前提 guard 在 `shell-session-tool.ts:397`（`if (!result.completed || !session.isAlive()) return session.currentWorkdir;`）。对照：同步路径 230-233 行是**先刷新后 settle**。

### 根因

`settleSession`（255-257 行）在 `result.completed && !keepSession` 时 `closeOwned` → `sessionManager.close` → `session.close()` 置 `alive=false`。异步路径把 `resolveCurrentWorkdir` 放在 `settleSession` **之后**，其首行 `!session.isAlive()` 直接返回陈旧的 `session.currentWorkdir`——`keep_session` 缺省为 false（默认）且命令完成时，刷新完全不执行。round1 文档「遗留观察 1」声称已修复，实际只在显式 `keep_session: true` 时有效；且该改动无任何测试伴随，所以未被发现。

### 触发路径

`shell` 工具 `exec` + `async: true`（不传 `keep_session`）执行 `cd sub && …` 类命令 → `await_async` 或结果自动注入交付的 `current_workdir` 是会话创建时的旧值（工作区根），而非命令实际所在目录。

### 用户/系统可见损害

模型据错误的当前工作目录解析后续相对路径（如 `cat build.log` 在新会话的工作区根找不到 `sub/build.log`）；`handleList` 在异步路径下同样报旧值。无崩溃、无数据丢失，属「修复未按声明口径生效」的元数据错误。

### 最小验证用例（临时 spec，已删除）与运行结果

用假 `ShellSession`/`OutputManager`（`close` mock 会真实置 `alive=false`，对齐 `ShellSessionManager.close`），同一命令分别走异步（默认 keep_session）与同步路径，比对 `current_workdir`：

```ts
// 第 1 次 readUntilMarker = 命令输出；第 2 次 = pwd 回显 '/tmp/sub'
const asyncResult = JSON.parse(await submittedTask())   // async: true，不传 keep_session
const syncResult  = JSON.parse(await tool.execute(JSON.stringify({ command: 'cd sub && make' }), 11, 7, '/tmp'))
expect(syncResult.current_workdir).toBe('/tmp/sub')     // 同步：刷新成功
expect(asyncResult.current_workdir).toBe('/tmp/sub')    // 异步：默认参数下失败
```

运行结果（`npx vitest run src/harness/tool/impl/zz-tmp-async-workdir.spec.ts`）：

```
× async exec（默认 keep_session=false）必须与同步路径同口径刷新 current_workdir
  AssertionError: expected '/tmp' to be '/tmp/sub'
✓ 对照组：keep_session=true 时异步路径刷新成功（证明修复只在该参数下有效）
```

### 建议修复方向

把 `resolveCurrentWorkdir` 移到 `settleSession` 之前，与同步路径同序（`readUntilMarker → resolveCurrentWorkdir → settleSession → formatResult(workdirNow)`）；并补一条默认 `keep_session` 的回归用例（可复用现有 `shell-session-tool.spec.ts` 的假 session 模式，`close` mock 需置 `alive=false` 才具备防回归能力）。
