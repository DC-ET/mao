# 代码审查报告

- 审查范围：当前 Git 工作区未提交代码
- 重点：OAuth state 生命周期、待绑定消息持久化映射、回调恢复执行、飞书卡片 patch、重复回调/并发安全、数据库迁移与 TypeScript 构建
- 结论：发现 2 个会直接影响业务功能的问题。

## 严重问题

### [高] 待绑定消息仓储读取字段使用了 snake_case，导致 OAuth 回调恢复执行必然失败

- 位置：`backend-ts/src/feishu/pending-binding.repository.ts:37-47`，尤其是 `row.app_id`、`row.message_id`、`row.card_message_id`、`row.event_json`。
- 现象：`Db.queryOne()` 会统一通过 `toCamelList()` 将数据库列名转换为 camelCase。查询 `SELECT *` 后返回的字段实际是 `appId`、`messageId`、`cardMessageId`、`eventJson`。当前代码读取 snake_case，因而 `appId/messageId` 会变成 `NaN/undefined`，`JSON.parse(String(row.event_json))` 会对 `"undefined"` 解析并抛异常。
- 影响：飞书绑定回调虽然可以完成 OAuth 状态更新和账号绑定，但随后恢复原群消息时无法构造事件，Agent 不会继续执行；同时 pending 记录已经先被标记为 `CLAIMED`，后续重复回调也不会再次处理，消息永久丢失。
- 修复建议：按 Db 的返回约定读取 `row.appId`、`row.messageId`、`row.cardMessageId`、`row.eventJson`，或改为显式选择并统一类型映射；补充仓储集成测试，覆盖 snake_case 数据库行经 `Db.queryOne()` 后的恢复流程。

## 中等问题

### [中] 发送未授权卡片失败时没有回退到文本消息，且会留下不可恢复的待绑定记录

- 位置：`backend-ts/src/create-app.ts:1024-1043`；调用链为 `backend-ts/src/feishu/inbound-processor.ts:67-72`。
- 现象：`sendUnauthorizedCard()` 在发送卡片前插入 PENDING 记录。如果 `reply()` 抛异常，异常直接离开 `sendUnauthorizedCard()`，处理器不会执行 `if (!sentCard) await this.sendUnauthorized(...)` 的文本回退；`finally` 只会释放入站事件，不会删除或失效待绑定记录。
- 影响：飞书 API 临时失败、权限不足或原消息不可回复时，用户既收不到绑定链接，也没有普通提示；数据库还会残留 PENDING 记录。若之后同一流程再次使用相同 state/重试，可能触发唯一键冲突或产生脏状态。
- 修复建议：在 `sendUnauthorizedCard()` 内围绕持久化与卡片发送做明确的失败处理：发送失败时删除/标记对应 state 的待绑定记录并返回 `false`，让处理器发送文本回退；卡片发送成功但 `setCardMessageId()` 失败时也应记录可诊断状态，并避免把该记录当作可恢复成功记录。

## 已验证项目

- TypeScript 构建：`backend-ts` 执行 `npm run build` 成功。
- OAuth state 的数据库更新使用了状态条件，`consumeSuccess()` 使用 `consumed_at IS NULL`，具备基本的重复消费保护。
- 待绑定消息 `claim()` 的 UPDATE 带 `status = 'PENDING'` 条件，数据库并发 claim 时只有一个调用可成功领取。
- 飞书恢复执行时会将保存的 `cardMessageId` 传入 `progressCardMessageId`，进度卡片路径使用 patch 同一张卡片；但该链路仍受上述字段映射问题阻断。
