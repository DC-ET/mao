## 二、新发现问题

### A（中）聚焦模式状态标签/颜色仍未消费 treeFailed / treeRunning

- **位置**：`desktop/src/components/task/TaskIndexPanel.vue` `focusStatusLabel`（约 589 行）/ `focusStatusClass`（约 602 行）
- **问题**：两函数只 switch `session.phase`（自身阶段），不读 `treeFailed` / `treeRunning`。排序已按树聚合升档（focusSort 修复），但视觉标签不一致：主任务自身 IDLE、边路任务失败/运行时，任务排在「失败/运行中」档最前，状态标签却显示「空闲」、颜色为默认，用户会困惑「为什么这个空闲任务排在最上面」。
- **建议**：与 `focusPriority` 同源判定——`focusStatusLabel`：`treeFailed → '已失败'`（在自身 phase 判定前）；`treeRunning → '运行中'`；`focusStatusClass` 同步补充 `treeFailed → status-failed`、`treeRunning → status-running`。

### B（中）边路任务 markAsRead 后父会话 treeUnread 仍不更新（M-5 修复不完整）

- **位置**：`backend/src/main/java/cn/etarch/mao/session/controller/SessionController.java` markAsRead 端点（约 295-296 行）调用 `treeSignalPublisher.publish(id)`
- **问题**：`publish(parentSessionId)` 的语义是「把参数当**父会话**重新聚合」。前端 `markSideTaskRead(sideId)` 调 `PUT /sessions/{sideId}/read`，此时 `publish(sideId)` 把边路任务当父会话：聚合「sideId + 0 个子边路」后推送 `session_tree_status(sessionId=sideId)`；前端 `updateSessionTreeSignals(sideId)` 在 `sessionEntities` 中找不到边路任务实体（边路任务不进入实体缓存）→ 直接 return。**真正父会话实体上的 treeUnread 不会被清除，聚焦排序滞留「未读」档（权重 3）**——与上轮 M-5 的问题场景完全一致，只是主会话已读路径被修好了。
- **建议**：区分主/边路再发布。例如：
  ```java
  sessionService.markAsRead(id);
  Session s = sessionService.getSession(id);
  if ("SIDE_TASK".equals(s.getSessionType()) && s.getParentSessionId() != null) {
      treeSignalPublisher.publish(s.getParentSessionId());
  } else {
      treeSignalPublisher.publish(id);
  }
  ```
  或组合 `publishIfSideTask(id)`（边路→父会话）+ `publish(id)`（主会话），注意边路场景会多一次无效推送（sessionId=sideId，前端忽略，可接受但不够干净）。
- **关联**：前端 `markAsRead` 成功回调只清 `entity.unread`，不清 `treeUnread`，完全依赖后端推送——后端此路径不修，断线/推送丢失场景亦无兜底。

## 三、观察项（低，非阻断）

- **C-1**：`toggleArchive` 展开时调用 `loadArchive()`（非 silent），即使 `archivedLoaded=true` 也置 `archivedLoading` 并全量重拉；与「刷新已归档」按钮行为重复。可改为 `archivedLoaded ? loadArchive(true) : loadArchive()` 或展开仅静默刷新。
- **C-2**：`updateSession` 深链接判断的边缘：若 `updates` 不带 `status` 且 `existing` 为空（如只 `{ executionMode: 'CLOUD' }`），`next.status === undefined` 不会被 `!== 'ARCHIVED'` 拦截，未知状态会话短暂进入标准投影。当前所有调用方（`fetchSession`/`loadSession`）都传完整 VO 含 status，实际不触发；可加 `next.status !== 'ARCHIVED' && next.status !== undefined` 防御。
- **C-3**：后端 `mvn test` 在本次核查中出现一次偶发 `BUILD FAILURE`（未捕获到具体失败用例，重跑即过，两次成功）。建议 CI 观察是否与并行/随机用例（如 CoverageSurfaceTest）相关，暂不构成阻断。
- **C-4**：聚焦主项与历史区 item 不渲染未读圆点（仅标准模式有，TaskIndexPanel.vue 118 行）。与问题 B 叠加会放大「排序在未读档但无视觉提示」的困惑。上轮已提，本轮未改动。
