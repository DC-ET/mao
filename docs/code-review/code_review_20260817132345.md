# 代码审查报告

## 中风险

### 1. 后端已移除 stale session 扫描器，长时间无响应的运行中会话将不再自动终止
- **位置**：`backend-ts/src/create-app.ts:76,293-303,724-752`，`backend-ts/src/session/stale-session-sweep.ts:1-39`，`backend-ts/src/session/session.service.ts:399-401`
- **问题**：这次改动删除了 `StaleSessionSweepScheduler` 的创建、启动和关闭逻辑，同时把 `SESSION_STALE_MINUTES`、`findStaleRunningSessions()` 也一并移除。当前仓库里没有看到替代的定时清理机制，`StreamingWsHandler.terminateStaleSession()` 只是在被外部调用时执行终止，并不会自己触发。
- **影响**：一旦某个 `RUNNING` / `RESUMING` / `WAITING_APPROVAL` 会话因为网络中断、前端崩溃、工具卡死等原因长时间不再有心跳或消息，系统将不再自动把它们转成失败态并清理运行资源。用户会看到会话长期挂在运行中，新的任务调度/恢复逻辑也可能被错误地阻塞。
- **建议**：保留原来的 stale session 扫描任务，或补上等价的新机制（例如基于 `last_activity_at` 的定时巡检）。如果确实想取消自动终止，也需要同步调整会话状态机和前端/调度逻辑，避免“僵尸运行中会话”影响后续业务。
