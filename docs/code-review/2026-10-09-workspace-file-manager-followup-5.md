## 从搜索结果重命名时，输入框里是整段路径

**现象：** 搜索结果行把 `name` 设成完整相对路径（例如 `src/a.ts`），用来区分同名文件。点重命名后，输入框的初值也是 `src/a.ts`，而不是文件名 `a.ts`。确认时名称里不能有 `/`，所以直接回车会提示「名称不合法」并取消；把显示内容改成 `src/b.ts` 同样过不了。用户必须先把目录前缀删掉，只留文件名，重命名才会提交。

**复现：** 打开搜索结果节点 `{ name: 'src/a.ts', path: 'src/a.ts' }` 的重命名输入框。

**失败测试：**

- 文件：`desktop/src/components/file-browser/FileTreeNode.rename.test.ts`
- 用例：`uses the file name when the row label is a search path`
- 断言：输入框的值应为 `a.ts`
- 实际：渲染结果是 `value="src/a.ts"`

**为什么是功能错误：** 重命名的新名字必须是同一目录下的一段文件名，后端也会拒绝带 `/` 的名称。打开文件、下载已经按路径取最后一段当标题或文件名，重命名输入框仍用了搜索行的整段路径，默认确认无法完成重命名。
