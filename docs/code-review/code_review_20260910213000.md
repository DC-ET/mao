## 二、需要处理的问题

### P1【中高】BUG-9 修复未生效：首次发送互斥仍在首次 `await` 之后

- 文件：`desktop/src/components/chat/SideChatPanel.vue`（`handleChatSend`）
- 现状：

```515:552:desktop/src/components/chat/SideChatPanel.vue
async function handleChatSend(text: string, files: File[], pendingUploads?: File[]) {
  ...
  await connect()
  ...
  const imageUrls = files.length > 0 ? await uploadImages(files, uploadSessionId) : []
  ...
  if (pendingUploads && pendingUploads.length > 0 && uploadSessionId) {
    resolvedText = await uploadPendingFiles(...)
  }
  ...
  if (sending.value) return
  // 首次/后续发送在任何 await 之前同步置位，防止双击/双 Enter 创建两个边路任务
  sending.value = true
```

- 问题：注释写「任何 await 之前同步置位」，实际 `sending` 在 `connect` / `uploadImages` / `uploadPendingFiles` 之后才检查并置位。双击/双 Enter 期间 `sending` 仍为 `false`，两次调用都可通过守卫并各自 `createSideSession`，与原 BUG-9 触发路径一致。
- 对照：主聊天 `prepareAndSendMessage` 在 `await` 前同步 `sending.value = true`（`useChat.ts` ~280–288 行）。
- 建议：函数入口（或至少在任何 `await` 之前）同步置位互斥标志；失败路径统一复位。队列入队分支可继续不受 `sending` 阻塞，但需避免与首次创建会话竞态。

### P2【中】BUG-3 残留：`saveMessage` 落库窗口内的取消仍可能被丢弃

- 文件：`backend-ts/src/session/ws/streaming-ws-handler.ts`（`autoConsumeQueue` / `handleSendMessage`）
- 现状：`autoConsumeStartedAt` 在 **占位、出队、saveMessage 成功之后** 才记录（约 1197–1207 行），再提交 500ms 延迟任务。
- 时序：

1. 占位/出队后进入 `saveMessage`（`cancelFlags` 尚未注册）；
2. 用户点「停止」→ `pendingCancels.set(sessionId, T1)` + `finishCancelledSession`；
3. `autoConsumeStartedAt = T2 > T1`；
4. `handleSendMessage` 以 `sendStartedAt = T2` 消费 pending，`T1 < T2` → 判定陈旧标记并丢弃；
5. 执行照常提交，CANCELLED 被覆盖回 RUNNING。

- 评估：原 BUG-3 描述的 500ms 窗口已覆盖；但「占位→落库完成」窗口与 500ms 窗口本质相同，修复时间点偏晚。
- 建议：在 `executionClaims.add` / 出队时刻（或 `autoConsumeQueue` 入口）记录 `sendStartedAt`，使整个 autoConsume 前置链路都落在取消可识别窗口内。

### P3【中】BUG-4 不完整：最后管理员检查与写入仍分离（TOCTOU 残留）

- 文件：`backend-ts/src/user/user.service.ts`、`backend-ts/src/permission/permission.service.ts`、`backend-ts/src/permission/permission.repository.ts`
- 已做对的部分：
  - `updateUser` 在 `updateById` 前拒绝空 `roleIds`；
  - `assignRoles`/`assignPermissions` 用 `transaction` 做先删后插，避免半截状态。
- 未做对的部分：
  - `assertCanChangeRoles` / `assertCanDisableUser` 仍在事务外单独读库；
  - 对 ADMIN 角色绑定行没有 `SELECT ... FOR UPDATE`；
  - 仅剩管理员 A、B 时并发降级仍可能双双放行，系统失去全部管理员。
- 另：`updateUser` 仍先持久化用户行再 `assignRoles`。角色写入失败时资料/状态已改、角色未改（空数组已提前挡住，其它失败仍有半截风险）。
- 建议：最后管理员断言与角色写入放进同一事务，并对 ADMIN 绑定加锁；或对「去 admin」路径做条件更新 + 行锁复核。

### P4【中低】BUG-2 不完整：busy 入队后任务状态永久停在 QUEUED

- 文件：`backend-ts/src/schedule/scheduled-task.service.ts` + 消费侧 `streaming-ws-handler.ts`
- 已做对的部分：
  - busy 入队时累加 `fireCount`/`lastFireTime`，`lastExecutionStatus='QUEUED'`；
  - `once` 任务入队成功即 `finished=1` 并清 `nextFireTime`，避免次年二次触发（原路径 A 已堵住）。
- 残留：
  - 队列消息之后由 autoConsume 当普通 USER 消息执行，**不回查/不回写** `scheduled_task`；
  - 周期任务在 busy 入队后，`lastExecutionStatus` 会永久显示「排队中」，不会变成 COMPLETED/FAILED（原路径 B 的状态展示问题仍在）。
- 建议：enqueue 时绑定 `scheduledTaskId`，autoConsume 成功/失败后 CAS 回写 `QUEUED → COMPLETED/FAILED`（至少更新 `lastExecutionStatus`）。

### P5【低】BUG-8 不完整：SSE 回退仍在构造器 try/catch

- 文件：`backend-ts/src/harness/mcp/mcp-client-manager.ts`（`buildTransport` / `connect`）
- 现状：

```104:118:backend-ts/src/harness/mcp/mcp-client-manager.ts
const url = new URL(server.url ?? '');
try {
  return new StreamableHTTPClientTransport(url);
} catch {
  return new SSEClientTransport(url);
}
```

- 问题：`StreamableHTTPClientTransport` 构造通常不抛错；连接失败发生在 `client.connect(transport)`，不会触发 SSE 回退。原报告要求「SSE 回退改到 connect/listTools 阶段」未落实。
- 另：`callTool` 的 `withTimeout` 只是 `Promise.race`，超时后底层 MCP 调用仍在跑，不 abort transport/请求。可接受为「不拖死整轮」的缓解，但不是完整取消。
- 已做对：重连前 `closeClient` 旧客户端；`listTools` 失败清理连接；`callTool` 有超时。

### P6【低】BUG-13 残留：endsWith 左边界允许空格，短句仍有误命中面

- 文件：`sdk/embed/src/core/store.ts`（`sameMessageText`）
- 现状：优先 `stripContextPrefix(fetched) === local`；兜底 `endsWith` 要求左边界为 `\n` 或空格。
- 问题：拼装分隔符 `PREFIX_SEPARATOR` 以 `\n` 结尾，空格边界偏松（如历史正文 `"... BOOK OK"` 与本地 `OK` 仍可能命中）。
- 建议：左边界仅保留 `\n`（或分隔符末字符），或去掉 endsWith 兜底、只保留 strip 全等/精确相等。

## 三、确认正确的修复（摘要）

1. **BUG-1**：`handleInsertMessage` 校验 `status === 'PENDING'`；`abortRunningExecution` 仅在校验通过后执行；`awaitExecutionRelease` 后二次复读，避免 autoConsume 抢先消费导致重复执行。
2. **BUG-5**：`cancelAllForParent` 改 `updateTerminal`（仅 RUNNING/RECOVERING→CANCELLED）；`finishExecution` 对已终态 session 直接忽略，避免把 COMPLETED 子会话改写成 CANCELLED。
3. **BUG-6**：空响应分支不再更新 anchor、不压 `afterStream`；`continue` 前调用 `onRoundEnd`，前后端回合事件成对。
4. **BUG-7**：`file-write-lock.ts` 按绝对路径串行；`edit_file`/`write_file` 均包在锁内。
5. **BUG-10**：`session.removeLastUserMessage` 已实现并导出；`prepareAndSendMessage` 失败路径回滚乐观用户消息。
6. **BUG-11**：`clearPendingApprovals(onlySessionId)`；`newSession`/`cleanup` 只清当前会话审批。
7. **BUG-12**：选中内容写入前 `escapeSeparatorSequences`，`extractQuotedSelection` 回显前 unescape。
8. **BUG-14**：`createAgentExecutor` 用 `.catch().finally()`，reject 不再变成 unhandled rejection。
