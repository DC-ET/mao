## 总体结论

**不可合并（阻塞项 2 个）**。核心链路（用户点踩、管理端明细）在真实 DB 环境下会因行键名大小写转换而全部失效；单测因 mock 未覆盖。

## 阻塞

### 1. FeedbackDbLookup 读取 snake_case 键，但 Db.query 已统一转 camelCase → 所有用户点踩必然报「无权操作该消息」

- 文件：`backend-ts/src/feedback/feedback.service.ts:22-34`（`findAssistantMessageOwner`）
- 描述：查询走 `this.db.queryOne(...)`，而 `Db.query` 内部经 `toCamelList` 把所有行键转为 camelCase（`backend-ts/src/db/db.ts:8-11`、`common/case.ts`）。SQL 里 `s.id AS session_id, s.user_id, s.agent_id` 运行时键是 `sessionId / userId / agentId`，但代码按 `row.session_id / row.user_id / row.agent_id` 读取，全部为 `undefined`。
- 影响：`requireOwnedAssistantMessage` 中 `ownership.userId !== userId` 恒为 true（undefined !== number），任何合法用户点踩/取消点踩都会抛 `MESSAGE_ACCESS_DENIED`（3031），功能完全不可用；且 upsert 会写入 undefined 的 sessionId/userId（若判断被绕过还会污染数据）。
- 修复建议：读取键改为 `row.sessionId / row.userId / row.agentId`（或泛型直接声明 camelCase 字段），并补一条不走 mock、直接验证该 SQL 结果键名的集成测试。

### 2. mapDetailRow 同样按 snake_case 读键 → 管理端明细列表字段全空/错乱

- 文件：`backend-ts/src/feedback/feedback.repository.ts:139-158`（`mapDetailRow`）
- 描述：`listDetails` 同样使用 `db.query`（键已转 camelCase），但 `mapDetailRow` 读取 `row.message_id / row.session_id / row.user_id / row.agent_id / row.display_name / row.agent_name / row.content_raw / row.created_at`，均为 `undefined`（仅 `id / username / reason` 等单词键幸存）。`content_raw === undefined` 时因 `undefined == null` 判 null。
- 影响：`/v1/feedback/admin/list` 返回的明细：`messageId/sessionId/userId/agentId` 为 undefined，`displayName/agentName` 恒 null，`contentPreview` 恒 null（内容明明存在却显示「消息已不存在」），`createdAt` 为字符串 `"undefined"`（`String(undefined)`）→ 前端时间列显示 undefined。管理端点踩反馈页面基本不可用。
- 修复建议：`mapDetailRow` 改读 camelCase 键（或该查询绕过 toCamel / 用别名保持一致），并补集成测试覆盖真实行键名。

## 重要

### 3. 管理端汇总卡片不随日期筛选变化，与筛选语义不符

- 文件：`backend-ts/src/feedback/feedback.service.ts:90-91`（`getSummary`：total/byReason 不吃日期参数，仅 byDay 吃）+ `admin/src/views/feedback/FeedbackView.vue`（`fetchSummary` 把 startDate/endDate 传给 summary 接口）
- 描述：admin 页把日期范围同时传给 `/feedback/admin/summary` 和 `/feedback/admin/list`，用户自然预期汇总卡片随日期过滤；但后端 `getSummary` 的 `total`/`byReason` 始终是全量统计，日期参数只影响 `byDay`，而 byDay 前端根本没展示。
- 影响：选择日期范围后，「点踩总数」与各原因卡片数字不变，与明细列表（已过滤）对不上，造成统计口径困惑。
- 修复建议：二选一并保持前后端一致——① `getSummary` 让 total/byReason 也按 startDate/endDate 过滤；② 前端 summary 不传日期参数并在 UI 上注明汇总为全量。

## 建议

### 4. 点踩 popover 无法通过点击外部关闭

- 文件：`desktop/src/components/chat/MessageBubble.vue:130-137、489-493`
- 描述：`el-popover` 使用受控 `:visible="dislikePopoverVisible"`，只有再次点按钮或选完原因/取消点踩才置 false；受控模式下 Element Plus 不会响应外部点击关闭。
- 影响：轻微交互问题（popover 一直悬停），不影响数据正确性。
- 修复建议：监听 popover 的 outside-click（如 `trigger` 改手动 + `:virtual-triggering` 或在 document click 上关闭），或改用非受控方式配合 `hide` 方法。

### 5. 会话被逻辑删除后其消息仍可点踩

- 文件：`backend-ts/src/feedback/feedback.service.ts:24-31`
- 描述：`findAssistantMessageOwner` 只校验 `m.deleted = 0`，未校验 `s.deleted = 0`（V051 起 session 也有逻辑删除）。
- 影响：极边缘场景：会话删除后若前端仍有消息 ID，可继续写入点踩；统计侧影响很小。
- 修复建议：SQL 追加 `AND s.deleted = 0`。

### 6. repository 存在死代码 `listMessageIds`

- 文件：`backend-ts/src/feedback/feedback.repository.ts:64-72`
- 描述：`listMessageIds(messageId[])` 生产代码无任何调用（仅 spec mock），与 `listMessageIdsBySession` 重复。
- 影响：无功能影响，仅可维护性。
- 修复建议：删除或留注释说明预留用途。
