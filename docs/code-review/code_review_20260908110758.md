## P3：后台允许通配端口 0 通过校验，实际保存被后端拒绝

### 位置

- `admin/src/views/settings/companySsoConfig.ts:40-55`：`validateOrigins` 的通配 Origin 分支。
- `admin/src/views/settings/components/CompanySsoConfigPanel.vue:78-90`：前端校验通过后提交单 key PUT。
- 对照：`backend-ts/src/auth/company-sso.config.ts:41-47`：`parseWildcardOrigin` 的端口正则明确从 1 开始。
- 回归覆盖缺口：`tests/admin-company-sso.spec.ts:39-52` 的非法通配列表未包含 `https://*.acg.team:0`；后端 `company-sso-origin.spec.ts` 已将此值列为非法。

### 触发及实际结果

1. 在可编辑、具备 settings:write 权限的公司 SSO 配置中输入 `https://*.acg.team:0`。
2. 前端移除 `*.` 后解析为 `https://acg.team:0`。WHATWG URL 接受端口 0，域名检查和 `url.origin === origin` 均通过，前端没有额外端口下界检查。
3. 保存将提交包含该值的完整 JSON。
4. 后端通配端口正则为 `[1-9][0-9]{0,4}`，因此拒绝该配置，返回业务 code=2001，数据库更新次数为 0。

已在内存中调用真实 admin helper，再将其输出通过 Fastify inject 交给真实 settings 路由和 service，复现上述结果；存储使用 mock，无真实数据库访问。

```json
{
  "adminAccepted": ["https://*.acg.team:0"],
  "saveResponse": { "code": 2001 },
  "writes": 0
}
```

### 影响

属于前端漏校验与配置保存体验问题：界面认为配置有效并发送请求，但实际无法保存，且后端仅返回通用配置错误。现有配置未被覆盖，不构成权限或信任边界绕过，因此定为 P3。

### 修复建议

保持后端已明确的通配端口规则，在前端通配分支显式拒绝端口 0，并给出端口范围提示；不要放宽后端作为兼容或降级处理。补充前端 helper、表单不发送 PUT 的回归测试。可增加两端共享测试向量，覆盖无端口、0、1、443（显式默认端口拒绝）、8443、65535、65536及前导零。

## 已验证的其余行为

- 子域通配匹配任意层级子域，不包含根域；严格比较协议和端口。
- 相似后缀、域名拼接欺骗、userinfo、路径及非规范 Origin 被拒绝。
- 精确匹配先于通配计算，IP/IPv6/localhost 与通配混合时不受列表顺序影响。
- CORS 与 POST 使用相同 matcher，配置仍经五字段校验并按单条 JSON 保存；每请求共享快照，新请求读取更新后的配置。
- `*` 下预检与 POST 返回 Access-Control-Allow-Origin: *，不设置 Access-Control-Allow-Credentials。
- `*` 未取消 Mao HTTPS、checkUrl HTTPS、校验域名白名单和 SSO 认证。
- 补充合成验证：HTTP/null Origin 下缺失 Bearer 返回 400，上游明确 illegal=true 返回 401；不绑定身份、不签发 JWT。
- 损坏/禁用配置仍 fail-closed，保存及启停未重建限流器。
