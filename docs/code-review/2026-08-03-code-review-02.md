## 1. [阻断] Flyway 迁移版本号重复，应用启动时迁移校验会失败

- 位置：`backend/src/main/resources/db/migration/V069__user_mcp_server.sql:1`
- 现有冲突文件：`backend/src/main/resources/db/migration/V069__scheduled_task_finished.sql:1`
- 触发条件：后端启动并由 Flyway 扫描数据库迁移脚本。
- 影响：同一迁移目录内存在两个 `V069` 版本。Flyway 要求版本迁移唯一，会报重复版本错误，导致数据库迁移及后端启动失败，本轮功能无法部署。
- 建议：将新增迁移调整为当前未占用的后续版本号。

## 2. [高] 编辑私有 MCP Server 时连接配置被清空，常规编辑无法保存

- 位置：`desktop/src/views/settings/McpServersView.vue:290`、`desktop/src/views/settings/McpServersView.vue:347-380`
- 触发条件：用户编辑已有私有 MCP Server，只修改名称、描述或环境变量后保存。
- 影响：
  - `load()` 将 `/mcp-servers/me` 返回的 `command`、`argsJson`、`url` 丢弃；
  - `openEdit()` 又将 `command`、`args`、`url` 全部初始化为空；
  - STDIO 配置会因缺少启动命令/参数而校验失败，HTTP 配置会因缺少 URL 而校验失败。
  因此用户不能在保留原连接参数的情况下完成普通编辑；重新手工填写还可能意外覆盖原配置。
- 建议：编辑时保留完整 `McpServerConfig`，并回填 `command`、解析后的 `argsJson` 与 `url`；仅环境变量按现有安全策略不回显。

## 3. [高] 全局 Server 后创建时可与私有 Server 重名，运行时工具路由产生歧义

- 位置：`backend/src/main/java/cn/etarch/mao/harness/mcp/service/McpServerService.java:390-418`
- 关联位置：`backend/src/main/java/cn/etarch/mao/harness/mcp/local/McpSyncService.java:174-180`
- 触发条件：用户先创建名为 `foo` 的私有 Server，管理员随后创建或重命名一个同名全局 Server；该全局 Server 被 Agent 关联并由该用户运行。
- 影响：私有 Server 创建时会检查全局重名，但全局 Server 创建时只检查其他全局记录，没有反向检查私有记录。运行时会同时注入两个 `foo`，生成相同的 `mcp__foo__{toolName}` 工具前缀；LOCAL 模式还会通过仅按名称且 `LIMIT 1` 的查询反查 Server ID，可能覆盖工具、重复提交工具或路由到错误 Server。
- 建议：创建/重命名全局 Server 时同步检查所有私有 Server 的同名记录，或让运行时路由使用带作用域/ID 的唯一标识。

## 4. [中] 逻辑删除后无法重新创建同名私有 Server

- 位置：`backend/src/main/resources/db/migration/V069__user_mcp_server.sql:8`
- 关联位置：`backend/src/main/java/cn/etarch/mao/harness/mcp/service/McpServerService.java:241-250`、`backend/src/main/java/cn/etarch/mao/harness/mcp/service/McpServerService.java:404-407`
- 触发条件：用户删除一个私有 Server，之后使用相同名称重新创建。
- 影响：`deleteById()` 受 `@TableLogic` 影响只将记录标记为删除；服务层查重会自动忽略逻辑删除行，但数据库唯一索引 `(user_id, name)` 仍包含该行。创建时会绕过业务查重，随后因唯一键冲突失败，用户无法复用已删除 Server 的名称。
- 建议：采用与逻辑删除兼容的名称复用方案，例如删除时归档名称后再逻辑删除，或对该表使用受控物理删除；不要只把 `deleted` 加入唯一索引，否则多次删除同名记录仍会冲突。
