# 未提交代码审查报告

审查范围：当前 Git 工作区中未提交的代码变更。仅检查功能逻辑，已排除页面样式与文档变更。

## 结论

发现 3 个潜在功能问题，其中 2 个中等优先级、1 个低优先级。

## 1. [中] 异步补拉完成时按“当前标签类型”写缓存，快速切换可能写错或丢失元数据

**位置**：`desktop/src/views/task/TaskView.vue:277-306`

监听器只固定了请求对应的 `sid`，但请求返回后重新读取了 `inspectorViewType.value` 和 `activeSessionIdRef.value`。如果用户在请求期间从边路任务切换到子代理，或切换了主会话，响应会按切换后的标签类型和父会话处理。

例如：打开边路任务 A 后，在请求返回前切换到子代理 B。A 的响应返回时可能进入 `updateSubagentMeta` 分支；由于 A 不是子代理，更新会被静默丢弃。切换主会话时，也可能使用新主会话 ID 更新边路任务缓存。

这会造成子会话标题、状态或 `modelId` 未正确写入，检查器持续显示回退数据。并且该 `sid` 已被加入 `fetchedInspectorMeta`，后续切回也不会再次补拉。

**建议**：请求发起前固定本次请求的会话类型和父会话 ID，响应处理时使用固定值，而不是读取届时的响应式状态。

## 2. [中] 首次补拉失败后永久禁止重试，且一个接口失败会丢弃另一个接口的成功结果

**位置**：`desktop/src/views/task/TaskView.vue:280-309`

`fetchedInspectorMeta.add(sid)` 在请求成功前执行，异常分支没有删除该标记。同时元数据和 todos 使用 `Promise.all` 请求，任意一个接口失败都会让整个处理流程进入 `catch`。

因此首次打开子会话时，只要发生临时网络失败、超时，或两个接口中任意一个失败，该子会话在当前页面生命周期内就不会再补拉。即使 `/sessions/{sid}` 已成功、仅 todos 请求失败，成功返回的标题、状态和模型信息也不会写入缓存。对于不会再产生 WebSocket 更新的历史子会话，缺失状态可能一直持续到刷新页面。

**建议**：区分“请求中”和“已成功获取”状态；失败时允许重试，并让元数据与 todos 独立处理失败，避免互相阻断。

## 3. [低] 子会话上下文缺失时会混用主会话 token 和子会话模型上限

**位置**：

- `desktop/src/views/task/TaskView.vue:256-272`
- `desktop/src/components/task/TaskInspector.vue:219-223`

子会话没有自身 `contextWindow` 时，`inspectorContextWindow` 回退主会话的 token 数据；但 `inspectorModelId` 仍优先使用子会话模型。若主、子会话模型的上下文上限不同，界面计算的是“主会话 token / 子会话模型上限”，显示的上下文百分比会不准确。

**建议**：确保 token 数据和模型 ID 始终来自同一会话；子会话上下文缺失时可不显示占比，或让两项数据一起回退到主会话。
