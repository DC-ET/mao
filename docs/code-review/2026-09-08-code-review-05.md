## 高严重度（P1）

### 1. 旧快照仍可在 SPA 导航或目标语义变化后执行，可能操作错误业务对象

**位置**：`sdk/embed/src/page.ts:86-94,107`。

**问题**：增加 snapshotId 比较只解决了“重新 inspect 后拒绝旧快照”，没有解决页面自身变化导致的引用过期。执行前既不比较当前 URL 与快照 URL，也不校验 DOM 语义版本。SPA 路由复用同一按钮或列表复用 DOM 节点时，元素仍在 document 中且可见，旧 snapshotId 仍匹配，动作会作用于新的业务对象。例如 inspect 记录 A 的删除按钮后，页面切到记录 B 并复用该按钮，旧 click 请求仍会执行 B 的处理逻辑。

pageVersion 也仍不一致：快照为 URL、body 子元素数及时间戳，成功动作结果只有 URL 和子元素数；无法据此可靠判断页面是否改变。

**修复建议**：建立导航和关键 DOM 语义变化的失效机制；执行前核验页面版本及目标身份，失效明确返回 snapshot_expired，要求重新 inspect。统一快照与结果的版本机制，补充 SPA 路由复用、列表节点复用和重采样后旧引用拒绝测试。

**历轮状态**：18:00 报告的引用失效和版本问题、18:17 报告第 4 项仍未完整修复；不能把新增 snapshotId 判等视为完成导航失效。

### 2. task 授权仍没有任务/会话边界，会扩大到后续任务

**位置**：`sdk/embed/src/authorization.ts:5-13`；`sdk/embed/src/index.ts:64,69,72-74`。

**问题**：task 只是实例中的一个字符串，未绑定 taskId/sessionId，也没有任务结束、停止、会话切换或身份切换时的撤销入口。setPageAuthorization('task') 后，执行 API 持续放行；newSession 仅调用 controller.newSession，不清除授权。用户只同意本次任务，后续任务仍可以沿用该级别执行提交等动作。

最新入口是 `new PageAuthorization(..., 'anonymous', false)`，因此本项不是“刷新后恢复 task/full”或“持久化跨账户继承”。刷新不恢复已修复，但内存授权范围仍不正确；真实身份隔离也尚未接入。

**修复建议**：task 绑定经过确认的任务和会话标识，在结束、停止、切换会话、身份变化或撤销时立即失效；每次产生 DOM 副作用前验证请求归属。未接入任务生命周期前，不应把 task 当作已实现的任务级授权。

**历轮状态**：18:17 报告第 2 项中的持久化问题已修复，任务/会话结束失效问题仍未修复。

## 中严重度（P2）

### 3. 动作仍忽略控件状态和适用类型，并将未完成动作报告为成功

**位置**：`sdk/embed/src/page.ts:82-84,94,101-107`。

**问题**：扫描返回 disabled/readonly，但执行没有使用这些状态，也没有按动作核验实际控件类型，最终只要未抛异常就返回 success。

- readonly 输入框仍可被原生 value setter 改写；这违反页面所表达的只读交互约束。
- disabled 原生按钮调用 click 通常不触发行为，代码却返回成功；继承 disabled fieldset 的状态也未检查。
- select 接收不存在的 value 时会丢失选择，仍派发 change 并返回成功；也未拒绝禁用 option。
- 已选 radio 执行 uncheck 只调用 click，不能取消选中，却返回成功。
- 对 button 等不可填写元素执行 fill 时，setter 不存在被可选调用跳过，仍派发 input/change 并返回成功。

这些问题会使调用方基于错误成功结果继续提交，或改写本不应编辑的字段。不是单纯的错误信息不友好。

**修复建议**：执行前按动作核验元素类型、`:disabled`、readonly 和适用的 ARIA 状态；对不支持的组合明确拒绝。select 在写入前检查 option，填写、勾选和选择后校验最终值/状态；不能把“没抛异常”当成动作完成。补充失败时不产生错误 DOM 副作用的测试。

**历轮状态**：无效 select 自 17:46、18:00 至 18:17 连续报告，仍未修复；状态/类型检查及 fill 伪成功在 18:00、18:17 已报告，仍未修复。

### 4. keyboard 类型已改为 key，但执行分支未实现，合法按键请求必然失败

**位置**：`sdk/embed/src/page.ts:32,101-105`。

**问题**：公开 PageAction 定义 keyboard 使用 key，execute 却没有 keyboard 分支，最终进入 fill 的兜底逻辑。合法请求 `{ type: 'keyboard', key: 'Enter', elementId, snapshotId }` 没有 value，会返回 element_not_fillable，完全不会发送按键事件或执行按键语义。Enter、Escape、Tab 等公开能力不可用。

**修复建议**：为 keyboard 增加独立执行分支和明确支持的按键语义；不能可靠实现的行为返回准确的 unsupported 错误，不混入 fill。覆盖 Enter/Escape/Tab，确认不会覆盖输入框已有值。

**历轮状态**：18:17 报告第 8 项是 keyboard 错误覆盖字段；本轮合法类型请求不再覆盖字段，但变为全部失败，功能仍未修复，不能原样沿用旧复现描述。
