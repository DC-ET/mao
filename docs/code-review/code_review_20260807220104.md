## 问题清单

### 【低】边路/子代理面板的自动滚动未纳入 llmRetry（本轮修复不对称）

- 位置：
  - `desktop/src/components/chat/SideChatPanel.vue` `buildScrollAnchor`（聚合 `msgs.length`/`content.length`/`toolCalls`/`sending`/`showTypingIndicator`/`sidePendingQuestions` 等，**未含 llmRetry**）
  - `desktop/src/components/chat/SubagentChatPanel.vue`（仅 `watch(displayMessages.length)` 与 `watch(phase)` 触发滚动，无 retry 维度）
- 说明：本轮仅给主会话 `ChatPanel.buildScrollAnchor` 纳入了 `activeLlmRetry`。边路/子代理面板的 `typing-retry` 重试条出现在消息区底部（typing-indicator 内），若消息区较长且用户滚动位置较高（或已上滑），重试条出现/更新不会触发自动滚回底部 → 重试提示不可见，与本需求「避免重试期间界面无响应」目标相悖。边路/子代理同为本次需求覆盖场景，应同步补齐。
- 建议：`SideChatPanel.buildScrollAnchor` 追加 `sessionStore.getLlmRetry(String(realSessionId.value)) ? 'retry' : ''`；`SubagentChatPanel` 增加对 `sessionStore.getLlmRetry(sid.value)` 的 watch（或在现有 `watch` 中补充该依赖）。

### 【低】`typingRetry` 判据盲区：最后一条为 assistant 且 thinking/streaming 均为 false 时提示仍不可见（遗留）

- 位置：`ChatPanel.vue`、`SideChatPanel.vue`、`SubagentChatPanel.vue` 三处 `typingRetry`（判据均为「最后一条非 assistant 才兜底」）
- 说明：重试提示的两种承载均依赖「该会话 thinking=true」（后端 `thinking_start` 先于 `llm_retry`，正常时序成立）。但以下场景 thinking=false：
  1. 页面刷新/重连后 `restoreSession` 恢复进行中会话（store 状态清空，`thinking_start` 不会重发；`ensureStreamingAssistantMessage` 追加的空占位 assistant 消息是最后一条）→ MessageBubble `isAssistantRunning=false` 不显示 + `typingRetry` 因最后一条 assistant 返回 null → 提示完全不可见；
  2. 断线窗口恰逢 `thinking_start` 事件丢失（`llm_retry` 在重连后仍会重发）。
- 影响：低概率（需重试恰逢刷新/断线窗口），但两处条件均依赖 thinking 状态、无本地兜底。上一轮已记录，本轮未修复。
- 建议（可选）：`typingRetry` 判据放宽为「最后一条 assistant 消息不满足 `isAssistantRunning`（无 thinking/streaming/running tool）时也允许底部兜底」，可消除盲区（需注意与 MessageBubble 的条件对齐，避免正常时序下重复显示）。

### 【低】SideChatPanel 占位窗口 `session-id=''` 回退主会话（遗留，前几轮已提）

- 位置：`SideChatPanel.vue:21`（`:session-id="hasRealSession ? String(realSessionId) : ''"`）
- 说明：首次发送边路消息、`side_session_created` 未返回的占位窗口内，MessageBubble 的 `llmRetry`/`isAssistantRunning` 回退主会话 `active*`。若主会话恰好正在重试，边路占位 assistant 消息会误显主会话重试条。实际时序上 `llm_retry`（带真实 sid）必在 `side_session_created` 之后到达，窗口极短，影响可忽略。维持现状可接受。

### 【提示】`showStreamIndicator` 仍使用主会话 `activeStreaming`，与 `isAssistantRunning` 按会话读取不一致（遗留）

- 位置：`MessageBubble.vue:235-237`
- 说明：边路/子代理消息在自身会话 streaming 而主会话未 streaming 时不显示三点指示器（漏显），反之可能错显。属既有行为，非本需求引入，但本轮改动后语义不一致更明显。建议一并对齐为按 `props.sessionId` 读取。

### 【提示】`llm_retry` 分支未做字段级校验（遗留）

- 位置：`useStreamWS.ts` `llm_retry` 分支（仅 `sessionId && data` 守卫）
- 说明：后端 payload 固定四字段（`WsStreamingEventListener.onLlmRetry`），风险低。可保持现状。
