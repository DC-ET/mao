# 代码审查报告：子代理追问（delegate_followup）功能 — 第 1 轮

> 审查时间：2026-08-07 23:00 | 审查方式：reviewer 子代理（git diff + 源码阅读 + mvn compile + 单测运行）
> 状态：已修复（见文末「修复记录」）

## 一、严重问题

### 【严重】1. `delegate_followup` 未加入 `ToolDispatcher.SERVER_ONLY_TOOLS`，LOCAL（桌面）模式下追问功能完全不可用

- **位置**：`backend/src/main/java/cn/etarch/mao/harness/tool/ToolDispatcher.java`（`SERVER_ONLY_TOOLS` 集合）；新工具位于 `DelegateFollowupTool.java`
- **问题**：`SERVER_ONLY_TOOLS` 包含 `"delegate"` 但不含新增的 `"delegate_followup"`。LOCAL 模式下 `dispatch()` 会把该工具经 WebSocket 发给桌面端执行，桌面端 `main.cjs` 对未知工具返回 `Unknown tool: delegate_followup`，追问在 LOCAL 模式必然失败。
- **修复**：将 `"delegate_followup"` 加入 `SERVER_ONLY_TOOLS`（与 `delegate` 并列）。

## 二、一般问题

### 【一般】2. 同一子会话被并行追问时存在竞态（check-then-act 非原子）

- **位置**：`DelegateFollowupTool.java`（phase 校验 → 落 USER 消息 → 插 RUNNING 审计 → `executeVisible`）
- **问题**：`AgentLoop` 并行执行同轮工具调用。若同一轮输出两个针对同一 `child_session_id` 的 `delegate_followup` 调用，两个线程都会通过 phase 校验并各自执行，导致双 USER 消息、双 RUNNING 审计、并发推流交错、cancel flag 互相覆盖。
- **修复**：执行前原子抢占——`UPDATE session SET phase='RUNNING' WHERE id=? AND phase<>'RUNNING'`，影响行数为 0 即返回「正在执行中」。

### 【一般】3. skip/取消路径下子会话 phase 与审计状态不一致（追问路径特有）

- **位置**：`DelegateFollowupTool.java` skip 分支、CANCELLED 终态；`TaskTerminalService.finishExecution` 终态守卫
- **问题**：`executeVisible(skip=true)` 不置 phase=RUNNING（父会话已取消场景），子会话 phase 仍停留在上一轮终态（如 COMPLETED）。随后 `finishSubagent(CANCELLED)` → `TaskTerminalService.finishExecution` 检测到 phase 已是终态直接 return：phase 不更新、也不发 WS 终态事件，DB 与审计状态不一致。
- **修复**：统一在执行前原子抢占置 RUNNING（同 #2 修复），保证 finish 前 phase 处于非终态，终态守卫放行。

## 三、轻微问题

### 【轻微】4. 追问开始未向前端推送任何事件，若子代理 Tab 已关闭则本轮过程不可见

- **位置**：`DelegateFollowupTool.java`（对比 `DelegateTool` 的 `notifySubagentCreated`）
- **问题**：追问只做服务端 `ensureSubscribed` 兜底；若用户此前关闭子代理 Tab，追问的流式事件无 UI 承接。
- **处理决定**：**本期不做**（已确认前端零改动；追问内容以普通 USER 消息呈现；用户可通过「查看过程」重开 Tab 拉取已落库历史）。`ensureSubscribed` 已保证订阅有效。

### 【轻微】5. `ToolResultSummarizer` 未为 `delegate_followup` 增加摘要分支

- **位置**：`backend/src/main/java/cn/etarch/mao/session/util/ToolResultSummarizer.java`
- **问题**：追问结果摘要显示为 `delegate_followup (成功)`，而 `delegate` 显示 `委派子代理 (成功)`，影响主代理上下文可读性。
- **修复**：补充 `case "delegate_followup" -> summarizeGeneric("追问子代理", result);`。
