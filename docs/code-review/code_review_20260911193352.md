## 复审新发现（均为低危，不阻塞收尾）

### N1（低）· 失败回退未恢复 localStorage 常驻指针与 tabs.claim

- 位置：`sdk/embed/src/controller.ts` — `selectHistory()` 回退分支
- 现象：切换中途已执行 `sessions.adoptSession(target)`（写 localStorage）与 `tabs.claim(target)`；历史拉取失败回退时只恢复 store 绑定，不写回 `previous`。后果：回退后 UI 显示 previous 会话，但持久化指针指向 target——刷新页面/新开 tab 后浮窗落在 target 会话，与本轮 UI 状态不一致（target 已通过 GET 校验、本身可用，故仅为体验不一致，无数据风险）。
- 建议（可后续优化）：回退分支补 `this.sessions.adoptSession({ id: previous } as EmbedSessionVO)` 与 `this.tabs.claim(previous)`。

### N2（低）· 回退路径 ui.phase 未恢复

- 位置：同上回退分支
- 现象：回退后 `ui.phase` 停留为 null（或目标会话 phase），依赖重新 subscribe 的 `session_snapshot` 回放纠正；若恰逢 WS 断线，phase 会缺显到重连为止。
- 建议：回退时从重拉历史/快照同步 previous 的 phase，或接受现状（重连必然对账）。

### N3（低）· newSession 的 catch 分支无 stale 检查

- 位置：`sdk/embed/src/controller.ts` — `newSession()`
- 现象：POST 在途期间发生身份切换且请求失败时，旧流程的错误文案会写到新身份的 `sessionError` 横幅（新身份 boot 会覆盖，窗口很短）。纯展示层问题。

### N4（提示）· loadMore offset 基于去重后的本地长度

- `loadMoreHistory` 用 `historyItems.length` 作 offset，去重后本地计数可能小于服务端已消费条数，翻页会重复拉取少量条目（去重已兜住，不会重复展示，也不会跳过条目）。当前实现可接受，无需改动。
