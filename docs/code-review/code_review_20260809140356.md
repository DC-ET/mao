# 代码审查报告：任务列表右键菜单 / 归档 / 聚焦模式（前端）

## 高（功能正确性）

### 1. 聚焦排序 / 状态标签未消费 `treeRunning` / `treeFailed` 聚合信号

- **位置**：`desktop/src/utils/focusSort.ts`（`focusPriority`、`FocusCandidate`、`sessionToFocusCandidate`）；`desktop/src/components/task/TaskIndexPanel.vue`（`focusStatusLabel` / `focusStatusClass`）
- **问题**：技术方案 2.B7 / 5.6 明确「主任务代表整棵任务树，待审批、待回答、**运行中、失败**均聚合主任务及其边路任务」，验收清单 #14 要求「Side Task 状态变化（如失败/待回答）→ 父任务在聚焦模式实时升档」。
  实际实现中：
  - `FocusCandidate` 没有 `treeFailed` / `treeRunning` 字段；
  - `focusPriority` 的「失败（权重1）」「运行中（权重2）」档位只判定主会话**自身** `phase`；
  - store 与 WS 侧确实把 `treeRunning` / `treeFailed` 写进了实体（`updateSessionTreeSignals`），但**全代码库无人读取**（grep 仅命中写入点与测试）。
- **后果**：边路任务失败时父任务显示「空闲」、按空闲档（权重4）沉底，且 `focusStatusLabel` 不显示「已失败」；边路任务运行中父任务也不升「运行中」。与需求核心价值（让用户知道哪些任务需要处理/在跑）直接冲突。
- **修复建议**：`FocusCandidate` 增加 `running` / `failed` 字段，`sessionToFocusCandidate` 从 `treeRunning` / `treeFailed`（回退自身 phase）映射；`focusPriority` 按 `failed → 1`、`running → 2` 判定（保持 pending 优先）；`focusStatusLabel` / `focusStatusClass` 同步消费。注意与 `WAITING_APPROVAL`（自身 phase）去重：树聚合 running 已含 WAITING_APPROVAL，但 pending 计数优先的既有逻辑已覆盖。

## 中

### 2. `updateSession` 深链接 / 冷启动恢复会把已归档会话误插入标准 ACTIVE 投影

- **位置**：`desktop/src/stores/session.ts` `updateSession`（约 676-680 行）
  ```ts
  if (!existing && updates.executionMode) {
    // Deep-link / loadSession for a session outside the current group preview
    if (!standardSessionIds.value.includes(sid)) {
      standardSessionIds.value = [sid, ...standardSessionIds.value]
    }
  ```
- **问题**：守卫条件只看 `!existing && updates.executionMode`，不检查 `status`。当用户通过 URL 深链打开（或 `getLastSessionId()` 冷启动恢复）一个**未在本地加载过实体的已归档会话**时（`fetchSession` / `TaskView.loadSession` 都会走 `updateSession(sid, data)`，data 含 `executionMode`），该已归档会话会被 unshift 进 `standardSessionIds`，错误出现在主任务列表，直到下次 `fetchSessions` 才被洗掉。
- **修复建议**：追加 `next.status !== 'ARCHIVED'`（或 `updates.status !== 'ARCHIVED'`）判断后再入标准投影；并补一条单测覆盖「已归档会话深链接不进标准投影」的回归场景。

### 3. 聚焦模式「历史」区右键菜单的「编辑标题 / 删除」不可用

- **位置**：`desktop/src/components/task/TaskIndexPanel.vue` 历史折叠区模板（`v-for="session in historySessions"`）
- **问题**：历史区 item 模板既没有 `session-title-input`（编辑态）也没有 `session-item-actions`（删除确认/取消按钮）。右键菜单「编辑标题」→ `editingSessionId` 置位后无输入框渲染，无法编辑；「删除」→ `confirmingDeleteId` 置位后无确认按钮，删除永远无法确认，且只有点击其它会话才能解除确认态（`selectSession` 会清 `confirmingDeleteId`）。
- **修复建议**：历史区 item 复用标准/focus item 的编辑输入与行内操作块；或在 `openContextMenu` 中对历史区 zone 做区分，隐藏「编辑标题 / 删除」，仅保留「归档」。

### 4. 已归档区无自动加载，冷启动后首次展开为空

- **位置**：`desktop/src/components/task/TaskIndexPanel.vue`（`loadArchive` 定义于 493 行，唯一调用点是 290 行「刷新已归档」按钮）
- **问题**：`archiveCollapsed` 展开、组件 `onMounted`、模式切换均不触发 `fetchArchivedSessions`。冷启动后首次展开「已归档」区显示「暂无已归档任务」，此前的归档全部不可见，必须手动点刷新按钮。
- **修复建议**：`watch(archiveCollapsed, (v) => { if (v && sessionStore.archivedSessionIds.length === 0 && !sessionStore.archivedLoaded) void loadArchive() })`，或 `onMounted` 时若 `archivedLoaded === false` 静默加载。

### 5. `treeUnread` 已读后本地不清理，聚焦排序滞留「未读」档

- **位置**：`desktop/src/stores/session.ts`（`markAsRead` / `markSideTaskRead`）；`desktop/src/composables/useStreamWS.ts`（`session_status` 分支）
- **问题**：`markAsRead` 只清主会话自身 `unread`，`markSideTaskRead` 只清 `sideTaskCache` 中边路项，均**不清父实体 `treeUnread`**；后端 `SessionService.markAsRead` 也不触发 `session_tree_status` 重推（`SessionTreeSignalPublisher.publishIfSideTask` 仅被 ToolDispatcher / LocalToolExecutor 调用）。因此用户已查看后，父任务在聚焦排序中仍长期停留在权重3「未读」档（聚焦项又不显示未读圆点，用户无法感知原因），直到下次拉取列表。
- **修复建议**：前端在 `markAsRead` / `markSideTaskRead` 成功后将父实体的 `treeUnread` 一并本地清除（或对已读边路重算）；更彻底的方案是后端在 read 路径补调 `publishIfSideTask`，让 `tree*` 由权威端刷新。

## 低（次要）

### 6. 聚焦模式下刷新按钮只刷新标准列表

- **位置**：`TaskIndexPanel.vue` `refreshSessions`（仅 `fetchSessions()`）
- **问题**：停留在聚焦模式时点顶部刷新，标准分组被重拉而 `focusSessionIds` 不更新，聚焦列表数据保持陈旧（设计 5.9「重连静默重拉」也未实现，见 #8）。
- **建议**：聚焦模式下 `refreshSessions` 改为 `fetchFocusSessions(true)`（或两者都刷）。

### 7. 聚焦首次加载无 loading 态（silent 静默拉取）

- **位置**：`TaskIndexPanel.vue` `watch(listMode)` → `loadFocus()` → `fetchFocusSessions(true)`
- **问题**：`focusLoading` 不置位，模板 `focusLoading && focusedSessions.length === 0` 不成立，首次进入聚焦模式会先闪现「暂无任务」再出数据。
- **建议**：首次进入（`focusedSessions.length === 0`）用非 silent 拉取，或增加本地 `focusLoadingFirst` 态。

### 8. 重连后不重拉聚焦列表（设计 5.9 未落地）

- **位置**：`desktop/src/composables/useStreamWS.ts` `onopen`
- **问题**：设计写明「focusSessionIds 已加载过 → 静默重拉全量 ACTIVE」，当前 `onopen` 只做会话订阅与 `refreshQueue`，聚焦数据依赖重新进入模式才会刷新。
- **建议**：`onopen` 中若 `sessionStore.focusLoaded` 则 `void sessionStore.fetchFocusSessions(true)`。

## 测试覆盖缺口（session.test.ts / focusSort.test.ts）

对照方案第 7 节「必测」清单，以下关键场景缺失：

1. **历史折叠 3 天边界**（恰好 3 天不折叠 / 超过 3 天折叠 / 无 `updatedAt` 用 `createdAt` 兜底）——无测试；
2. **`focusedSessions` computed 自动重排**：实体 `phase` / `tree*` / `unread` 更新后排序随之变化——现有测试只断言了实体字段写入，未断言重排结果；
3. **已归档会话深链接不进标准投影**（即问题 #2 的回归用例）——缺失；
4. **归档时 `archivedLoaded=true` 分支**（归档后静默刷新已归档区）与**重进聚焦静默刷新**——未覆盖；
5. `markAsRead` 成功后 `treeUnread` 联动清理（问题 #5）——未覆盖。

（已覆盖良好：分页隔离、归档 API 失败不预移除、markAsRead 失败保留未读、适配器字段映射。）
