## 中严重度

### 1. AgentLoop 将处理后的工具结果传给所有监听器，导致 WebSocket 图片预览丢失

**位置：**
- `backend-ts/src/harness/core/agent-loop.ts:496-515`
- `backend-ts/src/session/ws/ws-streaming-event-listener.ts:75-108`

`AgentLoop.executeToolCalls` 现在先调用 `processToolResult`，再将 `toolSave.content` 传给 `listener.onToolCallResult`：

```ts
const toolSave = this.processToolResult(rawResult, tc, context);
listener.onToolCallResult(tc.id!, toolSave.content);
```

`processToolResult` 会调用 `ToolImageResultProcessor.process`。当模型支持视觉且工具返回图片时，它会从 `sanitizedContent` 中删除 `data_uri`，并把原始 data URI 仅保存到 attachment/metadata。此前 WebSocket 监听器收到的是 `rawResult`，可在 `WsStreamingEventListener.onToolCallResult` 内再次处理并生成 `preview`，从而向桌面/Web 推送图片预览；改为 `toolSave.content` 后，WebSocket 侧收到的 JSON 已没有 `data_uri`，其 `ToolImageResultProcessor` 无法生成 preview，客户端将看不到工具图片预览。`WsStreamingEventListener` 的普通文本/文件结果仍可工作，但图片结果的其他通道行为发生回归。

**修复建议：**
不要用同一个字符串同时承担 Agent 上下文持久化和监听器展示两个语义。建议保持 `listener.onToolCallResult` 接收 `rawResult`（或扩展事件参数，同时传递 rawResult 与 toolSave.content）；Feishu 卡片摘要单独使用 `ToolResultSummarizer` 的结果/显式 summary 字段，WebSocket 继续基于 rawResult 完成图片预览及其展示清洗。补充 vision 模型下 `AgentLoop -> WsStreamingEventListener` 的集成测试，断言 `tool_call_result.data.preview` 存在。
