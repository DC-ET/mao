## 发现的问题

### [低] 重连重推与其他客户端提交答案并发时，会恢复已经失效的问题面板

**位置**：`backend/src/main/java/cn/etarch/mao/session/ws/StreamingWsHandler.java:401-408`

`handleSubscribe` 先通过 `getPendingForSession()` 获取待回答问题的快照，再逐条发送重推事件。若另一标签页或设备在获取快照后、事件入队前提交答案，`AskUserQuestionsRegistry.complete()` 会删除该 pending 条目并让 Agent 继续运行，但当前重连仍会把旧快照发送给客户端。

触发后，客户端会展示一个实际上已完成的问题；用户再次提交时，后端因对应 pending 已删除而静默忽略，面板也不会收到关闭事件。如果 Agent 后续仍长时间运行，该失效面板可能持续显示。

建议让问题完成时向客户端广播对应 `ask_user_questions_cancelled`（或等价关闭事件），并保证其与重连恢复事件的入队顺序；或者在 registry 内协调 pending 状态检查与恢复事件发送，避免查询快照和发送之间的竞态。
