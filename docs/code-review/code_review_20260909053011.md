## 二、P3

### P3-1. `dispatchBlur` / `executeFocus` 的 `ownerDocument` 口径对「开放 Shadow DOM 内元素」仍失效（既有问题，非本次引入）

**位置**
- `sdk/embed/src/page/framework-events.ts:54`（本次改动行 `if (el.ownerDocument.activeElement !== el) return;`）
- `sdk/embed/src/page/executor.ts:260`（`const active = el.ownerDocument.activeElement;`，同口径）

**问题**
元素位于 open shadow root 内时，`el.ownerDocument` 仍是主 `document`，而 `document.activeElement` 返回的是**宿主元素**（真正的焦点元素在 `shadowRoot.activeElement`）。于是 `dispatchBlur` 提前返回、`executeFocus` 的焦点校验失败。本次只修了 iframe，Shadow DOM 仍是同一处口径的盲区。

**复现（副本探针，happy-dom）**
- `div.attachShadow({mode:'open'})` 内放 `<input>`，`inspect` 后执行 `fill`：`success=true`，但 `blur` 触发 **0 次**（`focusout` 同样不派发）。
- 同一元素执行 `focus`：返回 `success=false`，`error.code='not_focusable'`。

**影响**
交接文档宣称支持「开放 Shadow DOM」，但该场景下 `fill` 不会触发依赖失焦提交/校验的表单逻辑，`focus` 动作直接失败。属既有缺陷（改动前后一致），但本次新增注释声称「与 `executeFocus` 口径一致」，容易让后续读者误以为 iframe 与 Shadow DOM 都已覆盖。

**建议**
统一改用根节点口径：`const root = el.getRootNode(); root.activeElement === el`。`getRootNode()` 对 iframe 内元素返回该 iframe 的 `Document`、对 Shadow DOM 内元素返回 `ShadowRoot`，可同时覆盖 iframe 与 Shadow DOM，并让 `dispatchBlur`、`executeFocus`（必要时含 `executor.ts:385` keyboard 的 `document.activeElement` 回退）口径一致；建议补一条 Shadow DOM 的 fill/focus 用例。若确认 Shadow DOM 不在本轮范围，至少在注释中写明「仅 iframe 已修复」。

### P3-2. `stateKeyOf` 未比较 option 的 `value` / `disabled`：select 非选中项取值变化不可见（覆盖缺口，非回归）

**位置**
- `sdk/embed/src/page/snapshot-manager.ts:42`（`descriptor.options.map((option) => option.selected)`）
- 对照 `sdk/embed/src/page/scanner.ts:113-118`（`options` 同时含 `value`、`disabled`）

**问题**
`signatureOf` 不含 option 的取值，`stateKeyOf` 又只比 `selected`。当选项 label 未变、仅某个**非选中** option 的 `value`（或 `disabled`）变化时，两处比较都不变 → `observe` 报「无变化」。

**复现（副本探针，happy-dom）**
`<select><option value="a" selected>A</option><option value="b">B</option></select>` → `inspect()` 后把第二个 option 的 `value` 改为 `'z'` → `changes = {added:0, removed:0, updated:0}`。（选中项值变化会被 `descriptor.value` 捕获，故只有非选中项受影响。）

**影响**
依赖下拉选项值（常见为后端 ID）变化的下拉场景，`page_observe` 会漏报，agent 可能误判页面未变化。属既有盲区，本次改动未使其恶化。

**建议**
若认为需要覆盖，把 `:42` 改为 `descriptor.options.map((o) => [o.value, o.selected, o.disabled])`（options 本就不脱敏，两侧口径一致）；否则可接受现状并保持注释说明。
