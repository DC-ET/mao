# 提案：出网边界与敏感数据防泄漏 —— 给 Agent 的"对外通道"装策略

- 状态：**已否决**（2026-10-09 评审：不做。本文仅存档，勿再评审）
- 日期：2026-10-09
- 提案总览：见 `docs/proposals/README.md`

## 1. 背景与现状

自托管团队部署 Mao 的核心动机是"数据与密钥不出内网"，但 Agent 的**出网面**今天完全自由：

1. **open_web_page**（`harness/tool/impl/open-web-page-tool.ts`）：Agent 可抓取任意 URL，`fetch-bytes.ts` 只做 URL 解析，**无任何内网地址/私网 IP 过滤**（全库 grep 私网段模式零命中）——这意味着一个被提示词注入污染的会话可以把 `http://169.254.169.254/`（云元数据）或内网服务内容抓出来，再经模型处理写进回复。
2. **web_search**：底层 Tavily / TinyFish，`base_url` 管理后台可配——搜索词本身会离开内网到达第三方搜索服务，这一点今天没有任何 UI 明示。
3. **shell**：CLOUD 模式下 `curl` / `wget` / `nc` 任意目标可达；LOCAL 模式同理（本机网络）。
4. **外发内容无扫描**：工具结果、模型回复经飞书/钉钉/微信/出站事件订阅外发时，不检查是否夹带密钥（模型 Key、Token、私钥）——一旦 Agent 读到 `.env` 并"汇报工作"，秘密就出了边界。

现有护栏只有执行边界（CLOUD/LOCAL）与工具审批（工具级、按调用），都是**粗粒度**的；审计Interceptor 记录管理 API 调用，不覆盖工具出网行为。与 `docs/research/2026-09-27-egress-traffic-analysis.md` 的边界：那份文档解决出流量的**体积**（带宽成本），本提案解决出网行为的**策略**（安全边界），两者正交。

## 2. 目标 / 非目标

**目标**

1. **私网与元数据地址拦截**：open_web_page / fetch-bytes / shell 网络命令在派发前判定目标地址，`127.0.0.0/8`、`10/8`、`172.16/12`、`192.168/16`、`169.254/16`、IPv6 等价段、link-local 一律拒绝；域名解析后取 IP 复检（防 DNS 指向私网）；HTTP 重定向跟随时对每一跳复检。
2. **出网域名策略**：系统级 allow / deny 列表（管理后台配置），deny 优先；作用于工具出网层（搜索源固定域名默认放行并可改）。
3. **敏感信息外发扫描**：对经渠道（飞书/钉钉/微信）与出站事件订阅外发的内容做模式扫描（API Key / Token / PEM 私钥 / 常见证件号模式），三档行为可选：`audit`（记录放行）、`warn`（通知管理员）、`block`（拦截该条外发并通知）。
4. **可观测**：所有拦截与扫描命中进审计（新事件类型）+ 管理后台「网络与数据边界」报告页（谁、哪个会话、什么目标、命中哪条规则）。

**非目标**

- 不做完整 DLP 平台：无内容分级分类、无水印、无文档权限继承。
- 不做 HTTPS 中间人解密/透明代理：工具保持直连模式，策略在工具层判定。
- 不阻断 LLM 提供商量流量：模型 Key 是平台自身配置，属可信出口（管理后台明示这一点）。
- 不做跨实例策略同步（P1 服务端全局 + 用户级覆盖两级，够用即止）。

## 3. 技术方案

### 3.1 判定链（P1）

- 新模块 `harness/safety/egress-policy.ts`（同级先例：`danger-assessor.ts`、`jev-risk-assessor.ts`）：
  - `EgressPolicy` 服务：读系统设置 + 用户覆盖，判定 `{host, port}` → allow / deny / block-private。
  - `resolveAndCheck(url)`：DNS 解析取全部 A/AAAA，逐一过私网判定；重定向由调用方逐跳回传复检。
- tool-dispatcher 判门链新增 egress 项（与 permission-level、approval-rule 并列）：open_web_page / fetch-bytes 在派发前调用；shell 工具对命令做网络目标提取（`curl`/`wget`/`nc`/`ssh` 的参数解析，保守策略：解析失败按需转审批而非放行）。
- LOCAL 委托：策略快照随 WS 委派消息下发给桌面 LocalToolExecutor，本地执行器同样判定（判定逻辑共享同一模块，双端一致）。

### 3.2 敏感信息扫描（P2）

- `harness/safety/secret-scanner.ts`：正则模式库（`sk-`、`AKIA`、`-----BEGIN.*PRIVATE KEY-----`、`Bearer <token>`、身份证/手机号模式）+ 高熵串兜底（限长、限采样，控 CPU）。
- 挂点：渠道外发（feishu/dingtalk/weixin 发送前的统一出口）+ 出站事件订阅投递前。行为档 `audit / warn / block` 按数据类型可配（P2 先 `audit` + `warn`，`block` P3）。
- 误报处理：命中记录含模式名与位置，管理员可在报告页标"误报"沉淀例外（会话级 + 全局两级）。

### 3.3 配置与报告（P1/P2）

- 系统设置新增「网络与数据边界」页：私网拦截开关（默认开）、allow/deny 列表编辑、搜索源白名单明示、扫描档位。
- 审计新增 `EGRESS_BLOCKED` / `SECRET_SCAN_HIT` 事件类型；管理后台报告页按 用户/Agent/规则 聚合。

## 4. 分阶段实施

| 阶段 | 内容 | 规模 |
|---|---|---|
| P1 | 私网/元数据拦截 + DNS 解析复检 + 重定向逐跳 + 设置页 + 审计事件 | 中 |
| P2 | allow/deny 域名策略 + secret-scanner（audit/warn 档）+ 渠道外发挂点 | 中 |
| P3 | block 档 + shell 网络命令提取 + 误报例外沉淀 + 报告页聚合 | 小~中 |

## 5. 风险与开放问题

- **误拦正常抓取**：用户确实需要抓内网服务（自托管 wiki 等）。缓解：allow 列表逃生舱 + 拦截错误信息含命中规则与目标地址，一目了然。
- **DNS rebinding / TOCTOU**：解析复检与请求之间窗口不可避免。缓解：抓取实现绑定"校验时的 IP"发起请求（不二次解析），把窗口压到最小。
- **shell 命令解析不全**：`curl` 参数变形（短选项合并、配置文件、管道中转）无法全覆盖。缓解：解析失败不猜——按需转人工审批（已有审批链路），而不是静默放行。
- **LOCAL 双端一致性**：桌面端执行器版本滞后于服务端策略。缓解：策略快照随每次委派下发 + 版本号，旧版执行器缺策略时按最严（私网必拦）执行。
- **扫描性能**：大 body 全扫 CPU 不可接受。缓解：限长（如前 64KB）+ 仅扫外发出口，不扫入站。
- **开放问题**：是否给"Agent 读到的文件内容"也过扫描（防密钥被读进上下文）——入站扫描误报代价高，P1 只做出站，列入后续评估。

## 6. 测试要点

- 私网 URL（`127.0.0.1` / `192.168.x` / `169.254.169.254` / IPv6 `::1`、`fc00::/7`）在 open_web_page 与 fetch-bytes 均被拦，错误含规则名。
- 域名解析到私网 IP 被拦；重定向链中任一跳指向私网被拦（含 allow 域名内的跳转）。
- allow 列表命中放行；deny 优先于 allow；LOCAL 委派工具同样生效。
- secret-scanner 各模式命中三档行为正确（audit 记录放行 / warn 通知 / P3 block 拦截）；命中记录进审计且报告页可见。
- shell 网络命令解析失败时转审批而非放行。
