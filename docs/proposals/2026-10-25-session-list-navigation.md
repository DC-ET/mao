# 提案：会话的「排得开、找得回」—— 半截子功能收口与长会话阅读导航

> 后端把置顶、收藏、标题过滤都做好了，前端一个入口都没接；长会话回访时「上次那段结论在哪」只能滚动硬找。会话是 Mao 的核心资产，列表超过两屏后就既排不开也找不回。

- 状态：待评审（第十六批）
- 日期：2026-10-25
- 提案总览：见 [docs/proposals/README.md](README.md)
- 规模：小~中（P1 约 2-3 人日、P2 约 1 人日、P3 约 2-3 人日；纯前端为主，零迁移）
- 关联：`desktop/src`（TaskIndexPanel / ChatRoundList / ChatPanel）；`session` 域（只消费既有端点）

## 1. 背景与现状

### 1.1 三个「后端已就绪、前端未接」（代码可查）

| 能力 | 后端现状 | 前端现状 |
|---|---|---|
| 置顶 | `PUT /v1/sessions/:id/pin`（session.routes.ts:331），toggle 语义；列表 SQL 已按 `is_pinned DESC` 排序（session.service.ts:275、335） | desktop 全仓无一处调用 pin 接口，列表无置顶入口、无置顶视觉 |
| 标题过滤 | `GET /v1/sessions` 的 listSessionGroups 已接受 `keyword`（title LIKE，session.service.ts:391；routes.ts:190 已透出） | TaskIndexPanel 无过滤框，会话多了只能滚动硬找 |
| 收藏 | `PUT /v1/sessions/:id/favorite`（session.routes.ts:338） | 同样零调用（语义与置顶重叠，见开放问题） |

这是典型的半截子功能：服务端排序、过滤、存储全部生效，用户却摸不到。**P1 的本质不是新功能，是把已建成的能力接上插座。**

### 1.2 两个真缺口

- **无批量操作**：归档只能逐条右键；一年上百个会话的存量用户清理成本极高。
- **长会话阅读无导航**：历史轮折叠为「已执行 N 个步骤」（ChatRoundList），但无轮次目录 / 跳转；无「只看回复」过滤（几百个工具卡片淹没十条回复）；顶部只有「回到最新」（ChatPanel.vue:71），没有回到顶部。运行轨迹解决的是「执行为什么这样」，不解决「我上次读过的那段答案在哪」——后者是日常回访的主要动作。

### 1.3 现有可复用的地基

- 全局搜索（Ctrl+K）已实现命中片段高亮 + 跳转定位 + 2 秒闪烁（`useMessageLocate.ts` / `search-highlight.ts`）——轮次目录的定位直接复用 `locateMessageId` 机制。
- 会话分组、归档区恢复、红点体系（运行 / 待审批 / 未读）均已就绪，批量操作是在既有语义上加多选。

## 2. 目标 / 非目标

**目标**

1. **P1 列表收口**：行内置顶 toggle（钉子图标，置顶会话有视觉区分）；列表顶部过滤框（接既有 `keyword` 参数，防抖 300ms，聚焦 / 标准两模式均生效）。
2. **P2 批量操作**：列表多选模式 → 批量归档（二次确认；恢复走既有已归档区）。
3. **P3 长会话导航**：轮次目录（每轮首条用户消息摘要 + 相对时间，点击复用 locateMessageId 定位闪烁）；「只看回复」开关（隐藏工具卡片 / 思考块 / 系统行，纯展示层过滤）；回到顶部按钮（与「回到最新」对称）。
4. 全部操作与既有排序语义（活跃 > 置顶 > 时间）兼容，不要求后端改动。

**非目标**

- 不做标签 / 文件夹体系（分组 + 归档 + 置顶已覆盖主要组织诉求；标签是另一量级的组织系统，待置顶验证使用率后再议）。
- 不做会话内全文搜索框（全局搜索已覆盖；P3 可顺手让 Ctrl+K 打开时预填当前会话过滤——若实施代价小）。
- 不做跨用户 / 会话移交（已否决，2026-10-25）。
- 不做收藏的两层语义 UI（见开放问题 1，P1 不接 favorite）。
- 不动移动端布局（安卓壳约束不变）。

## 3. 与已否决 / 已排除方向的边界

| 方向 | 本提案为何不是它 |
|---|---|
| 会话移交（2026-10-25 否决） | 那是「人 → 人」的资产交接；本提案是单人对自己会话的组织与回访，不新增任何权限面。 |
| 任务模板 / Runbook（2026-10-19 否决） | 不沾边，本提案不生产新资产。 |
| 运行轨迹深钻（已实施） | 轨迹面向「执行调试」；轮次目录面向「内容回访」，数据源不同（轨迹读 llm_call / 工具，目录读消息轮次），不重复建设。 |

## 4. 技术方案

### 4.1 置顶（P1）

- 列表行右键菜单与 hover 操作区加「置顶 / 取消置顶」→ 调既有 `PUT /v1/sessions/:id/pin` → 本地按服务端返回刷新列表（排序由服务端 SQL 保证）。
- 置顶会话视觉：行首钉子图标 + 微弱底色；不单独分组（遵循服务端 `活跃 > 置顶 > 时间` 的现有次序——运行中的会话仍排在置顶之上，符合「正在干活的事优先」的产品直觉）。
- 聚焦模式（活跃平铺）与标准模式（分组）都要能看到置顶态；聚焦模式按 `is_pinned` 提前插入。

### 4.2 列表过滤（P1）

- TaskIndexPanel 顶部加过滤输入框（折叠为图标，点击展开），输入经防抖调既有 `GET /v1/sessions?keyword=`，结果沿用现有分组渲染；清空即还原。
- 与分页「展开更多」的组合：keyword 由服务端过滤，分页口径不变。
- 归档区不参与过滤（归档本身有「恢复」入口，保持简单）。

### 4.3 批量归档（P2）

- 列表头部进入「选择模式」→ 行复选框 → 底部操作条「归档 N 个」→ 二次确认 → 前端循环调用既有归档端点（量级小，不新增批量端点；若实测 >50 条卡顿再议批量 API）。
- 完成后列表局部刷新；被归档会话的运行态排除（RUNNING 会话不可批量归档，与单条语义一致）。

### 4.4 长会话导航（P3）

- **轮次目录**：ChatRoundList 已按轮分组渲染，目录数据直接派生（每轮首条 USER 消息文本截断 + 相对时间），右侧浮动小抽屉（或从检查器边缘滑出），点击 → 复用 `locateMessageId` 整页替换 + 闪烁定位，目标轮自动展开。
- 目录懒构建：仅记录轮次锚点（已有 round 数据结构），不为目录单独扫全文；几百轮会话目录本身是轻量列表（虚拟滚动按需）。
- **只看回复**：聊天头部开关，纯展示层过滤（隐藏 TOOL / 思考 / 系统注入行，保留 USER + ASSISTANT 主干）；关闭即还原，不触碰数据加载。
- **回到顶部**：与既有「回到最新」条对称，锚定历史后同时提供两个方向。

## 6. 风险与开放问题

| 问题 | 风险 | 推荐默认 |
|---|---|---|
| 置顶与既有排序的次序预期 | 低 | 维持服务端 SQL 语义（活跃 > 置顶 > 时间），只加 UI，不改排序；验收时与产品确认一次 |
| keyword 过滤与红点 / 分组的交互 | 低 | 过滤只是查询参数，分组逻辑不动；红点按既有口径渲染 |
| 批量归档误操作 | 中 | 二次确认 + 已归档区可恢复（既有机制），操作条显示数量 |
| 轮次目录在超长会话的表现 | 中 | 目录只存锚点与摘要文本；虚拟滚动；定位复用 aroundMessageId 取页机制 |
| 「只看回复」与滚动跟随打架 | 低 | 开启时暂停智能跟随（沿用现有手势识别逻辑），关闭后恢复 |

**待确认决策**

1. favorite 的归宿：接 UI（与置顶成两层）还是收敛（后端保留、前端永不做）？建议 P1 不接，观察置顶使用率后再定；若团队认为两层概念冗余，明确「不做」并从 VO 文档标注，避免永远悬着。
2. 轮次目录入口形态：右侧浮动把手（常驻小箭头）vs 检查器工具栏按钮——建议浮动把手（回访动作高频，一键直达）。
3. 「只看回复」是否保留工具轮折叠行（「已执行 N 个步骤」）？建议保留（占位小，保留时间感）。

## 7. 测试要点

- 置顶：toggle 后组内次序（活跃 / 置顶 / 时间三段）、刷新持久、聚焦与标准双模式、LOCAL / 云端 / IM 渠道分组均生效。
- 过滤：keyword 命中与空态、防抖、与「展开更多」分页组合、切换 Agent 后过滤保留语义。
- 批量：含 RUNNING 会话的选择被禁用；确认后全部进入已归档区且可恢复；中途失败的部分完成态提示。
- 导航：轮次目录定位（复用 locateMessageId 测试口径）+ 深分页会话（目标轮不在缓存时 aroundMessageId 取页）+ 定位后该轮自动展开；只看回复开关与流式新消息、跟随底部、回到最新的组合行为。

## 8. 验收标准

1. 会话列表：可置顶、可按标题即输即筛、可批量归档恢复——三个动作全部 2 次点击内完成。
2. 长会话（>200 条消息）：打开轮次目录 3 秒内定位到任意一轮；开启「只看回复」后屏幕上只剩对话主干。
3. 后端零改动（评审可核）：全部能力由既有端点承载。
4. 既有列表性能（分组 / 分页 / 红点）回归无退化。
