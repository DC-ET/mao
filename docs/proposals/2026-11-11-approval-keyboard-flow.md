# 提案：审批键盘流 —— 桌面审批卡片的 Y/N 快捷键与焦点序

> 工具审批是「打断心流」的时刻：Agent 停下来等用户裁决，用户要做的只有两件事——看一眼内容、按一个键。但今天的桌面审批卡片（`ApprovalStack.vue`）**没有任何键盘交互**（grep `keydown` 零命中）：允许 / 拒绝只能鼠标点击按钮，焦顺序是浏览器自然 Tab 序（穿过全部工具卡与正文）。批次 25 做了命令面板与 `isTypingTarget` 守卫、0.0.471 做了焦点可见体系——键盘基建都在，唯独系统最高价值的按键时刻（审批）没有键盘流。本提案给桌面审批卡片加 **Y / N 快捷键 + 显式焦点管理**，审批语义（升级链路 / 规则 / 多端广播）零改动。

- 状态：已落地（2026-11-11，批次 29，0.0.520）
- 日期：2026-11-11
- 提案总览见 [docs/proposals/README.md](README.md)
- 规模：小（约 1 人日；**零后端、零迁移**，纯 desktop 前端交互层）
- 关联：`desktop/src/components/chat/ApprovalStack.vue`（审批卡片，现无键盘处理）、`desktop/src/components/chat/ExecutionErrorBanner.vue`、`desktop/src/components/chat/ChatPanel.vue`（挂载点）、`desktop/src/utils/terminal-ime-guard.ts` / `TopNav.vue` 的 `isTypingTarget` 守卫惯例

## 2. 目标 / 非目标

**目标**

1. **P1 Y/N 快捷键**：桌面主会话存在待审批卡片时，`Y` = 允许、`N` = 拒绝（等价于点击对应按钮，走完全相同的回调）；`isTypingTarget` 守卫（输入框 / 终端 / 对话框内聚焦时不触发）+ `e.repeat` 防连按。
2. **P1 显式焦点序**：待审批卡片出现时，第一个待审批按钮进入 Tab 焦点序（不抢焦点、不自动 focus——避免打字中被抢）；卡片获得焦点时按钮有 `focus-visible` 轮廓（0.0.471 同款）。
3. **P1 可发现性**：按钮 `title` 补「快捷键 Y / N」提示；快捷键速查表（批次 25）+1 条。
4. **P1 边路任务同流**：边路任务的审批卡片同样生效（焦点判定按「当前活跃 Tab」归属，避免跨 Tab 误批——与中心 Tab 活跃态判定同源）。
5. 安卓壳：无硬件键盘不触发快捷键（守卫天然覆盖），按钮点击行为不变。

**非目标**

- 不改审批的任何语义：允许 / 拒绝回调、升级链路（飞书卡片）、审批规则、多端广播零改动——快捷键只是按钮点击的另一个触发器。
- 不做跨任务审批收口（批次 21 已否决）、不做审批历史 UI。
- 不做 `A`（总是允许）快捷键：「总是允许」是带副作用的规则写入，不适合单键误触——保持点选。
- 不做移动端长按手势（安卓布局不做重构）。
- 零后端、零迁移。

## 4. 方案设计

- **键位注册**：ChatPanel 层文档级 `keydown`（与 TopNav 命令面板同款模式），守卫链：`isTypingTarget(e.target)` → 不触发；活跃 Tab 归属判定（主会话 / 边路中心 Tab，复用中心 Tab 活跃态）→ 只响应归属 Tab 的待审批；多卡片并存时只响应**栈顶（最新）**一张。
- **Y/N 触发**：直接调用审批卡片按钮的既有回调（props 下传的 approve/deny 函数），不模拟 DOM click；触发后卡片随既有流程消失（回调驱动）。
- **焦点序**：待审批按钮组加 `tabindex` 显式序（卡片内容之后、按钮组最先），`focus-visible` 样式沿用 0.0.471 令牌；不做自动 focus（防打字抢占），用户 Tab 一次即达。
- **速查表**：批次 25 速查表常量 +1 条「Y/N 审批（待审批卡片出现时）」；与命令面板速查组（批次 29 提案三）共用同一常量源。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| **误批风险（Y 键按下时卡片内容未看清）** | ①不做自动焦点（用户必须在看）；②`e.repeat` 防连按；③仅栈顶一张响应；④typing 守卫挡住输入场景；⑤速查表明示。误批兜底仍是既有撤销面（审批规则可关） |
| Y/N 与浏览器 / IME 冲突 | `isTypingTarget` + 面板内输入框聚焦判定；Y/N 在非输入场景无浏览器默认绑定 |
| 跨 Tab 误批（边路任务后台等待时在主会话按 Y） | 活跃 Tab 归属判定：只响应「当前可见 Tab」的审批；后台 Tab 的审批仍走鼠标 / 多端升级 |
| 键盘流与多端升级竞态 | 快捷键走与按钮点击完全相同的回调（同一把锁），无新增竞态面 |
| 焦点序改动影响既有 Tab 流 | 仅在待审批卡片存在时插入 tabindex；卡片消失后焦点序自动恢复 |

## 7. 测试要点

1. 待审批卡片出现 → `Y` 允许（回调收到与按钮点击相同的参数）、`N` 拒绝；卡片随之消失；连续两次审批各自生效。
2. 输入框聚焦时 `Y`/`N` 不触发（`isTypingTarget`）；长按 `Y`（`e.repeat`）只触发一次。
3. 主会话与边路任务各有待审批卡片时，仅活跃 Tab 的栈顶卡片响应；后台 Tab 不响应。
4. `A`（总是允许）无快捷键；按钮 title 含快捷键提示；速查表 8 条含新条目。
5. 回归：审批回调、升级链路（飞书卡片）、审批规则、多端广播全部零变化（既有审批测试全绿）；审批语义源码级断言（快捷键路径与按钮路径调用同一函数）。
6. 安卓壳：无键盘不触发；点击路径不变。

## 8. 决策记录

已拍板（2026-11-11，评审确认）：

1. **键位选择**：**`Y` / `N`**——Y=允许、N=拒绝，直觉与惯例；否决 `Enter`/`Esc` 备选（Esc 与关闭面板冲突）。
2. **焦点序是否自动聚焦**：**不自动**——卡片出现时不抢焦点，Tab 一次可达，防打字抢占与误批。
3. **`A`（总是允许）快捷键**：**不做**——规则写入有副作用，不适合单键误触，保持鼠标点选。
