# 提案：运行轨迹深钻二阶段 —— 轨迹内搜索与拖选聚焦

> 批次 10 的「运行轨迹深度下钻」已落地 P1（0.0.336 / 0.0.337）：run 内时间概览条带（`RunTraceTimeBand.vue`）、色条点击定位（展开 → 滚动 → 1.2s 高亮，`RunTracePanel.vue:570-576`）、记录详情抽屉、解码/吞吐/provider 展示都在了。台账明确留了尾巴：**「轨迹内搜索、拖选聚焦未做，继续做须重新立项」**（README 已落地表，批次 10 行）——本提案就是按这条规则把 P2 余项重新立项。今天的体验断点：
> 1. **搜不到**：轨迹工具栏只有慢/贵两个阈值输入（`RunTracePanel.vue:8-30`）。几十轮的长 run 里找一个 `grep` 调用、定位某条报错、确认「这轮到底调没调过某工具」，只能肉眼扫行 + 翻页。全局消息搜索（Cmd+K）搜的是聊天正文，进不了轨迹视图的行粒度。
> 2. **时间段不可聚焦**：条带色条只能单点点击定位。并行工具色条互相重叠时，「这 30 秒里到底发生了什么、谁在等谁」回答不了——没法框选一段时间让记录表只显示区间内活跃的行。这正是原提案 §2 目标 1 预留的 P2 形态（参照 deepseek-harness Trajectory 的横向拖选）。

- 状态：已否决（2026-11-07：轨迹使用频率低，暂无需求。见 [README](README.md) 台账）
- 日期：2026-11-07
- 提案总览见 [docs/proposals/README.md](README.md)
- 前序：[2026-10-22-run-trace-deep-dive.md](2026-10-22-run-trace-deep-dive.md)（已落地 P1；本提案承接其 §3.4 搜索与 §2 目标 1 的拖选聚焦余项）
- 规模：小-中（搜索约 1 人日 + 拖选聚焦约 1.5-2 人日；**零数据库迁移、零后端改动**——搜索定位在「已加载页过滤」，P1 已定此口径）
- 关联：`desktop/src/components/center/{RunTracePanel,RunTraceTimeBand}.vue`、`desktop/src/utils/trace-display.ts`、`desktop/src/composables/useCenterTabs.ts`

## 1. 背景与现状

### 1.1 已落地的基础（P1 验收口径）

| 能力 | 现状 | 代码证据 |
|---|---|---|

| 点击定位闭环 | 展开 run → `locateNode` 滚动 → 行高亮 1.2s；行锚点 key 与条带节点同源（曾因此修过定位 bug，口径已固化） | `RunTracePanel.vue:518-526,541-546,570-576,1210` |

### 1.2 为什么现在做是低风险的

- **纯前端过滤 + 既有定位设施**：搜索是对已加载记录的内存过滤，命中跳转直接复用 P1 的 `locateNode` / 高亮机制（那个机制刚修过跨段定位 bug 并固化了 key 口径，`RunTracePanel.vue:518-526` 注释明确「行 :key 直接用条带 key」）；拖选聚焦是对条带 SVG 的一次交互增强，数据源（`startedAtMs`/`durationMs`）P1 已备齐。
- **台账留名**：这两项是批次 10 立项时划入 P2 的既定范围，不是新发明的需求；README 规则明文「余项未做的，继续做须重新写一篇提案放回待评审」。

## 2. 目标 / 非目标

**目标**

1. **P1 轨迹内搜索**：工具栏（阈值输入旁）加搜索框；对当前已加载 run 页的记录过滤 + 命中高亮 + 「上一个 / 下一个」跳转。
   - 匹配字段：用户消息预览、工具名、目标（target）、错误信息、模型名；大小写不敏感；空关键词恢复全量。
   - 与翻页状态联动：翻页后重建匹配集（沿用原提案 §3.4 口径——**不做服务端全会话轨迹搜索**）。
   - 跳转复用既有展开/滚动/高亮逻辑；无匹配时显示空态计数「0/N 命中」。
2. **P2 拖选聚焦**：`RunTraceTimeBand` 支持横向拖选时间区间——mousedown 拖动画选区遮罩，mouseup 得 `[t0, t1]`；释放后记录表过滤为「区间内活跃」（`startedAtMs`/`durationMs` 与区间相交）的行，条带高亮所选区间并显示「聚焦 xx 秒 · N 条记录 · 清除」提示条。
   - 拖选与单击定位互斥：位移超过阈值（如 4px）判为拖选，否则视为单击定位（保持既有行为）。
   - 聚焦状态在 run 收起/翻页时自动清除，不做跨 run 持久化。
3. **P2（可选，独立验收）条带缩放**：聚焦状态下滚轮缩放时间轴。列为可选——原提案将其列为 P2 可选项，交互成本高，若评审认为过度设计可直接砍掉，不影响 1、2。

**非目标**

- 不做服务端全会话轨迹搜索（消息正文检索已有全局搜索覆盖；轨迹搜索定位「已加载页快速过滤」，原提案既定边界）。
- 不做右键平移、全局固定条带、虚拟化（原提案开放问题，等长 run 卡顿再评估）。
- 不改 `startedAtMs` 估算口径、不改导出结构、不动 P1 的任何已上线行为。
- **不做「请求构成记录」**（提示词版本/工具目录埋点）：原提案 §3.6 明确单独评审，本提案不吸收。
- 零后端、零迁移。

## 4. 方案设计

### 4.1 搜索（P1）

- 状态：`traceSearchKeyword` 存于 RunTracePanel 本地（不进 store、不进 URL——轨迹 Tab 状态已有 per-session 持久化机制，关键词是否纳入由实施时按 `useCenterTabs` 既有 state 结构决定，倾向不持久化）。
- 过滤层：在渲染列表的 computed 上游套一层 `matchTraceRows(rows, keyword)`，命中行集合同时驱动「上一个/下一个」的游标；命中词在行内 `<mark>` 高亮（仅预览文本列）。
- 计数与空态：工具栏搜索框右侧显示「N 命中」；0 命中显示空态文案，列表区域不清空（避免误以为数据丢了），改为行集半透明 + 空态浮层。

### 4.2 拖选聚焦（P2）

- `RunTraceTimeBand.vue`：SVG 上叠交互层，`pointerdown` 记起点、`pointermove` 画选区矩形、`pointerup` 落区间；`setPointerCapture` 防止拖出条带丢事件。
- 聚焦过滤：与搜索共用过滤层（两者叠加时取交集）；聚焦区间以 `run 时间域` 反算为记录维度条件（相交判定），tooltip 仍标注起点为估算值。
- 清除路径：提示条「清除」按钮、Esc、切 run、翻页四处均可退出聚焦态。

### 4.3 与导出的关系

- 聚焦/过滤状态**不改变**导出内容：导出仍导出完整 run 数据（P1 口径「导出结构语义不变」）；提示条注明「仅影响视图，不影响导出」。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 过滤层破坏 P1 修好的行锚点定位（跨段 key 口径） | 过滤只影响「渲染哪些行」，不重排 key；`locateNode` 对被过滤掉的行静默返回（与既有「行不存在静默返回」同口径，`RunTracePanel.vue:576` 注释）；单测覆盖过滤态下定位不串行。 |
| 拖选与单击、与悬停 tooltip 手势冲突 | 位移阈值判型 + `setPointerCapture`；拖选中禁用 tooltip；判定逻辑抽纯函数单测。 |
| 估算起点导致聚焦区间边界误差 | 与 P1 同口径：tooltip 标注「估算」；相交判定放宽半个节（可选），或维持精确相交并接受秒级误差——实施时按实测观感定，不回填数据。 |
| 搜索 + 聚焦叠加态组合爆炸 | 单一过滤管线（关键词 × 区间两维与运算），状态机两个布尔位，穷举 4 种组合写用例。 |
| 长 run 下过滤计算量 | 已加载页规模有限（分页 + 50 条/页量级），纯内存过滤无压力；不引入虚拟化（非目标）。 |
| 工具栏拥挤 | 搜索框放阈值输入右侧既有空间（原提案 §3.4 判断「已有空间」）；必要时阈值输入收进下拉，实施时按视觉定，不改交互语义。 |

## 7. 测试要点

1. 搜索：命中高亮、大小写不敏感、0 命中空态、清空恢复全量；「上一个/下一个」循环跳转且每跳命中行展开 + 滚动 + 高亮。
2. 搜索 × 翻页：翻页后匹配集重建，游标复位不越界。
3. 拖选：拖选区间后记录表只剩相交行、提示条计数正确；清除按钮 / Esc / 切 run / 翻页四种路径均退出聚焦。
4. 拖选 × 单击：位移 < 4px 视为单击定位（P1 行为回归）；拖选中 tooltip 不出现。
5. 叠加态：关键词 + 区间同时生效取交集；4 种组合逐一断言。
6. 导出回归：聚焦/过滤态下导出 JSON/CSV 内容与不过滤时完全一致。
7. P1 回归：阈值标记（慢/贵）、条带点击定位、详情抽屉、编辑前分段、未挂到轮行为全部不变（复用既有 `run-trace-*.test.ts` 套件）。
