# 提案：首次成功体验 —— 自托管的流失发生在第一个 10 分钟，不是功能不够多

> 一个自托管产品的真实漏斗：装起来 → 打开网页 → 默认密码没改 / 模型 Key 没配 / 不知道该让 Agent 干什么 → 关掉，再也没回来。功能已经 340 多个版本了，「第一次跑通一个任务」这件事却没人管。

- 状态：方向已认可（2026-10-25），已细化技术方案待评审：[docs/plan/2026-10-25-first-run-onboarding-technical-design.md](../plan/2026-10-25-first-run-onboarding-technical-design.md)
- 日期：2026-10-25
- 提案总览：见 [docs/proposals/README.md](README.md)
- 规模：小~中（检测服务 + 向导组件 + 种子内容；零核心链路改动）
- 关联：`auth`（首登判定）、`model` / `agent`（就绪检测）、`preference`（向导完成标记）、`settings`（系统状态）、README / DEPLOY（部署后路径）

## 1. 背景与现状

### 1.1 激活断点没有任何机制兜底

现状事实（代码可查）：

- **管理员首登**：无任何就绪检测。默认密码 `admin/admin123` 未改没有提醒（只在文档里写了「立刻改密」）；模型 Key 没配、一个 Agent 都没有，界面照常呈现——用户第一次发消息才在报错里发现模型不可用。
- **普通用户首登**：无引导。直接落进会话列表，空状态只有一句话；Agent 是什么、CLOUD / LOCAL 选哪个、工作区干嘛的，全靠读文档。
- **无示例内容**：没有任何预置的「跑一遍就能看懂」的示例任务或入门 Agent。

对比同类开源自托管产品的通行做法（就绪检查清单 + 交互式首启向导 + 示例内容），Mao 在「装好之后的前 10 分钟」是完全裸奔的。**这不是 polish，是漏斗上最大的洞**：README 定位「适合需要私有化的个人与团队」，这类用户 evaluating 阶段的放弃，功能再多也看不见。

### 1.2 三个断点各自的死法

| 断点 | 用户的实际体验 |
|---|---|
| 管理员没配模型 Key | 发消息 → 模型报错 → 以为是产品坏了，不知道要去 admin 配 Key |
| 普通用户第一次见工作台 | 一排概念（Agent / 会话 / 工作区 / CLOUD / LOCAL）没有任何解释，不敢点 |
| 不知道能干什么 | 文档里特性列表很长，但没有一个「90 秒看到 Agent 真的在干活」的路径 |

### 1.3 一个真实场景

运维按 DEPLOY.md 把服务起了，登录 admin，改了密码（记得的话），配模型那步被「去模型管理 → 添加 → 填 OpenAI 兼容地址和 Key」劝退——因为界面上没有任何信号告诉他「不配这个后面全不能用」。第二天他跟同事说「装了下那个 Mao，感觉没啥」。

同样的部署，若有就绪清单：登录 admin 首屏就是三步卡——①改默认密码（红牌）②配一个模型 Key（带直跳）③建一个 Agent（可一键用「入门助手」模板）——三步全绿后提示「去工作台跑第一个任务」。用户 10 分钟内看到 Agent 调工具干活，留存是完全不同的结果。

## 2. 目标 / 非目标

**目标**

1. **管理员就绪清单**：admin 首页（或首登全屏）呈现三步就绪卡：改默认密码（未改则红牌常驻）→ 至少一个可用模型 → 至少一个启用 Agent；全绿前每张卡可直跳对应页面；全绿后收起。
2. **用户首启向导**：普通用户首次登录工作台时三步引导：①挑一个 Agent（一句话介绍 + 推荐问题预览）②理解执行边界（CLOUD / LOCAL 一屏图解，默认 CLOUD）③发第一条消息（预填一条示例指令，可改可发）。
3. **入门 Agent 模板**：admin 建 Agent 时可选「从入门模板创建」——内置 1~2 个模板（如「信息助理」：联网搜索 + 引用溯源 + 推荐问题），一键填充提示词与技能引用，可改。
4. **90 秒示例任务**：向导第三步提供一条内置示例指令（走联网工具、无需工作区配置，如「搜一下本周 AI 领域的重要新闻，给我 5 条带来源的摘要」），让用户第一次就看到「工具调用 + 引用上标」的产品核心差异点。
5. **空状态分级**：会话列表 / Agent 选择器的空状态按根因分流——模型未配（提示找管理员）≠ 无可用 Agent ≠ 纯新用户（给向导入口）。
6. 完成标记存 `preference`，一次性体验不做重进入口（2026-10-25 评审确认）；不打扰老用户（存量用户不弹）。

**非目标**

- 不做交互式产品教程 / 视频托管（向导三步止）。
- 不做多语言向导（界面 i18n 在贡献边界外，向导跟随现有中文界面）。
- 不做匿名 demo 站 / 官方 SaaS 试用（README 边界）。
- 不改部署流程本身（DEPLOY.md / install.md 照旧，向导只是把文档里的「上线检查」搬进产品）。
- 不做强制流程（全部可跳过；仅默认密码红牌在改密前常驻，因为它同时也是安全项）。

## 3. 与已否决 / 已排除方向的边界

| 方向 | 本提案为何不是它 |
|---|---|
| 各已否决功能方向 | 不碰执行 / 治理 / 知识任何链路；纯「既有能力的首达体验」 |
| 界面国际化（README 排除） | 向导即中文，与现有界面一致 |
| 官方 SaaS / 托管（README 排除） | 内容全部本机内置（模板随版本分发，等同文档资产），无外部依赖 |
| business_process.md 上线清单（已存在） | 那是给人看的文档；本提案把其中机器可判定的部分（密码 / 模型 / Agent）做成产品内检测，两者互为引用不重复维护——就绪判定逻辑单一来源，文档链接进向导 |

## 4. 技术方案

### 4.1 就绪检测（后端一个只读端点）

`GET /v1/readiness`（登录即可调用，管理员语义）聚合返回：

```json
{
  "defaultPasswordChanged": false,
  "modelsConfigured": 0,
  "agentsEnabled": 1,
  "onboardingSeen": false
}
```

- `defaultPasswordChanged`：比对 admin 账号密码 hash 与默认值（种子迁移里的已知 hash，成本低）；仅在 admin 上下文返回。
- 前端轮询或进入时拉取；红牌项在顶栏常驻角标直到解决。

### 4.2 入门 Agent 模板

- 模板作为代码内常量（`backend-ts/src/agent/agent-templates.ts`）：名称、提示词、技能引用（仅引用既有内置技能如联网搜索，不依赖外部安装）、推荐问题。
- admin 建 Agent 页加「从模板开始」；创建后即为普通 Agent，模板不留运行时痕迹。
- 模板随版本演进，算文档级资产（无需迁移）。

### 4.3 用户首启向导（desktop）

- 判定：登录用户 `preference` 无 `onboarding.completedAt` 且实例 `readiness` 全绿（不全绿时向导降级为「等待管理员配置」提示页，避免新用户在坏环境里瞎试）。
- 三步组件：`views/onboarding/OnboardingWizard.vue`（步骤条 + Agent 卡片选择 + 边界图解 + 示例指令输入框），最后一步「发送」直接复用现有新建会话链路。
- 完成写 `preference`；「跳过」同样写标记。
- 会话列表空状态：根因分流数据同样来自 `readiness` + Agent 列表接口。

### 4.4 admin 首页

- admin 现有首页（仪表盘）顶部插入就绪清单卡组（三步卡 + 进度），全绿自动折叠为一行「环境就绪」。

## 5. 分阶段实施

| 阶段 | 内容 | 预估 |
|---|---|---|
| P1 | readiness 端点 + admin 就绪清单（默认密码红牌 / 模型 / Agent 直跳）+ 用户三步向导 + 完成标记 + 空状态分流 | 5-6 人日 |
| P2 | 入门 Agent 模板 + 示例指令内置 | 2-3 人日 |
| P3 | 向导步骤数据化（模板 / 文案后台可配，供团队实例定制内部新员工引导） | 2-3 人日 |

**改动面（P1+P2）**

| 层 | 文件 / 模块 | 改动 |
|---|---|---|
| 后端 | `GET /v1/readiness`（auth 或 settings 域）+ `agent-templates.ts` | 新增（只读） |
| desktop | `views/onboarding/` 向导 + 空状态分流 | 中（主要工作量） |
| admin | 首页就绪卡组 + 建 Agent「从模板开始」 | 小~中 |
| 迁移 | 零迁移（preference 复用既有表；模板是代码常量） | 无 |

## 6. 风险与开放问题

| 问题 | 风险 | 推荐默认 |
|---|---|---|
| 向导打扰存量用户 | 中 | 只对无完成标记的账号出现；上线时给全部存量账号静默写入标记（迁移外的一次性回填，或首次拉取时判定「已有会话历史即视为完成」——推荐后者，零迁移） |
| 示例指令依赖联网工具与模型质量 | 中 | 示例选最稳的路径（web 搜索）；失败时向导文案兜底「任务失败也是正常体验，可在轨迹里看原因」——顺带教育轨迹功能 |
| 默认密码 hash 比对失效（种子密码将来变化） | 低 | 判定逻辑与种子迁移同源常量，加一条联动测试 |
| admin 首页布局改动冲突 | 低 | 卡组为顶部插入式组件，不重排既有面板 |
| 模板内容过时 | 低 | 模板极薄（提示词 + 既有技能引用），随版本维护，等同文档 |

**待确认决策**

1. 向导对「LDAP / 飞书登录」用户是否同样适用？建议适用（判定只看 preference，与登录方式无关）。
2. 示例指令是否按 Agent 推荐问题动态化（用所选 Agent 的第一条推荐问题）？建议优先推荐问题、无则回退内置示例。
3. 默认密码红牌是否允许管理员关闭？建议不允许（安全项）；若实例确有内网隔离诉求，环境变量级开关，不入界面。

## 7. 测试要点

- readiness：三态各组合的返回正确性；admin 上下文才含密码项；默认密码改动后红牌消除。
- 向导：无标记弹、有标记不弹、「已有会话历史视为完成」的存量判定；跳过与完成都写标记；环境未就绪时的降级提示页。
- 模板：一键创建后为普通 Agent（可改可删，与手建无差异）；模板只引用既有内置技能。
- 空状态分流：模型未配 / 无 Agent / 纯新用户三种根因各自呈现正确引导。
- 回归：admin 首页既有面板、新建会话链路、preference 读写零影响。

## 8. 验收标准与观察指标

**验收**

1. 全新部署：admin 首登看到三步就绪卡，按卡直跳完成改密 / 配模型 / 建模板 Agent，全绿收起。
2. 新用户首登走完三步向导，发出第一条示例任务并看到带引用上标的回复；再次登录不再出现向导。
3. 存量实例升级后，老用户无任何打扰。
4. 模型未配环境下的新用户看到「等待管理员配置」提示而非报错对话。

**指标（上线后 8 周）**

- 实例就绪率：部署后 72h 内完成「改密 + 配模型 + 建 Agent」的比例（readiness 端点匿名聚合计数，随每日摘要已有链路上报？——不新增遥测，仅 admin 本地可见，避免隐私争议；上线后用人工抽样或社区反馈评估）；
- 新用户首任务完成率（首次登录 → 7 天内发出至少一条消息）；
- 社区反馈中「装完不知道怎么用」类 issue 的数量变化。
