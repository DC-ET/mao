# 提案：每日运营摘要（Daily Digest）—— 无人值守自动化的"每天一眼"

- 状态：**已确认**（2026-10-12 评审通过，技术方案见 [../plan/2026-10-12-daily-digest-technical-design.md](../plan/2026-10-12-daily-digest-technical-design.md)，决策记录 11 条于 2026-10-12 逐条确认）
- 日期：2026-10-12
- 提案总览：见 `docs/proposals/README.md`

## 1. 背景与现状

这个项目的自动化设施已经铺得很全：定时任务（含失败重试、停机补偿、连续失败自动暂停）、信号哨兵（变化触发）、入站 Webhook、开放 API、出站事件订阅。问题也随之转移——**事件越来越多，但没有一个"汇总视角"**：

1. **通知是点状的，没有线的**。收件箱里躺着昨天的 3 条任务完成、1 条审批待办、1 条哨兵停用；要弄清"昨天我的自动化 overall 怎么样"，得逐条点开。用户实际的动作变成：根本不看，直到某天发现哨兵停了一周。
2. **出站订阅是事件粒度，没有日报粒度**。出站事件订阅（`outbound-subscription`）推的是"任务完成 / 失败"单事件。想接自己的 BI / 群机器人做日报的团队，得自己在接收端聚合——而接收端聚合恰恰是最容易烂尾的代码。
3. **失败会自己说话，成功不会**。连续失败自动暂停会发通知（这条链路已通），但"昨天 12 次定时任务全成功、花了 3.4 元"这种健康信号没有任何渠道触达用户。运维视角里，**没有消息本身就是坏消息**——你无法区分"一切正常"和"根本没跑"。

相邻方向的边界：

- **不是监控告警**（哨兵已明确不做的那类）：摘要不判阈值、不报警，只做事实汇总；异常事件仍走各自的实时通知链路。
- **不是出站事件订阅**（已实施）：订阅是"事件发生时即推"，摘要是"按天汇总后推一次"，粒度相反，复用同一条投递管道。
- **不是用量分析页**（已实施）：那是给人主动去看的仪表盘；摘要是主动送到眼前（收件箱 / 端点 / IM）的被动视图，数据源共用。
- **不是数据保留 / 可携带**（已否决）：摘要只推当天汇总数字，不导出原始数据。

## 2. 目标 / 非目标

**目标**

1. **每日一封**：按用户维度汇总 Asia/Shanghai 上一个自然日（00:00:00 ~ 次日 00:00:00，半开区间，对齐用量统计既有口径）的运营事实，于每日可配置时间（默认 08:30）生成。
2. **汇总内容**（全部来自既有表，零新事实源）：
   - 任务：完成数 / 失败数（失败列出 Top 3 及原因摘要，可跳转会话）；
   - 定时任务：执行次数、成功 / 失败、被自动暂停的任务（如有）；
   - 信号哨兵：触发次数、停用告警（如有）；
   - 审批：待办仍挂起的数量（提醒有活没批）；
   - 成本：当日总成本、Top 3 Agent 花费（对齐 `cost_micros` 口径）；
   - 开放接口：入站调用次数 / 拒绝次数（如有配 Token / Webhook）。
3. **三路投递**（全部复用既有设施）：
   - 站内收件箱新 kind `DAILY_DIGEST`（一条消息，正文为渲染好的摘要）；
   - 出站订阅新增事件类型 `digest.daily`（复用 HMAC 签名 + 退避重试管道，团队可接自己的群机器人 / BI）；
   - P3：完成通知既有链路推送 IM（飞书 / 钉钉 / 微信，对齐任务完成通知的投递方式）。
4. **零事实迁移**：不新建任何事实表；用户偏好（开关 + 推送时间 + 投递渠道）落 `preference` 域（既有 JSON 偏好存储），仅需在迁移台账里挂一个偏好键注册。**安静日不打扰**：当天无任何事件（无会话、无任务、无调用）的用户不生成、不推送。

**非目标**

- 不做周报 / 月报（同一设施的时间粒度变体，P1 只做日报；周报等日报稳定跑一个月后再评估）。
- 不做自定义看板 / 指标勾选（自定义看板在路线图里一直是 P2 且从未启动，摘要只给固定事实集）。
- 不做邮件渠道（项目无 SMTP 设施，邮件是新的基础设施方向，超出"建立在既有设施上"的前提）。
- 不給管理员做全站日报（多租户汇总的责任与隐私边界另需设计；P1 只做"我的日报"）。

## 3. 技术方案

### 3.1 调度器（`usage` 或新 `digest` 域）

新增 `digest/digest-scheduler.ts`，结构对齐既有 `InboxCleanupScheduler` / `OutboundDeliveryScheduler`（start/stop + interval，进程内单飞）：

- 每分钟扫一次：当前时间 ≥ 某用户配置的推送时间 且 今日未生成 → 进入该用户的生成队列（内存队列 + 数据库 `preference` 里的 `last_digest_date` 防重，重启不重复发）。
- 生成窗口固定为**上一个自然日**（与"今天 08:30 发昨天"的语义一致，避免"当天边发生边汇总"的半成品）。
- 聚合查询全部走既有索引（`created_at` 范围 + 用户 id）；`llm_call` / `inbox_item` / `scheduled_task_run` / `signal_watcher_check` / `api_call_log` 六张表各一条聚合 SQL，单用户规模（几十条量级）无性能顾虑。

### 3.2 渲染与存储

- 摘要渲染为 Markdown 文本（收件箱消息正文直接存；出站 payload 用同一份文本 + 结构化字段双格式，对齐出站订阅既有 payload 约定）。
- 不落事实表：生成的摘要文本只进收件箱消息行；防重状态在 `preference.last_digest_date`。

### 3.3 投递复用

- **收件箱**：新 kind `DAILY_DIGEST`——按规范同步 `backend-ts/src/inbox/types.ts` 白名单、`@mao/contracts` 的 `InboxKind` 联合、桌面抽屉图标与通知偏好（对齐 `WATCHER_DISABLED` 的先例）；点击跳转「我的用量」页（当日数据即 Digest 同源）。
- **出站订阅**：事件类型集合加 `digest.daily`（`outbound-subscription.service.ts` 的事件白名单 + HMAC 签名 + 失败退避原样复用）；订阅方按天收到一条。
- **P3 IM**：对齐任务完成通知的投递选择逻辑（用户通知偏好里已绑定的渠道），无新渠道代码。

### 3.4 偏好与开关

「设置 → 消息通知」新增「每日运营摘要」区：

- 总开关（默认开，但安静日不生成，首感无骚扰）；
- 推送时间（默认 08:30，可改）；
- 投递渠道勾选（站内收件箱默认开；出站端点需已有订阅时才可勾；IM 渠道 P3）；
- 摘要末尾常驻「调整摘要设置」入口。

## 4. 分阶段实施

| 阶段 | 内容 | 规模 |
|---|---|---|
| P1 | 调度器 + 六表聚合 + Markdown 渲染 + 收件箱 kind `DAILY_DIGEST` + 通知偏好设置 | 小~中 |
| P2 | 出站订阅事件 `digest.daily`（含签名 / 重试回归）+ 偏好防重与重启恢复 | 小 |
| P3 | IM 渠道投递 + 管理后台"摘要送达率"只读统计 | 小 |

## 5. 风险与开放问题

- **安静日判定漏判**："无事件"依赖六表聚合均为空——任何一张表漏查都会导致空摘要发出或安静日误发。缓解：聚合结果为空即跳过，判定逻辑单测覆盖六表组合；上线首周灰度到管理员账号观察。
- **时区口径**：汇总窗口必须 Asia/Shanghai 自然日 + 半开区间——0.0.276 刚修过"最后一秒丢数据"的同类坑， Digest 聚合直接复用修正后的区间口径，不得另写。
- **退避重复投递**：出站端点失败时既有退避重试会重推 digest—— digest 是低价值可丢消息，重试 2 次后放弃即可（对齐既有最大重试配置，不特殊调高）。
- **偏好缺失兼容**：`last_digest_date` 缺省视为未发送；老用户首次开启若昨天有事件，**不发补领摘要**（避免开户第一天被昨天的历史轰炸）。
- **开放问题**：摘要里"失败原因摘要"从哪来——建议取该失败任务最后一条错误消息前 80 字（不调 LLM 总结，零成本零幻觉）；若评审认为可读性差，P2 再评估 `scene=digest_summary` 的 LLM 起草模式（会引入用量成本，默认关）。
- **开放问题**：管理员是否需要"全站当日健康一屏"——不在本提案范围；管理后台已有运行统计页，可作独立小提案。

## 6. 测试要点

- 聚合：六表各自的当日数据正确计入；半开区间边界（23:59:59.500 的记录属于当天）；失败任务 Top 3 及原因摘录正确。
- 调度：到点生成、不到点不生成；同一天重复调度只发一次（含重启后）；推送时间修改后次日生效；安静日（六表全空）不生成不收件箱消息。
- 投递：收件箱 kind 白名单接受 `DAILY_DIGEST`、未知 kind 仍拒绝；出站 payload 签名可验、HMAC 头正确；端点失败退避后放弃、不无限重试。
- 偏好：开关关闭不生成；渠道勾选状态正确驱动投递分支；老用户首次开启不发补领。
- 前端：抽屉内 Digest 卡片图标与跳转；设置页开关 / 时间 / 渠道交互；通知偏好里 Digest 类型的独立开关不干扰其他类型。
- 回归：用量统计口径零变化；收件箱未读数与清理任务（`InboxCleanupScheduler` 保留期）对 Digest 消息同样生效。
