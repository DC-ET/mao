# 提案：命令面板动态组 —— Agent 目录、上下文动作与快捷键速查面板化

> 命令面板（批次 24，`Ctrl/Cmd+K`）今天的能力是 **28 条纯静态命令**（`useCommandRegistry.ts:83` `buildCommands(host)`：主题三档、设置导航、搜索、新建会话等），打开时一次性构建（`CommandPalette.vue:121`），不含任何动态数据源。两个真实缺口因此存在：①**「用某个 Agent 开新会话」没有键盘路径**——面板里只有一条笼统的「新建会话」，用户想用特定 Agent 起会话必须走 UI（AgentSelector 点选）；Agent 是系统的核心资产（多 Agent 并存是 0.0.473 之后的常态），它们却不在面板目录里。②**快捷键速查表藏在设置页**（批次 25 的 7 条速查），用键盘的人不知道还有什么键可用。本提案把面板升级为**带动态数据源的入口**：Agent 目录组（数据源 `useAgentStore` 现成）+ 当前会话上下文动作组 + `?` 查看全部快捷键。静态命令零改动。

- 状态：已落地（2026-11-11，批次 29，0.0.520）
- 日期：2026-11-11
- 提案总览见 [docs/proposals/README.md](README.md)
- 规模：小（约 1-1.5 人日；**零后端、零迁移**，纯 desktop 前端）
- 关联：`desktop/src/composables/useCommandRegistry.ts`（:83 `buildCommands`）、`desktop/src/components/palette/CommandPalette.vue`（:121 一次性构建）、`desktop/src/stores/agent.ts`（agents 目录）、`desktop/src/components/common/TopNav.vue`（`Ctrl/Cmd+K` 与 `isTypingTarget` 守卫）

## 1. 背景与现状

| 场景 | 现状 | 代码证据 |
|---|---|---|
| 面板命令来源 | 28 条静态，打开时一次构建，无动态数据源 | `useCommandRegistry.ts:83`、`CommandPalette.vue:121` |
| 按 Agent 新建会话 | 无键盘路径；须走 UI 的 AgentSelector | `buildCommands` 仅一条 `new-session` |
| Agent 数据源 | store 现成（列表 / 名称 / 头像） | `stores/agent.ts` |
| 快捷键速查 | 7 条静态表，藏于设置页 | 批次 25 文档口径 |
| 动态组扩展位 | `buildCommands(host)` 无可选参数；面板 activeIndex 逻辑与分组渲染现成 | `CommandPalette.vue` 分组渲染 |
| 输入守卫惯例 | `isTypingTarget` + `e.repeat`（0.0.476 落地） | `TopNav.vue` keydown 分支 |

与已否决项的边界：批次 25 否决的「最近会话快切」是**会话时序数据源**（MRU）——本提案不含会话数据源、不碰会话切换语义，动态组是 **Agent 资产目录**（横切资产，非时序）与**当前会话上下文动作**（把既有页面动作搬进面板），两者都无时序语义。

## 2. 目标 / 非目标

**目标**

1. **P1 Agent 目录动态组**：面板新增「Agent」组——每个启用的 Agent 一条命令「新建会话 · {Agent 名}」（keywords 带名称别名），Enter = 新建会话并选中该 Agent（复用「新建会话 + AgentSelector 选中」的既有链路，不新增会话创建语义）；Agent 头像在条目右侧展示（store 现成）。
2. **P1 上下文动作组**：当前处于会话路由时，追加该会话的既有页面动作——「打开工作区文件」「查看运行轨迹」「查看我的用量」等（全部是既有入口的路由 / 事件转发，不新增动作语义；不在会话路由时该组不渲染）。
3. **P2 快捷键速查面板化**：`?` 键（`isTypingTarget` 守卫同款）在面板打开时渲染「快捷键」分组（批次 25 的 7 条全量列出），键入即过滤——速查表从设置页孤本变成面板内可搜。
4. 静态 28 条命令、搜索行为、`Ctrl/Cmd+K` 打开方式零变化；动态组按需构建（面板打开时计算），不进常驻内存。

**非目标**

- 不做会话 MRU / 最近会话组（批次 25 已否决，会话切换无痛点）。
- 不做命令自定义 / 用户收藏排序（无需求证据，且引入偏好持久化）。
- 不做面板外的新快捷键（`?` 仅在面板打开时生效；不与全局键冲突）。
- 不新增任何会话创建 / Agent 管理语义（只路由到既有链路）。
- 零后端、零迁移。

## 3. 与已否决 / 已排除方向的边界

| 方向 | 本提案为何不是它 |
|---|---|
| 最近会话快切（批次 25 否决） | 不含会话时序 / MRU / Alt 循环；动态组是 Agent 目录（资产）与上下文动作（页面入口转发） |
| 设置可达性（批次 27 否决） | 不做设置页的可发现性改造；速查表面板化是批次 25 已有资产的入口扩展 |
| 用户自建 Agent（批次 14 否决） | 不下放创建权限；目录只读展示既有 Agent |

## 4. 方案设计

- `buildCommands(host, dynamic?: { agents: Agent[]; contextActions: CommandItem[] })`——第二参数可选，缺省行为与现状逐字节一致（静态命令回归零变化）；`CommandPalette` 打开时（`open()`）实时构建传入（agents 从 store 取、contextActions 按 `route.name` 判定）。
- Agent 组 id 加 `agent:` 前缀命名空间（与上下文组 `ctx:` 前缀），避免与静态 id 冲突；keywords 含 Agent 名与别名（含中文）；禁用态（无 Agent）整组不渲染。
- 上下文动作组复用 `host` 既有的动作通道（打开用量抽屉 / 工作区 / 轨迹 Tab 的入口函数已存在），仅转发。
- `?` 速查组：静态数据（批次 25 的速查表常量收编进 registry 导出），面板内搜索即可定位；`?` 键在面板未打开时不响应（守卫与 `isTypingTarget` 同源）。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 动态组与静态命令 id 冲突 | `agent:` / `ctx:` 命名空间前缀 |
| Agent 很多导致面板过长 | 动态组按 keywords 过滤参与既有搜索；无关键词时 Agent 组限前 6 条 + 「输入名称筛选」提示 |
| 上下文动作组在非会话路由误渲染 | 按 `route.name` 判定，非会话路由整组不渲染 |
| 新建会话链路重复实现 | 只路由到既有「新建 + 选中 Agent」入口（AgentSelector 选中语义复用），不复制创建逻辑 |
| 静态命令回归 | 缺省参数下 `buildCommands` 输出与现状逐条一致——源码级断言锁死（快照测试） |

## 7. 测试要点

1. 面板打开：Agent 组列出全部启用 Agent（名称/头像/keywords 正确）；Enter 后进入新建会话且 Agent 已选中；禁用 Agent 不出现。
2. 会话路由内：上下文动作组出现且动作可达；非会话路由整组消失。
3. `?` 在面板内打开快捷键组并可搜索；面板未打开时 `?` 无反应；输入框聚焦时 `?` 不触发（`isTypingTarget`）。
4. 回归：无动态参数时 28 条静态命令逐条一致（快照断言）；`Ctrl/Cmd+K`、搜索、主题切换、设置导航零变化。
5. 安卓壳：面板 Agent 组与上下文动作可用。

## 8. 决策记录

已拍板（2026-11-11，评审确认）：

1. **Agent 组的上限与排序**：前 6 条按 store 顺序（与 AgentSelector 同源排序）；**不加**「全部 Agent」尾条——管理入口走既有设置导航。
2. **上下文动作组的条目集**：**取三个最高频**——打开工作区文件 / 查看运行轨迹 / 查看我的用量（全部既有入口转发）。
3. **`?` 键位**：**仅面板内生效**——面板打开时按 `?` 渲染速查组；不加全局键（不新增面板外快捷键）。
