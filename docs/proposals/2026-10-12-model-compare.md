# 提案：模型对照台（Model Compare）—— 一次提问，多模型并排作答

- 状态：**已否决**（2026-10-12 评审：不做。本文仅存档，勿再评审）
- 日期：2026-10-12
- 提案总览：见 `docs/proposals/README.md`

## 1. 背景与现状

「换个模型再问一遍」是用户每天做无数次的动作：同一个问题，先用默认模型问一遍，觉得不够好，切换到另一个模型，把原话复制过去再问。今天的代价是：

1. **操作链断裂**：模型选择器一次只能选一个。对照意味着：切模型 → 重输 / 复制原话 → 等完整一轮 → 来回切 Tab 比对。手机上这一步尤其难用。
2. **选型没有依据**：管理后台配了五六个模型（GPT 兼容的各家 API），用户不知道哪个适合自己——用量页能看到成本和调用量，但看不到"同一个问题谁答得好"。团队管理员推荐 Agent 时同样凭感觉。
3. **已否决的方向不覆盖这个需求**：Evals 是自动化回归评测（评测集 + 指标 + 报告），面向提示词迭代；本提案是**人工即时对照**，面向"这次问谁更好"，无评测集、无指标、无报告。

相邻方向的边界：

- **不是 Evals**（已否决）：Evals 用固定评测集跑回归、产出通过率；本提案是用户手输一个问题，当场并排看答案，人工择优。没有测试资产管理的工程量。
- **不是多 Agent 协作 / DAG**（已否决）：没有委派、汇合、队友信箱语义；N 个模型跑的是**同一条用户消息、同一个 Agent 配置**，只是 model 不同，是广播不是编排。
- **不是模型容灾 / 故障转移**（已否决）：容灾是"主模型挂了自动切备用"；本提案是 N 个模型**同时**跑、全部结果都展示，没有主备语义。
- **不是子代理**：子代理是独立任务上下文与工具集；对照的各路共用主会话的全部上下文，只是换 model。

## 2. 目标 / 非目标

**目标**

1. **对照模式**：新建任务时模型选择器支持多选 2~4 个模型（勾选即入对照），发送后一条用户消息广播到 N 路，各自独立流式输出，桌面端并排卡片（移动端纵向堆叠）。
2. **择优固化**：每路回答旁有「采用」按钮——点选后该回答固化为本轮正式回复（进入后续上下文），其余各路标记为「已放弃」并折叠；未选择的对照轮次不进入上下文历史（避免 N 份近似答案撑爆上下文）。
3. **可反馈**：每路回答可点赞 / 点踩（复用既有 `message_feedback` 表与消息点踩链路，管理后台负反馈汇总天然覆盖对照回答）。
4. **成本透明**：进入对照模式时输入框上方常驻预估提示「本次将调用 N 个模型，成本约为单次 ×N」；实际消耗按各路真实 token 落账。
5. **新统计场景**：各路调用记 `llm_call`，scene 新增 `model_compare`，按规范三处同改（`shared/contracts/src/usage.ts`、`backend-ts/src/usage/llm-call-context.ts`、desktop/admin 的 `llmCallLabels.ts`），「我的用量」可按此场景筛出对照花费。

**非目标**

- 不做自动择优（模型打分、胜率统计、ELO 排行榜）——那是 Evals 的地盘，已否决。
- 不做跨轮次对照（"用 A 模型的上下文继续问 B 模型"）——P1 只对照首轮；上下文分叉已有边路任务 / 会话分叉覆盖。
- 不给渠道（飞书 / 钉钉 / 微信 / Embed SDK）开放对照模式——卡片消息放不下 N 路并排，只做桌面 / Web / 安卓。
- 不做"对照结果自动沉淀为经验 / 记忆"——对照消息不触发记忆抽取（见风险节）。

## 3. 技术方案

### 3.1 数据模型（V151）

```sql
ALTER TABLE `message`
    ADD COLUMN `compare_group_id` BIGINT NULL COMMENT '对照组 ID（同一用户消息广播出的 N 条助手回复共享）',
    ADD COLUMN `compare_role` VARCHAR(16) NULL COMMENT 'CANDIDATE 候选 / ADOPTED 已采用 / DISCARDED 已放弃',
    ADD INDEX `idx_message_compare_group` (`compare_group_id`);
```

- 用户消息行 `compare_group_id` 非空、`compare_role` 为空（它是组根）。
- N 条助手消息各自成行（content / token / 耗时各自真实），共享组 ID；这样运行轨迹、点踩反馈、用量统计全部复用现有按消息行的链路，零特判。
- 组 ID 用消息行 id 即可（用户消息 id 即组 id），不新增发号器。

### 3.2 执行链路（harness）

- 入口：`AgentLoop` 收到带 `compareModelIds`（2~4 个）的运行请求时，**串行**发起 N 次 LlmAdapter 调用（并行打满上游配额的风险大于收益，且流式多路并发的 WS 复杂度陡增；串行总耗时 ≈ N × 单轮，对照场景可接受）。
- 上下文：N 路的第一轮请求共享同一份上下文快照（system prompt + 历史 + 本轮用户消息 + 工具结果），此后**各走各的**——某一路要调工具就调，互不等待。
- 固化：用户点「采用」时，`compare_role` 该路置 `ADOPTED`、其余置 `DISCARDED`；后续轮次的上下文组装**只纳入 ADOPTED 那一条**（`ContextManager` 按 `compare_role IN (NULL, 'ADOPTED')` 过滤）。
- 未固化直接开下一轮：默认自动采用最后完成的那一路（避免上下文断裂），其余置 DISCARDED，并在 UI 上提示"本轮未手动选择，已默认采用最后一路"。

### 3.3 预算与记忆

- **预算**：准入检查按 N 次计（`estimated_micros × N`），BLOCK 时整组不发；WARN 阈值按组累计，对齐既有 `finishExecution` 结算点。
- **记忆抽取跳过**：对照消息不触发 `memory_extract`（否则同一轮结论会被抽 N 遍近似记忆）；ADOPTED 固化后由用户手动"存入记忆"或下轮自然沉淀时再抽。
- **运行轨迹**：N 路各自成 run 记录，组 ID 关联，轨迹页可并排对照（与边路 / 子代理轨迹同模式）。

### 3.4 前端（desktop，三端共用）

- `ModelSelector.vue` 增加多选态（2~4 个，超过 4 个 toast 提示上限）；选中多个时常驻预估成本提示条。
- 消息流：一组 N 条助手消息渲染为并排卡片（桌面 grid，移动端单列），卡片头 = 模型名 + 状态（流式中 / 完成 / 失败）+ 耗时 / token；卡内复用 `MessageBubble` 全部能力（markdown、工具调用卡片、点踩）。
- 采用 / 放弃：卡片底部「采用此回答」；已采用金标、已放弃灰折叠。组内任一路失败不影响其他路，失败卡显示重试入口（重试仅该路）。
- WS 多路复用：`useStreamWS` 按消息 id 分流事件（现机制已是消息粒度），对照只是同一事件流里多几个消息 id，无协议变更。

## 4. 分阶段实施

| 阶段 | 内容 | 规模 |
|---|---|---|
| P1 | V151 迁移 + 选择器多选 + 串行 N 路执行 + 并排渲染 + 采用 / 放弃 + 上下文过滤 | 中~大 |
| P2 | 点踩反馈接入 + 预算 ×N 准入 + 新 scene `model_compare` 三处同改 + 轨迹页对照视图 | 中 |
| P3 | 默认采用策略提示 + 未固化开新轮的兜底 + 管理后台对照用量统计 | 小 |

## 5. 风险与开放问题

- **成本意外**：用户忘了自己在对照模式，连发几轮就是 N 倍账单。缓解：发送前预估提示常驻；对照卡片组头常驻"×N 成本"徽标；预算 WARN / BLOCK 照常生效。
- **上下文污染**：忘了固化的对照轮把 N 份答案都带进后续上下文。缓解：3.2 的兜底策略（开新轮自动只留一路）；上下文透视抽屉里 DISCARDED 消息不计入构成（该抽屉按消息行渲染，天然只统计纳入的）。
- **记忆双抽**：见 3.3，抽取链路显式跳过对照组；需回归记忆服务现有用例。
- **串行耗时**：4 模型 × 单轮 30s = 2 分钟才看全。缓解：流式是逐路先后开始，第一路 30s 即可读、不等其余；UI 明确"逐路生成中"。
- **公平性**：N 路共享首轮上下文快照，但工具调用可能改变后续上下文（比如某一路先搜了网页）。这是特性不是 bug（各自决策路径都要看），但需在文档里写明"对照的是完整决策过程，不是单次采样"。
- **开放问题**：对照模式要不要支持"同模型不同参数"（temperature / effort）——P1 只对照不同 model，参数对照价值更低且组合爆炸。
- **开放问题**：ADOPTED 之后还能改选另一路吗——建议允许（下一轮开始前可反悔），反悔只改标记不动上下文已生成部分。

## 6. 测试要点

- 执行：2~4 路广播各自产出完整消息行；任一路失败不影响其余；上下文快照一致性（N 路首轮 system prompt 与历史逐字节相同）。
- 固化：采用后其余路 DISCARDED；下一轮上下文只含 ADOPTED；未固化开新轮自动采用最后一路并提示；反悔改选后下一轮跟随新选择。
- 预算：准入按 N 倍估算；BLOCK 时整组不发出；WARN 通知携带组信息。
- 记忆：对照轮不触发 `memory_extract`（回归记忆服务用例）；ADOPTED 消息后续正常沉淀。
- 统计：`llm_call` scene=`model_compare` 三端汉化与筛选生效；「我的用量」成本含对照各路。
- 前端：选择器上限 4 个；并排 / 单列布局切换（窄屏）；点踩在各路可用且进管理后台汇总；渠道端不出现对照入口。
- 回归：单模型普通会话行为零变化（`compare_group_id` 为 NULL 的路径全覆盖现有用例）。
