# 代码审查报告

## 中风险

### 1. 边路任务升级流程缺少事务保护，失败时会留下半成品主会话
- **位置**：`backend-ts/src/session/session.service.ts:404-501`
- **问题**：`promoteSideTaskToMainSession()` 先插入新主会话，再依次复制消息、文件变更和 todo，最后才删除源边路任务。整个过程没有使用数据库事务，也没有在中途失败时回滚已插入的新会话和已复制的数据。
- **影响**：如果复制消息/文件变更/todo 过程中任一步抛错，用户会得到一个内容不完整的新主会话，同时源边路任务仍然存在，造成重复数据和流程中断。
- **建议**：将“创建新会话 + 复制关联数据 + 删除源会话”包裹在同一事务中；如果当前数据访问层不支持事务，至少在失败时补偿删除新插入的主会话及已复制记录。

### 2. 升级边路任务时未处理其子会话，可能留下孤儿节点并丢失会话树历史
- **位置**：`backend-ts/src/session/session.service.ts:404-501`，`backend-ts/src/session/session.service.ts:315-330`
- **问题**：边路任务本身允许挂载子代理/子边路任务（现有查询逻辑会递归把边路任务下的子会话合并展示），但升级逻辑只复制了消息、文件变更和 todo，没有处理 `parent_session_id = sideSessionId` 的子会话。随后又直接删除了源边路任务。
- **影响**：如果某个边路任务下已经生成了子代理或嵌套边路任务，这些子会话会继续指向被删除的父会话，升级后的新主会话也看不到这段历史树，导致数据归属不完整。
- **建议**：升级前要么明确禁止“存在子会话的边路任务”执行升级，要么把相关子会话一并复制/重挂到新主会话下，并同步处理其关联记录。
