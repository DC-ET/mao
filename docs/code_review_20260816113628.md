## 问题 1（高）：Docker 镜像构建失败 —— `shared/contracts` 未复制进镜像

### 根因

本轮新增的 `shared/contracts` 目录没有进入任何 Docker 构建阶段，而三个 Dockerfile 在构建期都依赖它：

- 后端 `@mao/contracts` 是 `file:../shared/contracts` 依赖，`tsc` 构建期需解析类型。
- 前端 admin/desktop 通过 `tsconfig` `paths` + Vite alias 指向 `../shared/contracts/src`，`vue-tsc` 类型检查期需解析该路径。

但三个 Dockerfile 只复制了各自子目录，从未复制 `shared/`：

| Dockerfile | 关键行 | 缺失 |
|---|---|---|
| `docker/Dockerfile.backend-ts` | 3-6 行仅 `COPY backend-ts ...` | 未 `COPY shared/contracts` |
| `docker/Dockerfile.admin` | 2-6 行仅 `COPY admin ...` | 未 `COPY shared/contracts` |
| `docker/Dockerfile.desktop` | 2-8 行仅 `COPY desktop ...` | 未 `COPY shared/contracts` |

### 具体表现

**后端**（`docker/Dockerfile.backend-ts:3-6`）

- `npm ci` 对 `file:../shared/contracts`（`backend-ts/package.json:49`）不会因目标缺失而报错，而是生成一个指向镜像内 `../../../shared/contracts` 的悬空符号链接。
- 随后 `npm run build` 编译 `backend-ts/src/common/result.ts:2` 时解析 `@mao/contracts` 失败。

实测复现（在仅含 `backend-ts`、不含 `shared` 的目录中构建）：

```
src/common/result.ts(2,29): error TS2307: Cannot find module '@mao/contracts' or its corresponding type declarations.
```

**前端 admin / desktop**

- `vue-tsc -b` 依据 `admin/tsconfig.app.json:7`、`desktop/tsconfig.app.json:8` 的 `paths` 将 `@mao/contracts` 解析为镜像内 `../shared/contracts/src/index.ts`，该路径不存在。

实测复现（仅含 `admin`、不含 `shared` 的目录中执行 `vue-tsc -b`）：

```
src/api/index.ts(3,29): error TS2307: Cannot find module '@mao/contracts' or its corresponding type declarations.
```

由于前端 build 脚本为 `vue-tsc -b && vite build`，类型检查先失败，`vite build` 不会执行。

### 影响

`docker compose up --build`（`docker-compose.yml` 中三个服务均配置 `build:`）在后端、admin、desktop 任一阶段都会失败，容器化部署链路被阻塞。

### 建议

在三个 Dockerfile 的构建阶段补 `COPY`，将共享契约复制到能被现有相对路径解析到的位置。例如后端在 `npm ci` 前复制 `shared/contracts` 到 `/build/shared/contracts`；前端在 `COPY admin/ .` / `COPY desktop/ .` 之后（或之前）复制 `shared/contracts` 到镜像内的 `/shared/contracts`。具体路径需与各端 `file:` 依赖、`paths`、Vite alias 的相对位置保持一致。

## 问题 2（高）：`shared/` 尚未纳入 git 跟踪

### 现象

`git status` 显示 `shared/` 为 untracked，而已修改的 `backend-ts/package.json`、`backend-ts/src/common/result.ts`、`admin/src/api/index.ts`、`desktop/src/api/index.ts` 等均已引用 `@mao/contracts`。

### 影响

若本轮只提交已跟踪文件的改动、遗漏 `shared/`：

- CI（`actions/checkout` 仅检出已提交内容）中后端 `npm run build` 与前端 `npm run build` 会因 `TS2307: Cannot find module '@mao/contracts'` 失败。
- 全新 clone 后的生产部署（`npm ci && npm run build`）同样失败。
- 当前本地能构建通过，仅因为 `shared/` 恰好存在于工作区。

### 建议

将 `shared/`（含 `shared/contracts/package.json`、`src/index.ts`、`src/result.ts`、`.gitignore`）一并纳入本次提交，再推送/合并。
