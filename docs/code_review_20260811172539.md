## 中等严重程度

### 1. fetch 前读取不到 upstream 时，刷新后仍沿用旧状态，导致拉取按钮被错误禁用

**代码位置：**

- `desktop/electron/gitStatus.cjs:478-528`
- `backend/src/main/java/cn/etarch/mao/file/service/GitWriteOperationService.java:117-135`（CLOUD 端重新读取状态，未受同一问题影响）

**问题说明：**

LOCAL 刷新先调用 `getGitStatus()`，随后执行 fetch，但 fetch 成功后没有重新读取 branch/upstream 状态。后续是否计算标准 ahead/behind 完全依据 fetch 前的 `status.upstream`。

Git 分支可能已配置 `branch.<name>.remote` 与 `branch.<name>.merge`，但对应远端跟踪引用暂时不存在，例如：

1. 本地曾执行 `git update-ref -d refs/remotes/origin/main`，或远端引用因清理/迁移暂时缺失；
2. `git rev-parse @{upstream}` 在 fetch 前失败，因此 `status.upstream` 为空；
3. 手动刷新成功 fetch 回 `origin/main`，此时 Git 实际 upstream 已恢复有效；
4. 当前实现仍进入“无 upstream”分支，只计算 `hasCommitsToPush`，不返回 `upstream` 和 `behindCount`；
5. 前端 `pullDisabledReason` 因 `!props.upstream` 一直提示“当前分支未配置 upstream”，即使远端已有新提交也无法点击拉取。

该问题仅影响 LOCAL/Electron 路径。CLOUD 路径在 fetch 后调用 `workspaceGitService.getStatus(...)`，会重新读取 upstream 并正确计算 ahead/behind。

已通过临时 Git 仓库复现：fetch 前 `upstream` 不可解析；远端新增 1 个提交；刷新后实际执行 `git rev-list HEAD...@{upstream}` 得到 `0 1`，但 `refreshGitStatus()` 返回 `upstream=undefined`、`behindCount=undefined`、`remoteStatusAvailable=true`。

**修复建议：**

LOCAL fetch 成功后重新调用一次本地状态读取，或至少重新读取 branch、upstream 与 HEAD，再基于刷新后的状态计算 divergence 和 `hasCommitsToPush`。建议让 CLOUD/LOCAL 遵循同一顺序：

1. 读取仓库与远端选择所需的基础状态；
2. fetch；
3. 重新读取最新本地状态；
4. 计算 ahead/behind 与 `hasCommitsToPush`；
5. 返回刷新后的完整状态。

补充 LOCAL 测试：分支配置保留 upstream，但删除其 remote-tracking ref；远端推进后执行刷新，断言返回 `upstream=origin/main`、`behindCount=1`、`remoteStatusAvailable=true`，从而允许拉取。
