# 代码审查报告

## 中风险

### 1. 升级边路任务时没有迁移压缩状态，长历史会话继续对话可能上下文失真
- **位置**：`backend-ts/src/session/session.service.ts:475-481`、`backend-ts/src/session/session.service.ts:523-524`
- **问题**：`promoteSideTaskToMainSession()` 会复制消息并映射 `contextAnchorMsgId`，但没有把源边路任务的 `session_compaction` / `session_compaction_event` 压缩记录迁移到新主会话；最后还会直接删除源边路任务的压缩记录。新主会话因此只有从源任务复制来的 `lastPromptTokens/contextAnchorMsgId/contextTokens`，却没有对应的压缩摘要和边界。
- **影响**：对于已经触发过上下文压缩的边路任务，升级后继续对话时 `HarnessService` 会因新会话没有压缩记录而按 boundary=0 加载完整消息历史；但 `ActiveContextCalculator` 又可能使用复制来的 `lastPromptTokens + anchor` 按增量估算上下文。这样实际 prompt 与 token 估算不一致，长会话下可能低估上下文窗口，导致请求超窗、压缩触发时机错误，或丢失原压缩摘要承载的上下文衔接。
- **修复建议**：升级时同步迁移压缩状态：将 `session_compaction.last_compacted_msg_id` 按 `messageIdMap` 映射到目标会话的新消息 id，并复制 `summary_text` 等字段；`session_compaction_event` 中的边界消息 id 也需要映射后复制。若暂不支持迁移压缩记录，则不要复制 `lastPromptTokens/contextAnchorMsgId/contextTokens`，并在升级后让新会话从完整历史重新计算/重新压缩，避免“有 anchor 但无 compaction”的不一致状态。
