# Desktop 未提交代码审查报告

审查范围：`desktop/` 下当前未提交的代码改动，仅关注功能逻辑。

## 发现的问题

### 1. [中] 父会话处于激活状态时，后台完成的边路任务不会产生未读提示

- 位置：`desktop/src/stores/session.ts:457-469`
- 相关调用：`desktop/src/composables/useStreamWS.ts:655-662`

`updateSideTaskUnread()` 只要发现边路任务所属的父会话等于 `activeSessionId`，就把边路任务直接设为已读，并调用 `/sessions/{sideSessionId}/read` 清除后端未读状态。

但“父会话已打开”不等于“用户正在查看这个边路任务”：用户可能正在主聊天、文件页或另一个边路任务 Tab。此时后台边路任务完成后既不会显示青色圆点，服务端未读状态也会被永久清除，用户可能完全错过完成提示。

建议仅在用户实际打开对应边路任务 Tab 时清除该边路任务的未读状态；收到完成事件时不要根据父会话是否激活推断已读。

### 2. [中] 点击父会话会把其全部边路任务误标为已读

- 位置：`desktop/src/components/task/TaskIndexPanel.vue:413-419`
- 位置：`desktop/src/stores/session.ts:617-636`

当父会话的圆点来自某个边路任务时，点击父会话会调用 `markAsRead(parentId)`；新增逻辑随后遍历该父会话下所有边路任务，清除全部本地 `unread`，并逐个调用后端已读接口。

进入父会话后通常仍停留在主聊天或此前保存的其他 Tab，并不代表用户查看了所有已完成的边路任务。该逻辑会让尚未查看的任务结果失去未读提示，多个边路任务完成时尤其明显。

建议父会话的 `markAsRead` 只清除父会话自身未读；边路任务应按 `sideSessionId` 独立标记已读，并在对应边路任务 Tab 被激活时调用。
